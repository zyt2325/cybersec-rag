中间人攻击与证书校验

一、基本概念  
1. 中间人攻击（MITM）指攻击者在通信双方之间秘密插入自身节点，劫持并可能篡改传输数据。  
2. 证书校验是客户端验证服务器身份的核心机制，依赖公钥基础设施（PKI）和可信证书颁发机构（CA）。  
3. TLS/SSL握手过程中，服务器必须提供由可信CA签发的数字证书，客户端需执行完整校验流程。  
4. 证书包含公钥、域名、有效期、签名等关键字段，任何一项校验失败即应终止连接。  
5. 主机名验证（SNI匹配）是证书校验必要环节，要求证书Subject Alternative Name（SAN）或Common Name匹配请求域名。

二、原理与关键机制  
1. MITM成功前提：攻击者能诱导客户端信任其伪造证书，或绕过证书校验逻辑。  
2. 证书链验证需逐级向上追溯至根CA，检查每级签名有效性、吊销状态及策略约束。  
3. CRL（证书吊销列表）和OCSP（在线证书状态协议）用于实时验证证书是否已被撤销。  
4. 证书透明度（CT）日志强制记录所有公开签发证书，支持第三方审计与异常检测。  
5. 客户端时间同步影响验证结果，系统时钟偏差超证书有效期范围将导致校验失败。

三、典型类型与常见问题  
1. 伪造CA证书攻击：攻击者通过恶意软件安装自签名根证书，使系统信任其签发的假证书。  
2. DNS劫持或ARP欺骗常作为MITM前置手段，将流量导向攻击者控制的代理节点。  
3. 移动应用若忽略证书固定（Certificate Pinning）或禁用主机名验证，易遭证书替换攻击。  
4. 浏览器对自签名证书仅提示警告而非阻断，用户误点“继续访问”即完成信任链绕过。  
5. 旧版TLS协议（如TLS 1.0）缺乏强加密套件与安全重协商机制，增加会话劫持风险。  
6. 开发者调试时硬编码信任所有证书（如OkHttp中设置TrustManager为空实现），引入生产环境漏洞。

四、防御措施与实践建议  
1. 服务端启用HSTS（HTTP Strict Transport Security）头，强制浏览器仅通过HTTPS通信并拒绝不安全降级。  
2. 客户端实施证书固定（Certificate Pinning），绑定特定公钥哈希，防止合法CA被入侵导致的证书滥用。  
3. 使用现代TLS版本（TLS 1.2+），禁用弱密码套件（如RC4、SHA-1签名）、导出密钥与压缩功能。  
4. 移动端应用集成动态证书吊销检查（OCSP Stapling或OCSP必选模式），避免因网络延迟跳过验证。  
5. 企业内网部署私有CA时，须严格管控根证书分发，并定期轮换中间CA密钥与证书。  
6. 开发阶段启用证书校验日志（如Java的javax.net.debug=ssl:handshake），便于定位校验失败原因。
