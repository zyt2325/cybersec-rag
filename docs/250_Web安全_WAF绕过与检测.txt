WAF绕过与检测

一、基本概念  
1. WAF（Web应用防火墙）是部署在Web服务器前端的专用安全设备或软件，用于实时检测和阻断HTTP/HTTPS流量中的攻击载荷。  
2. WAF绕过指攻击者通过修改请求特征，使恶意流量被WAF误判为合法，从而成功抵达后端Web应用。  
3. WAF检测是指WAF依据预设规则或模型对请求内容进行语义分析、模式匹配或行为建模，识别SQL注入、XSS等攻击意图的过程。  
4. 绕过成功与否取决于WAF规则覆盖度、解析一致性及后端应用实际处理逻辑三者之间的差异。  

二、原理与关键机制  
1. WAF通常采用多阶段检测：协议解析→规范化→规则匹配→响应拦截，任一阶段存在不一致即可能引发绕过。  
2. 请求规范化差异是核心绕过根源，如WAF与后端对URL编码、Unicode变体、空字节、大小写、注释符的处理逻辑不一致。  
3. WAF依赖签名规则（正则表达式）、启发式规则（长度/频率阈值）和部分语义分析，但难以完整还原后端执行上下文。  
4. 某些WAF支持JavaScript引擎模拟执行客户端脚本以检测DOM型XSS，但执行深度和环境保真度有限，易被控制流混淆规避。  

三、典型类型与常见问题  
1. 编码绕过：利用双重URL编码、UTF-8宽字节、HTML实体嵌套等方式使WAF解码后无法匹配原始攻击模式。  
2. 分块传输绕过：将恶意载荷拆分为多个HTTP分块，使WAF因未重组完整请求而漏检关键片段。  
3. HTTP协议畸形：构造非法但被后端容忍的Header（如大小写混用、多余空格、重复字段），干扰WAF解析流程。  
4. 逻辑绕过：利用WAF白名单机制，将payload嵌入允许路径（如/favicon.ico?xss=...）或伪装成静态资源请求。  
5. 时间盲注绕过：使用sleep()类函数配合布尔响应延迟，规避基于关键字匹配的SQL注入规则。  

四、防御措施与实践建议  
1. 实施WAF与后端应用的统一输入规范化：强制使用相同字符集、编码标准及解码顺序，消除解析歧义。  
2. 启用WAF的深度协议解析与完整请求重组能力，禁用仅解析首包或跳过分块/压缩内容的简化模式。  
3. 采用多层检测策略：结合正则签名、语法树分析（如SQL解析器）、行为基线（异常参数熵值、请求频次突变）联合判定。  
4. 定期开展WAF有效性验证：使用OWASP Core Rule Set测试集、自定义模糊测试用例，覆盖编码、分块、协议变异场景。  
5. 部署运行时应用自我保护（RASP）作为纵深补充，直接在应用内存中监控危险函数调用，不受WAF解析路径影响。  
6. 禁用WAF的“学习模式”长期运行，避免将已绕过流量误标为正常；所有规则变更须经灰度发布与流量回放验证。
