短信验证码安全

一、基本概念  
1. 短信验证码是通过运营商短信通道向用户手机号发送的一次性数字或字母组合，用于身份核验与操作授权。  
2. 其本质属于“所知+所持”双因子认证中的“所持”环节，依赖手机号的物理归属与SIM卡控制权。  
3. 验证码有效期通常为60–300秒，超时即失效，且单条验证码仅允许验证一次。  
4. 与静态密码不同，验证码无长期存储需求，服务端仅需缓存其哈希值或明文（短期内存中）并校验后立即清除。  

二、原理与关键机制  
1. 生成阶段采用密码学安全伪随机数生成器（CSPRNG），避免可预测性，长度建议4–6位数字或6–8位字母数字混合。  
2. 发送环节依赖SMPP协议或运营商API，服务端需对接短信网关，并对请求签名防篡改。  
3. 校验过程要求严格比对：时间有效性、使用次数限制（防重放）、绑定关系（手机号+业务场景+会话ID）。  
4. 后端须记录验证码生成时间、IP、设备指纹等上下文，用于异常行为关联分析。  

三、典型类型与常见问题  
1. 暴力穷举：攻击者利用短位数（如4位）和宽松重试策略，在有效期内尝试全部10000种组合。  
2. 短信劫持：通过SS7协议漏洞、基站伪冒或SIM卡复制，截获目标号码的短信内容。  
3. 会话绑定缺失：验证码未与具体登录会话或设备指纹强绑定，导致被跨会话复用。  
4. 逻辑缺陷：注册/登录流程中未校验手机号归属权（如跳过短信回填直接提交），形成越权注册。  
5. 信息泄露：前端JavaScript硬编码API密钥或明文传输验证码，导致中间人窃取或日志残留。  

四、防御措施与实践建议  
1. 强制验证码与当前会话ID、用户设备指纹、请求IP进行三元绑定，校验时缺一不可。  
2. 实施分级限速：单手机号每分钟最多2次请求、每小时最多10次，失败5次后锁定1小时。  
3. 敏感操作（如修改绑定手机、大额支付）必须叠加二次验证，禁止单靠短信完成关键动作。  
4. 服务端存储验证码时仅保存SHA-256哈希值，且加盐（salt为会话ID+时间戳），禁止明文落库。  
5. 对接短信平台时启用双向TLS加密与API密钥轮换机制，定期审计网关调用日志与异常IP分布。  
6. 前端禁止显示或缓存验证码，所有校验逻辑必须在服务端完成，避免客户端绕过。
