越权访问漏洞

一、基本概念  
1. 越权访问指攻击者绕过权限控制机制，非法访问本不应具备权限的数据或功能。  
2. 本质是服务端未对用户身份与操作资源的归属关系做严格校验，而非前端界面隐藏失效。  
3. 属于业务逻辑层漏洞，OWASP Top 10 中归类为“失效的访问控制”（A01）。  
4. 不依赖代码执行或注入，仅通过篡改请求参数（如ID、路径、状态值）即可触发。  
5. 常见于RESTful API、管理后台、用户中心等需细粒度权限区分的场景。

二、原理与关键机制  
1. 服务端在处理请求时，仅验证用户是否已登录或拥有某角色，未校验当前操作对象是否属于该用户。  
2. 权限判断逻辑缺失或错位：例如用session中用户ID查数据库，但未将该ID与请求资源owner_id字段比对。  
3. 状态机校验不足：允许用户跳过必要流程（如未支付直接访问订单详情），导致状态越权。  
4. 基于路径或参数的资源标识未绑定主体：如/api/orders/123中123可被任意替换，且无归属校验。  
5. 水平越权常因使用静态角色标签（如“user”）代替动态资源所有权检查；垂直越权多因管理员接口未做二次鉴权。

三、典型类型与常见问题  
1. 水平越权：同一权限级别用户间越界访问，如用户A读取用户B的私有信息（订单、地址、聊天记录）。  
2. 垂直越权：低权限用户冒充高权限角色，如普通用户调用管理员接口删除他人账户或修改系统配置。  
3. 多层次越权：结合水平与垂直特征，如客服人员越权查看高管审批流中的敏感附件。  
4. IDOR（Insecure Direct Object References）是水平越权的典型表现形式，源于直接暴露内部对象引用且无访问控制。  
5. 基于状态的越权：利用业务流程断点（如订单状态为“待支付”时，跳过支付直接触发“已发货”操作）。  
6. 隐式越权：API响应中泄露其他用户资源链接（如HATEOAS超媒体控件含他人ID），诱导后续越权请求。

四、防御措施与实践建议  
1. 强制服务端执行“基于资源的访问控制”（RBAC+ABAC混合）：每次请求均校验用户ID与目标资源owner_id一致性。  
2. 避免在URL、表单、API参数中直接暴露数据库主键；使用不可推测的随机标识符（如UUID）或加密映射ID。  
3. 对所有敏感操作实施二次鉴权：即使用户处于管理员角色，执行删除操作前仍需校验其对目标资源的操作许可。  
4. 实现最小权限原则：后端接口按功能粒度授权，禁用通配符权限（如“user:*”），明确声明可操作资源范围。  
5. 在业务逻辑层嵌入状态校验：如订单发货前必须验证其状态为“已支付”且归属当前操作用户。  
6. 自动化检测覆盖：在API网关或统一认证中间件中集成越权规则引擎，对高频参数篡改行为实时拦截并告警。
