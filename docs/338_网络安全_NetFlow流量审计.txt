NetFlow流量审计

一、基本概念  
1. NetFlow是Cisco开发的网络流量采集与导出协议，用于统计IP数据包的五元组（源/目的IP、端口、协议）及字节数、包数等会话级元数据。  
2. 审计目标是通过分析NetFlow记录识别异常通信模式，如横向移动、数据外泄、DDoS反射源等隐蔽行为。  
3. NetFlow本身不传输原始载荷，仅导出流摘要信息，因此具备低带宽开销与高隐私性，但无法检测加密载荷中的恶意内容。  
4. 当前主流版本为NetFlow v9和IPFIX（RFC 7011），后者为IETF标准化的增强版，支持模板化字段与可扩展信息元素。  

二、原理与关键机制  
1. 流（Flow）定义为具有相同五元组、相同输入接口、相同QoS标记等特征的单向数据包序列，超时或字节/包阈值触发流缓存导出。  
2. 路由器或交换机启用NetFlow后，在转发平面执行流匹配与计数，在控制平面生成流记录并按配置周期（如30秒）或事件（如流结束）发送至收集器。  
3. 收集器接收UDP报文，解析模板与数据记录，存储为时间序列数据库（如Elasticsearch）或专用格式（如nfdump二进制文件）。  
4. 流记录包含时间戳（开始/结束）、TCP标志位、TOS/DSCP、采样率标识等字段，支撑细粒度行为建模与基线比对。  

三、典型类型与常见问题  
1. NetFlow v5仅支持IPv4固定字段，无模板机制，无法携带BGP AS号、VLAN ID等扩展信息；v9/IPFIX通过模板动态定义字段，适配SDN与云环境。  
2. 采样导致小流漏检：1:1000采样下，短连接或低频C2通信可能未被记录，需结合会话持续时间、包速率等衍生指标补偿。  
3. NAT/负载均衡设备破坏五元组唯一性：多用户共用出口IP时，源端口随机化使流聚合失真，需部署NetFlow于内网接入层或启用应用层网关日志。  
4. 时间戳精度不足（秒级）影响微突发检测；部分旧设备使用系统启动时间而非绝对时间，导致跨设备关联失败。  

四、防御措施与实践建议  
1. 在核心路由出口、数据中心边界、云VPC网关等关键路径部署NetFlow，避免仅在非对称路径单侧启用造成流记录不完整。  
2. 配置双流导出：v9模板+数据记录分离发送，并启用UDP校验和与接收端模板缓存验证，防止模板丢失导致解析失败。  
3. 结合DNS日志、防火墙会话日志与NetFlow做多源交叉验证，例如匹配DNS解析域名与后续HTTP User-Agent中出现的同一FQDN。  
4. 建立动态基线模型：基于历史NetFlow计算各子网每日80分位TCP连接数、ICMP响应率、非标准端口占比，偏离阈值自动告警。  
5. 对NetFlow收集器实施访问控制：禁用默认SNMP社区字符串，限制UDP接收端口仅允许可信网络段访问，防止伪造流记录注入。
