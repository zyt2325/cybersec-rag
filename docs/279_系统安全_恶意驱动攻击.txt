恶意驱动攻击

一、基本概念  
1. 恶意驱动攻击指攻击者通过加载具备内核权限的恶意驱动程序，绕过用户态安全机制实施持久化、提权或隐蔽操作。  
2. 驱动程序运行在Windows内核模式（Ring 0）或Linux内核空间，拥有对硬件、内存及系统核心结构的完全访问权。  
3. 此类攻击常作为高级持续性威胁（APT）的初始立足点或横向移动关键环节，具备高隐蔽性与强破坏力。  
4. 与普通恶意软件不同，恶意驱动无需用户交互即可在系统启动早期加载，且多数杀毒软件难以深度扫描内核模块。  

二、原理与关键机制  
1. 利用合法驱动签名漏洞（如证书盗用、时间戳劫持）或未启用驱动强制签名（DSE）策略绕过内核模块加载校验。  
2. 通过IOCTL接口、设备对象或内核回调（如PsSetCreateProcessNotifyRoutine）劫持系统行为，实现进程隐藏或API钩子。  
3. 常驻于内核内存中，动态修改页表属性（如CR0.WP位）、禁用SMAP/SMEP等硬件保护机制以执行任意代码。  
4. 依赖驱动服务注册（SCM）、INF文件安装或利用存在漏洞的合法驱动（Bring-Your-Own-Vulnerable-Driver）完成注入。  

三、典型类型与常见问题  
1. Rootkit型驱动：隐藏进程、文件、网络连接及注册表项，使恶意活动对任务管理器和常规扫描不可见。  
2. 键盘/鼠标过滤驱动：记录击键、截获剪贴板内容，规避用户态输入监控工具。  
3. 网络中间人驱动：在NDIS层拦截并篡改TCP/IP数据包，实现流量劫持或SSL剥离。  
4. 固件通信驱动：通过PCIe配置空间或MMIO直接访问网卡、显卡固件，为硬件级后门提供控制通道。  
5. 驱动崩溃引发BSOD：因未适配内核版本或内存越界导致系统蓝屏，成为拒绝服务攻击载体。  

四、防御措施与实践建议  
1. 启用并强制执行驱动签名策略（如Windows DSE、Secure Boot + UEFI签名验证），禁止未签名驱动加载。  
2. 部署内核完整性保护机制（如HVCI、Hypervisor-protected Code Integrity）阻止未授权代码执行。  
3. 定期审计驱动服务列表（sc query type= driver）、驱动文件哈希及数字签名有效性，识别异常加载项。  
4. 使用内核调试器（WinDbg）或EDR内核模块检测工具分析IRP处理链、回调注册表及内存页属性异常。  
5. 限制本地管理员权限，采用最小权限原则部署驱动安装流程，禁用非必要驱动开发接口（如WDK调试驱动）。  
6. 在虚拟化环境中启用微隔离策略，将驱动加载行为与主机关键服务进行资源域隔离，降低横向影响范围。
