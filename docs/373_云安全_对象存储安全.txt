对象存储安全

一、基本概念  
1. 对象存储是一种以唯一标识符（如URL或Object Key）管理非结构化数据的分布式存储架构，典型代表为Amazon S3、阿里云OSS、MinIO。  
2. 与文件/块存储不同，对象存储无层级目录结构，采用扁平命名空间，元数据可自定义且与数据一同持久化存储。  
3. 安全边界主要位于访问控制层（而非网络或主机层），核心风险聚焦于权限误配、元数据泄露和未加密数据暴露。  
4. 对象存储服务通常通过RESTful API提供访问，认证依赖签名机制（如AWS Signature V4）、临时凭证或OAuth令牌。  

二、原理与关键机制  
1. 访问控制模型多采用基于策略的授权（如S3 Bucket Policy、IAM Policy），支持资源级、操作级及条件级细粒度控制。  
2. 预签名URL通过服务端签名生成临时访问链接，有效期、HTTP方法、参数均受签名算法约束，过期即失效。  
3. 服务器端加密（SSE）分三类：SSE-S3（服务托管密钥）、SSE-KMS（密钥管理服务加密）、SSE-C（客户提供的密钥），密钥不落盘。  
4. 版本控制与跨区域复制功能虽提升可用性，但若配置不当，可能扩大误删或恶意覆盖的影响范围。  
5. 对象ACL（Access Control List）已逐步被策略机制取代，因其仅支持有限权限组合且难以审计。  

三、典型类型与常见问题  
1. 公共读写桶因策略配置错误（如"Principal": "*" + "Action": "s3:PutObject"）导致任意用户上传并覆盖关键数据。  
2. 静态网站托管功能若开启且未禁用索引文档回退，可能暴露目录列表或敏感备份文件（如.git、.env）。  
3. 日志投递桶若未设置写入限制，攻击者可伪造日志流注入恶意内容，干扰SIEM分析或触发规则绕过。  
4. 跨账户访问中，信任策略未限定ExternalId或未校验调用方ARN，易引发权限提升或代币劫持。  
5. 客户端加密后上传的对象，若密钥管理缺失或加密参数硬编码，将使加密形同虚设。  

四、防御措施与实践建议  
1. 默认拒绝所有访问，遵循最小权限原则；使用IAM角色替代长期密钥，定期轮换并监控异常调用行为。  
2. 强制启用默认加密（如S3 SSE-KMS），对敏感对象额外启用客户端加密，并将密钥交由HSM或KMS托管。  
3. 禁用公共访问策略，通过VPC Endpoint或私有DNS实现内网直连，避免流量经公网路由。  
4. 启用对象版本控制与MFA删除，结合S3 Object Lock合规模式（Governance/Retention）防止勒索软件覆盖。  
5. 自动化扫描桶策略与ACL，集成CI/CD流水线，在部署前拦截宽泛权限语句（如"s3:*"、"Resource": "*"）。  
6. 对预签名URL实施严格时效控制（建议≤15分钟），禁止在日志或前端代码中明文拼接，使用短生命周期临时凭证替代。
