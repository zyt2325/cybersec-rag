Serverless安全

一、基本概念  
1. Serverless是一种按需执行、自动扩缩的云服务模型，开发者仅关注函数逻辑，无需管理底层服务器。  
2. 安全责任模型为共担：云服务商负责基础设施安全，用户负责函数代码、配置、依赖及事件源安全。  
3. 函数即服务（FaaS）是Serverless核心形态，典型平台包括AWS Lambda、Azure Functions、Google Cloud Functions。  
4. 无状态设计导致函数实例间不共享内存或磁盘，但冷启动时可能残留前序执行的临时文件或环境变量。  
5. 执行环境生命周期极短（毫秒至分钟级），传统基于持久主机的安全监控手段难以直接适用。

二、原理与关键机制  
1. 函数通过事件驱动触发，常见事件源包括API网关、对象存储、消息队列、定时器等，每个源引入独立信任边界。  
2. 运行时沙箱基于容器或轻量虚拟化（如AWS Firecracker）隔离函数实例，但共享宿主内核，存在侧信道风险。  
3. 权限通过最小权限策略控制，通常以执行角色（Execution Role）授予函数访问其他云服务的临时凭证。  
4. 函数包（ZIP或容器镜像）在部署时被静态扫描，但运行时动态加载的第三方库无法被部署期检测覆盖。  
5. 日志与指标默认由平台采集（如CloudWatch Logs），但日志内容受函数代码控制，敏感信息易被意外记录。

三、典型类型与常见问题  
1. 事件注入：恶意构造的API请求或存储对象元数据可触发非预期函数行为，如路径遍历或命令拼接。  
2. 权限过度分配：执行角色包含未使用的高危权限（如s3:GetObject+lambda:InvokeFunction），扩大横向移动面。  
3. 依赖链污染：函数引用的开源库含已知漏洞（如log4j2），且因无持续更新机制长期滞留。  
4. 配置错误：API网关未启用WAF或CORS策略宽松，导致函数暴露于跨域攻击或自动化爬虫探测。  
5. 冷启动数据残留：复用容器实例时，/tmp目录未清理或环境变量未重置，引发信息泄露。

四、防御措施与实践建议  
1. 强制函数输入验证与规范化：对所有事件源数据执行白名单校验，禁用eval、exec等动态执行函数。  
2. 使用基础设施即代码（IaC）模板定义权限，结合SCA工具扫描部署包中的CVE依赖项。  
3. 启用运行时保护：部署轻量代理（如eBPF-based runtime monitor）捕获异常系统调用与进程派生。  
4. 隔离敏感操作：将密钥读取、数据库连接等高风险逻辑拆分为独立函数，通过异步消息通信。  
5. 日志脱敏自动化：在函数入口统一过滤字段（如Authorization头、身份证号正则模式），禁止明文记录凭证。  
6. 设置执行超时与内存上限：防止DoS型资源耗尽，同时限制攻击者利用长时运行进行侦察或加密货币挖矿。
