WebSocket安全

一、基本概念  
1. WebSocket是HTML5定义的全双工通信协议，基于TCP，在单个TCP连接上实现客户端与服务器间双向实时数据传输。  
2. 协议通过HTTP/HTTPS升级请求建立连接，初始握手使用HTTP 101状态码，后续通信脱离HTTP语义独立运行。  
3. WebSocket统一资源标识符以ws://（明文）或wss://（TLS加密）开头，wss强制要求TLS 1.2+且证书有效验证。  
4. 连接建立后，数据以帧（frame）为单位传输，支持文本（UTF-8）和二进制两种载荷类型，无内置消息边界保护机制。  

二、原理与关键机制  
1. 握手阶段依赖Origin头校验，但该字段可被客户端伪造，不能单独作为可信来源依据。  
2. 协议本身不提供身份认证机制，需应用层集成Token、Cookie或JWT等方案完成会话绑定。  
3. WebSocket连接复用底层TCP连接，不继承HTTP的Same-Origin Policy限制，但受浏览器同源策略约束初始握手。  
4. 服务器必须显式解析并验证Sec-WebSocket-Key与Sec-WebSocket-Accept值，防止握手欺骗。  

三、典型类型与常见问题  
1. 认证绕过：未在WebSocket连接建立后二次校验用户会话有效性，导致会话固定或Token重放攻击。  
2. 消息注入：服务端未对客户端发送的WebSocket消息内容做输入过滤与上下文转义，引发XSS或服务端模板注入。  
3. 权限缺失：未按业务角色实施细粒度消息路由与操作授权，允许低权限用户订阅高敏频道或执行管理指令。  
4. 资源耗尽：未限制单连接消息频率、帧大小或并发连接数，易受慢速连接或大帧洪泛导致内存溢出或拒绝服务。  
5. 敏感信息泄露：通过WebSocket明文传输未脱敏的用户凭证、会话令牌或内部系统信息，且缺乏端到端加密保障。  

四、防御措施与实践建议  
1. 强制使用wss://协议，禁用ws://，配置HSTS预加载，并在TLS层启用OCSP装订与证书透明度日志验证。  
2. 在WebSocket握手完成后，立即通过独立通道（如HTTP POST至/auth/verify）验证用户身份与权限，拒绝未通过校验的连接。  
3. 对所有入站消息执行严格白名单校验：验证JSON结构、字段类型、枚举值范围及业务逻辑约束，拒绝非法格式帧。  
4. 实施连接级速率限制（如每秒最大帧数）、单帧最大长度（建议≤64KB）及全局并发连接阈值，结合IP与用户ID双重维度控制。  
5. 敏感操作指令（如账户删除、资金转账）须要求二次确认令牌，并在WebSocket消息中携带一次性操作签名，服务端验证时效性与完整性。  
6. 日志记录完整WebSocket生命周期事件（握手参数、连接ID、关闭原因、异常帧摘要），日志脱敏处理后再落盘，保留至少90天。
