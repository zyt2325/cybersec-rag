CTF Web题型

一、基本概念  
1. CTF Web题型是网络安全竞赛中模拟真实Web应用漏洞的解题类题目，目标是通过分析和利用Web服务缺陷获取flag。  
2. 题目通常部署在隔离靶机环境，提供URL、源码片段或Docker镜像等有限信息，考察选手对HTTP协议与Web架构的理解。  
3. 与Pwn、Reverse等题型不同，Web题聚焦于服务端逻辑、客户端交互及中间件配置层面的缺陷，不涉及二进制漏洞利用。  
4. 题目难度梯度明显，初级题常暴露基础漏洞，高阶题融合多层绕过、时序侧信道或业务逻辑链式利用。

二、原理与关键机制  
1. 核心依赖HTTP协议特性，如请求头可控性、状态保持机制（Cookie/Session）、MIME类型解析差异及缓存行为。  
2. 服务端脚本引擎（PHP/Python/Node.js）的类型弱校验、动态执行函数、反序列化机制易引入不可信数据执行路径。  
3. 前端JavaScript与后端交互存在信任边界模糊问题，如未校验的JSONP回调、CSP策略缺失导致XSS可升级为CSRF。  
4. 数据库访问层若使用拼接SQL且未参数化，结合错误回显或布尔/时间盲注可实现非交互式数据提取。

三、典型类型与常见问题  
1. SQL注入：出现在登录框、搜索接口或ID参数中，常见于未过滤单引号、双引号及注释符的字符串拼接场景。  
2. XSS：反射型多见于URL参数回显，存储型集中于用户提交内容未转义即入库渲染，DOM型源于document.write或innerHTML动态写入。  
3. 文件类漏洞：文件上传绕过常利用MIME类型校验松散、扩展名白名单不全或解析顺序差异；文件包含则依赖LFI路径遍历或RCE型伪协议。  
4. 逻辑漏洞：密码重置流程缺乏Token绑定、越权访问通过修改ID参数实现、支付金额前端校验缺失等均属典型业务逻辑缺陷。  
5. SSRF：由URL参数触发后端发起内网请求，配合协议支持（如gopher://）可探测内网服务或读取本地文件。

四、防御措施与实践建议  
1. 输入验证应采用白名单机制，对URL参数、表单字段、HTTP头严格限制字符集与长度，拒绝未预期格式数据。  
2. 数据库操作必须使用预编译语句或ORM参数化接口，禁用拼接SQL及动态查询构建方式。  
3. 输出编码需按上下文区分：HTML实体编码、JavaScript字符串转义、URL编码，避免通用encodeAll式处理。  
4. 敏感操作强制二次验证（如短信/邮箱确认），会话标识使用HttpOnly+Secure Cookie，禁止明文传输Token。  
5. 服务端禁用危险函数（如PHP的eval、file_get_contents含协议输入），关闭详细错误页面，日志中剥离敏感字段。  
6. 定期使用Burp Suite主动扫描与人工逻辑测试结合，重点关注身份认证、权限控制、异步接口及第三方组件集成点。
