云上挖矿病毒治理

一、基本概念  
1. 云上挖矿病毒指通过入侵云主机、容器或无服务器函数等云资源，非法占用其CPU/GPU算力进行加密货币挖矿的恶意程序。  
2. 与传统挖矿木马不同，云上挖矿病毒高度依赖云环境特性，如元数据服务、开放API、弱凭证和配置错误。  
3. 典型感染路径包括SSH/RDP爆破、未授权Docker API、暴露的Kubernetes Dashboard、云平台密钥泄露及供应链投毒。  
4. 挖矿行为常伴随横向移动、持久化驻留和反检测机制，易引发云资源超额计费、服务降级甚至账户被封禁。  

二、原理与关键机制  
1. 利用云平台元数据服务（如AWS IMDS、阿里云IMDS）获取临时凭证，进而调用云API创建新实例或拉取恶意镜像。  
2. 通过容器逃逸漏洞（如runc CVE-2019-5736）突破隔离，在宿主机部署挖矿进程并隐藏于systemd或crontab中。  
3. 借助Serverless函数冷启动缺陷，将恶意代码注入函数执行环境，利用闲置算力周期性执行挖矿任务。  
4. 使用内存马技术（如Linux eBPF后门）实现无文件驻留，规避基于文件签名的传统查杀。  

三、典型类型与常见问题  
1. 容器镜像型：预编译含XMRig等挖矿程序的恶意镜像，通过公共仓库或CI/CD流水线污染合法镜像。  
2. 云原生蠕虫型：如“Kinsing”“TeamTNT”，自动扫描暴露的K8s API Server、Docker Daemon端口并植入挖矿负载。  
3. 函数即服务型：在AWS Lambda或阿里云函数计算中部署轻量级Go挖矿程序，利用事件触发机制规避持续运行检测。  
4. 多阶段混淆型：首阶段仅下载加密shellcode，解密后加载第二阶段挖矿模块，绕过静态分析与沙箱检测。  
5. 资源劫持隐蔽性强：CPU占用率常控制在60%–85%，避免触发云平台告警阈值，且进程名伪装为nginx、java等合法进程。  

四、防御措施与实践建议  
1. 严格限制云服务角色权限，遵循最小权限原则，禁用root权限容器，关闭非必要元数据服务访问（如IMDSv2强制启用）。  
2. 对所有容器镜像实施签名验证与SBOM（软件物料清单）扫描，阻断含已知挖矿哈希或可疑网络连接的镜像部署。  
3. 在云主机部署eBPF驱动的运行时检测工具（如Falco），监控异常进程创建、高频系统调用及非常规网络外连行为。  
4. 配置Kubernetes PodSecurityPolicy或Pod Security Admission，禁止privileged容器、hostPID/hostNetwork及危险挂载。  
5. 定期审计云账号API调用日志，对非工作时段、异常地域来源或高频CreateInstance/CreateFunction操作设置实时告警。  
6. 对Serverless函数启用执行时长限制与内存配额，并结合WAF规则拦截含挖矿域名（如xmrpool.eu）的DNS请求。
