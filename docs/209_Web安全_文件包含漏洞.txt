文件包含漏洞

一、基本概念  
1. 文件包含漏洞是服务端脚本语言因不安全地处理用户可控的文件路径参数，导致任意文件被读取或执行的安全缺陷。  
2. 常见于PHP的include、require、include_once、require_once等函数，也存在于JSP的<jsp:include>、ASP的<!--#include-->等机制中。  
3. 本质是服务端将用户输入直接拼接进文件路径，未校验合法性与访问边界，破坏了文件系统隔离原则。  
4. 区别于文件上传漏洞：前者利用已有文件路径解析逻辑，后者依赖恶意文件落地后被触发执行。

二、原理与关键机制  
1. 动态包含函数在运行时解析传入的路径字符串，若该字符串含用户输入且未经过滤，即可构造非法路径。  
2. PHP中allow_url_include配置开启时，支持远程URL协议（如http://、php://filter），扩大攻击面至远程代码执行。  
3. 路径遍历（如../）可突破Web根目录限制，访问系统敏感文件（/etc/passwd、/proc/self/environ等）。  
4. 空字节截断（%00）在旧版PHP中可终止字符串解析，绕过白名单后缀检查（如file.php%00.jpg）。  
5. 协议封装器（php://input、data://）可注入恶意代码，无需物理文件存在即可实现代码执行。

三、典型类型与常见问题  
1. 本地文件包含（LFI）：读取服务器本地文件，常用于信息收集（配置文件、日志、源码）或配合日志注入提权。  
2. 远程文件包含（RFI）：加载并执行外部URL资源，依赖allow_url_include=On，可直接导致远程命令执行。  
3. 常见错误模式：使用$_GET['page']等参数直接传入include语句；仅校验后缀而忽略路径遍历与编码绕过。  
4. 日志文件利用：将恶意PHP代码注入访问日志（如User-Agent字段），再通过LFI包含该日志文件实现RCE。  
5. /proc/self/environ利用：在Linux Apache环境下，该文件可能包含HTTP头内容，可注入并执行PHP代码。

四、防御措施与实践建议  
1. 禁用allow_url_include和allow_url_fopen，从配置层阻断远程包含能力。  
2. 使用白名单机制控制可包含文件：将合法文件名映射为固定ID或枚举值，避免用户输入参与路径拼接。  
3. 对用户输入进行严格规范化：使用realpath()获取绝对路径后，校验其是否位于预设安全目录内。  
4. 移除危险函数调用，改用模板引擎（如Twig、Smarty）或静态路由分发替代动态包含逻辑。  
5. 设置open_basedir限制PHP脚本可访问的文件系统范围，配合disable_functions禁用include相关函数。  
6. Web服务器配置禁止访问敏感目录（如/etc/、/var/log/）及源码文件（.php、.inc），并启用日志文件权限最小化。
