Windows组策略安全

一、基本概念  
1. 组策略（GPO）是Windows域环境中集中配置用户和计算机安全设置的核心管理机制。  
2. GPO通过组策略对象（Group Policy Object）定义策略设置，由组策略容器（GPC）和组策略模板（GPT）共同构成。  
3. 策略应用遵循“本地→站点→域→组织单位（OU）”的继承顺序，支持强制（Enforced）和阻止继承（Block Inheritance）控制。  
4. 每个GPO具有唯一GUID标识，存储于Active Directory数据库（GPC）和SYSVOL共享目录（GPT）中，二者需同步一致。  
5. 用户和计算机策略分别作用于登录会话和系统启动阶段，执行时机与权限上下文严格分离。

二、原理与关键机制  
1. 客户端通过组策略客户端服务（gpsvc）定期（默认90±30分钟）向域控制器发起策略刷新请求。  
2. 域控制器验证客户端SID及OU成员关系后，返回适用GPO列表，并检查GPO的ACL权限（如Read、Apply Group Policy）。  
3. GPO链接（GPLink）属性决定OU级策略应用状态，包含启用/禁用标志及链接顺序权重。  
4. 策略处理采用双重传递机制：第一轮解析继承路径并计算适用GPO集，第二轮下载GPT内容并应用注册表/安全模板等设置。  
5. 安全筛选（Security Filtering）通过显式授权特定安全组（如Domain Computers）Apply Group Policy权限实现细粒度控制。

三、典型类型与常见问题  
1. 密码策略（如最小长度、历史记录）仅在域控制器上生效，且必须配置于域根GPO或具有“强制”标记的GPO。  
2. 软件限制策略（SRP）和AppLocker规则若配置冲突，AppLocker优先级更高，但未启用时SRP仍可生效。  
3. SYSVOL目录若未启用DFS-R复制或ACL配置错误，将导致GPO无法同步，客户端策略应用失败或回退至旧版本。  
4. 过度依赖“禁止访问此计算机”用户权限策略可能引发合法管理员被意外锁定，因该策略不区分交互式与网络登录场景。  
5. GPO中硬编码明文凭据（如计划任务、映射驱动器）或弱加密的密码字段（如旧版GPP密码）构成高危信息泄露风险。

四、防御措施与实践建议  
1. 对所有生产环境GPO实施最小权限原则：仅授予Domain Admins和GPO编辑者组Modify权限，禁用Authenticated Users的默认读取权限。  
2. 启用组策略首选项（GPP）密码加密时，必须部署KB2962486补丁并禁用旧版XML密码字段，改用AES加密的cpassword字段。  
3. 使用组策略建模（GPM）和结果集（GPR）工具定期审计策略应用效果，验证安全筛选与WMI筛选逻辑是否符合预期。  
4. 将敏感策略（如账户锁定阈值、远程桌面授权）置于强制GPO中，并在父OU启用Block Inheritance防止子OU覆盖。  
5. 监控SYSVOL和Active Directory复制健康状态，结合事件ID 1054、1085、4016识别GPO处理失败原因。  
6. 禁用未使用的策略扩展（如IE维护、文件夹重定向），减少攻击面并提升策略处理性能。
