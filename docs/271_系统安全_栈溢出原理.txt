栈溢出原理  
一、基本概念  
1. 栈溢出是指程序向栈中写入超出其分配空间的数据，导致覆盖相邻内存区域的现象。  
2. 栈是进程运行时用于存储函数调用信息（如返回地址、局部变量、寄存器保存值）的后进先出内存区域。  
3. C/C++等缺乏自动边界检查的语言中，使用gets、strcpy、sprintf等不安全函数极易触发栈溢出。  
4. 溢出数据可覆盖栈帧中的返回地址，使函数返回时跳转至攻击者控制的指令地址。  
5. 栈通常位于进程地址空间的高地址端，向下增长，其大小受操作系统限制（如Linux默认8MB）。  

二、原理与关键机制  
1. 函数调用时，编译器在栈上构建栈帧，包含局部变量区、保存的基址指针（rbp/rbp）、返回地址（ret addr）。  
2. 当向局部数组写入超长数据时，首先覆盖相邻局部变量，继而覆盖保存的基址指针，最终覆盖返回地址。  
3. 返回地址被篡改后，ret指令执行时将控制流转向攻击者指定位置（如shellcode或libc函数地址）。  
4. 栈内存默认具有可读、可写属性，但现代系统通常禁用栈执行（NX/DEP），迫使攻击转向ROP等绕过技术。  
5. 编译器优化（如栈随机化、函数内联）可能改变栈布局，影响溢出点定位与利用稳定性。  

三、典型类型与常见问题  
1. 基于返回地址覆盖的控制流劫持：最常见形式，通过覆盖ret addr跳转至恶意代码。  
2. 覆盖函数指针或异常处理结构（如SEH on Windows）：间接实现控制流转移。  
3. 格式化字符串漏洞常与栈溢出协同利用，用于泄露栈地址或绕过ASLR。  
4. 静态缓冲区（如char buf[256]）未校验输入长度是绝大多数栈溢出的根本成因。  
5. 多线程环境下，各线程拥有独立栈，但主线程栈溢出仍可导致整个进程崩溃或被利用。  

四、防御措施与实践建议  
1. 启用编译期保护：-fstack-protector-strong（插入canary检测）、-z noexecstack（禁用栈执行）、-pie（启用ASLR）。  
2. 使用安全替代函数：以fgets代替gets、snprintf代替sprintf、strncpy代替strcpy，并显式指定目标缓冲区长度。  
3. 开发阶段启用AddressSanitizer（ASan）进行动态内存错误检测，可精准定位溢出位置与规模。  
4. 在关键服务中部署Control Flow Integrity（CFI），限制间接跳转目标为合法函数入口。  
5. 禁用不必要的setuid/setgid权限，配合最小权限原则降低漏洞利用后的危害范围。  
6. 对接收外部输入的接口实施长度预检与白名单过滤，避免未经验证的数据进入栈操作路径。
