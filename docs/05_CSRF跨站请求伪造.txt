CSRF跨站请求伪造攻击与防御

CSRF（Cross-Site Request Forgery，跨站请求伪造）是指攻击者诱导已登录用户在不知情的情况下，向目标网站发送恶意请求，冒充用户执行操作。

一、原理
网站只验证请求是否来自已登录用户的浏览器，但不验证这个请求是不是用户主动发起的。攻击者构造一个恶意页面，当已登录目标网站的用户访问这个页面时，浏览器会自动带上Cookie，向目标网站发送请求——服务器以为是用户本人的操作。

二、与XSS的区别
- XSS是在目标网站注入恶意脚本，利用用户对该网站的信任
- CSRF是伪造请求利用网站对用户浏览器的信任，不需要注入脚本
- XSS可以窃取Cookie，CSRF不能窃取Cookie但能冒充用户操作

三、攻击场景
1. 用户已登录银行网站
2. 攻击者发送邮件，里面有一个img标签指向银行转账接口
3. 用户打开邮件，浏览器自动加载图片，同时带上银行Cookie
4. 银行收到请求，认为是用户主动转账，执行操作

四、防御方法
1. CSRF Token：服务器生成随机令牌，表单里带上，请求时验证
2. SameSite Cookie：设置Cookie的SameSite属性为Strict或Lax，限制跨站携带
3. 验证Referer/Origin头：检查请求来源是否可信
4. 敏感操作二次确认：转账、改密码等需要输入验证码或密码
5. 使用自定义请求头：如X-Requested-With，简单跨站请求无法添加

五、常见误区
- 只用Cookie验证身份不够，必须加CSRF Token
- GET请求不能用于修改数据，所有写操作必须用POST
- 即使是HTTPS网站也存在CSRF风险
