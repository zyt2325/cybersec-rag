云上数据加密

一、基本概念  
1. 云上数据加密指在公有云、私有云或混合云环境中，对静态数据（如对象存储、数据库）、传输中数据（如API调用、跨可用区同步）及使用中数据（如内存计算）实施的密码学保护。  
2. 加密主体包括客户数据、元数据、日志、备份快照等，但不默认覆盖云服务商自身管理面数据（如IAM策略配置）。  
3. 加密责任遵循共享责任模型：云服务商负责基础设施层加密（如磁盘级AES-256），客户负责应用层与密钥管理责任。  
4. 云环境特有的加密边界包括租户隔离域、跨区域数据流、无服务器函数执行上下文，这些影响密钥分发与生命周期设计。

二、原理与关键机制  
1. 静态数据加密普遍采用AES-256-GCM，支持硬件加速（如AWS Nitro Enclaves、Azure Confidential VMs），并绑定存储卷或对象版本ID实现细粒度控制。  
2. 传输中加密强制TLS 1.2+，要求双向证书验证与SNI扩展防护，云内东西向流量需启用服务网格mTLS或VPC内网加密隧道。  
3. 密钥管理依赖KMS（密钥管理服务），其根密钥由HSM（硬件安全模块）保护，客户主密钥（CMK）可轮换且不导出，仅提供加密/解密API接口。  
4. 使用中加密依赖可信执行环境（TEE），如Intel SGX或AMD SEV，将解密后的明文数据严格限制在CPU隔离内存页中，防止宿主机窥探。

三、典型类型与常见问题  
1. 客户托管密钥（CMK）若未启用自动轮换或审计日志关闭，将导致密钥泄露后无法追溯操作主体。  
2. 数据库透明加密（TDE）可能绕过应用层访问控制，攻击者通过SQL注入获取已解密行数据。  
3. 对象存储服务端加密（SSE-S3/SSE-KMS）不保护客户端上传前的明文，存在本地缓存或内存残留风险。  
4. 多云环境密钥孤岛问题突出：各云KMS互不兼容，跨云迁移时需重新加密，增加密钥同步延迟与一致性风险。  
5. 无服务器函数冷启动时，运行时解密密钥可能短暂驻留内存，被恶意容器利用eBPF探针提取。

四、防御措施与实践建议  
1. 实施密钥分级策略：根密钥（HSM生成）、主密钥（按业务域划分）、数据密钥（每对象独立，用主密钥加密封装）。  
2. 静态数据加密必须启用密钥轮换（90天周期）与密钥使用审计（CloudTrail/KMS日志），禁止长期使用同一CMK。  
3. 传输中加密需禁用TLS降级协议（SSLv3/TLS 1.0），所有API网关强制HSTS头与OCSP装订验证。  
4. 使用中加密应启用TEE，并配合远程证明（Remote Attestation）验证运行时完整性，拒绝未签名代码加载。  
5. 多云场景采用IaC模板统一定义密钥策略（如Terraform KMS模块），并通过密钥代理（如HashiCorp Vault）抽象底层KMS差异。  
6. 应用层加密优先于服务端加密：敏感字段（如身份证号）在客户端用AEAD算法加密后再上传，避免云服务商接触明文。
