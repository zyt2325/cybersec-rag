分组密码工作模式

一、基本概念  
1. 分组密码工作模式是将固定长度的分组密码（如AES-128）扩展为可加密任意长度明文的机制。  
2. 每种模式定义了明文分组与密钥、前序密文或初始化向量（IV）之间的运算关系。  
3. 模式本身不改变底层分组密码算法，但直接影响安全性、并行性、错误传播等工程属性。  
4. IV必须具备不可预测性（如CBC、CTR）或唯一性（如GCM），重复使用将导致严重安全降级。  
5. 所有标准模式均需配套完整性校验机制（如HMAC或AEAD），否则无法抵抗篡改攻击。

二、原理与关键机制  
1. ECB模式对每个明文块独立加密，无扩散性，相同明文块产生相同密文块，暴露数据模式。  
2. CBC模式通过异或前一密文块实现扩散，解密时需按序处理，首块依赖随机IV保障语义安全。  
3. CTR模式将计数器加密后与明文异或，本质为流式加密，支持随机访问与并行加解密。  
4. GCM模式在CTR基础上增加GHASH认证，提供机密性与完整性一体化保护，依赖唯一nonce。  
5. OFB与CFB将分组密码转化为同步流密码，密钥流生成独立于明文，但错误会持续传播。

三、典型类型与常见问题  
1. ECB因缺乏扩散性，禁止用于传输结构化数据（如图像、JSON），易被模式分析攻击识别。  
2. CBC中IV若可预测或重用，将破坏IND-CPA安全性，且填充Oracle攻击可恢复明文（如POODLE）。  
3. CTR模式下nonce重复会导致密钥流复用，攻击者可通过密文异或直接恢复明文异或值。  
4. GCM在nonce重复时完全丧失机密性与完整性，且GHASH密钥若未正确派生将引发伪造漏洞。  
5. CFB模式若移位寄存器初始值（IV）重复，将导致密钥流周期性复用，削弱抗统计分析能力。

四、防御措施与实践建议  
1. 优先选用AEAD模式（如AES-GCM、ChaCha20-Poly1305），避免手动组合加密与MAC。  
2. IV/nonce必须由密码学安全伪随机数生成器（CSPRNG）生成，且在密钥生命周期内绝对唯一。  
3. 禁止使用ECB模式处理任何敏感数据；对遗留系统，强制替换为CBC或CTR并严格管理IV。  
4. 实现CBC时采用确定性填充方案（如PKCS#7）并启用填充Oracle防护（如统一错误响应）。  
5. GCM应用中确保nonce长度符合标准（通常96位），且通过密钥派生函数（HKDF）隔离GHASH密钥。  
6. 对长消息加密，监控CTR/GCM的nonce空间消耗，达到阈值（如2^32次）后强制轮换密钥。
