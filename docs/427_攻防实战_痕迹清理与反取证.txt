痕迹清理与反取证

一、基本概念  
1. 痕迹清理指攻击者在完成入侵后，主动删除或修改系统中残留的活动证据，以阻碍后续调查。  
2. 反取证是涵盖痕迹清理、数据混淆、时间轴干扰等技术的综合性对抗行为，旨在降低数字证据的可采性与可信度。  
3. 与常规日志轮转或磁盘清理不同，痕迹清理具有隐蔽性、选择性和上下文感知特征，常伴随权限提升操作。  
4. 常见目标痕迹包括：系统日志（syslog、Windows Event Log）、Shell历史记录、进程快照、网络连接记录及临时文件。  
5. 反取证效果取决于证据链完整性破坏程度，而非单纯删除动作——即使文件被删，元数据或未覆盖扇区仍可能恢复。

二、原理与关键机制  
1. 利用操作系统内核接口直接覆写日志缓冲区或禁用日志服务，绕过用户态日志守护进程的审计路径。  
2. 修改文件时间戳（atime/mtime/ctime）与进程创建时间，制造时间逻辑矛盾，干扰事件时序重建。  
3. 通过内存映射（mmap）或直接I/O向底层块设备写入零值或随机数据，实现对已删除文件所在扇区的物理覆盖。  
4. 利用符号链接、硬链接或挂载覆盖（mount --bind）隐藏恶意文件，使取证工具无法通过标准路径发现。  
5. 在虚拟化或容器环境中，通过卸载日志卷、重置快照或篡改hypervisor日志接口实现跨层痕迹隔离。

三、典型类型与常见问题  
1. 日志清除类：清空/var/log/下的auth.log、secure、messages等关键日志，但可能遗漏journalctl持久化日志。  
2. Shell痕迹类：删除~/.bash_history并设置HISTSIZE=0，但未清除终端复用器（如tmux/screen）会话缓存。  
3. 文件系统级：使用shred命令覆写文件，但在SSD上因FTL映射和磨损均衡机制，实际物理扇区未必被覆盖。  
4. Windows专项：清除Prefetch、SRUM、Amcache及Jump List等二进制日志，但注册表事务日志（RegTrans)可能留存操作痕迹。  
5. 时间欺骗类：通过settimeofday系统调用篡改系统时钟，导致所有新生成日志时间戳失真，影响多源日志关联分析。

四、防御措施与实践建议  
1. 实施日志集中采集与不可变存储：将syslog、WMI日志实时转发至独立SIEM平台，并启用WORM存储策略。  
2. 启用内核级审计框架（如Linux auditd），监控execve、unlink、openat等敏感系统调用，避免依赖应用层日志。  
3. 对关键目录（/var/log、/etc、/root）部署文件完整性监控（AIDE、Tripwire），检测非授权修改与时间戳异常。  
4. 在终端主机启用命令行审计（如PowerShell Script Block Logging + Transcription），捕获完整执行上下文。  
5. 部署内存取证前置机制：定期采集易失性内存快照并加密存证，防范攻击者利用内存页回收规避磁盘日志。  
6. 对SSD设备启用全盘加密（如LUKS+TPM绑定）并配置TRIM禁用策略，限制攻击者利用未加密残留扇区恢复数据。
