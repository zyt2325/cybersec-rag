挑战应答认证

一、基本概念  
1. 挑战应答认证是一种基于质询-响应机制的身份验证方法，客户端不直接传输密码，而是对服务端动态生成的挑战值进行加密或计算响应。  
2. 其核心目标是防止密码明文传输、重放攻击及离线字典破解，适用于远程登录、无线网络接入、智能卡等场景。  
3. 与静态口令认证不同，每次认证使用的挑战值唯一且不可预测，确保会话间响应不可复用。  
4. 挑战通常为随机数（nonce）、时间戳或序列号，由认证服务器在每次握手时生成并发送给客户端。  

二、原理与关键机制  
1. 服务端生成一次性挑战值，经安全信道发送至客户端；客户端使用预共享密钥、私钥或派生密钥对该挑战执行确定性运算（如HMAC、RSA签名、S/Key哈希链）。  
2. 客户端将计算结果作为响应返回；服务端独立执行相同运算，比对响应值是否一致，一致则认证通过。  
3. 挑战必须具备抗预测性与时效性：采用密码学安全伪随机数生成器（CSPRNG），并设置合理有效期（如30秒）以防御延迟重放。  
4. 密钥材料不得在通信中暴露，预共享密钥需通过带外方式分发，非对称场景下私钥须严格保护于硬件安全模块（HSM）或TEE中。  

三、典型类型与常见问题  
1. S/Key基于哈希链，客户端从种子和计数器生成响应，服务端反向迭代验证；易受同步丢失与中间人劫持影响。  
2. CHAP（PPP协议）使用MD5-HMAC，但MD5已不安全，且未绑定通道参数，存在跨协议重放风险。  
3. EAP-TLS依赖X.509证书双向认证，安全性高，但部署复杂、证书管理开销大，易因CRL/OCSP失效导致拒绝服务。  
4. 基于时间的一次性密码（TOTP）将挑战与当前时间窗口绑定，若设备时钟偏差超30秒则认证失败。  
5. 实现缺陷常见于挑战熵不足（如固定长度递增整数）、响应未绑定会话ID、服务端未及时作废已用挑战等。  

四、防御措施与实践建议  
1. 强制使用密码学安全随机源生成挑战，最小熵值不低于128比特，避免使用系统时间、PID等低熵输入。  
2. 在响应中显式绑定上下文信息，如服务标识、客户端IP（需考虑NAT）、TLS会话ID或通道绑定扩展（Channel Binding）。  
3. 服务端须维护挑战-状态映射表，对每个挑战设置单次有效、超时自动清除策略，并记录异常响应频次以触发告警。  
4. 优先选用标准化协议（如RFC 5802 SCRAM-SHA-256、RFC 8446 TLS 1.3 PSK），禁用MD4/MD5/SHA-1等弱哈希。  
5. 硬件令牌或FIDO2安全密钥应启用用户验证（PIN/生物特征）与密钥隔离，防止响应被提取后离线滥用。  
6. 对调试日志严格过滤，禁止记录原始挑战值、响应值及密钥派生中间量，审计日志仅保留认证结果与时序元数据。
