文件完整性监控

一、基本概念  
1. 文件完整性监控（FIM）是通过持续比对文件哈希值或属性变化，检测未授权修改的安全控制技术。  
2. 主要监控对象包括系统二进制文件、配置文件、日志文件、Web应用脚本及关键数据库文件。  
3. FIM属于主机层安全机制，常作为入侵检测与合规审计的核心组件，支撑PCI DSS、HIPAA等标准要求。  
4. 监控粒度可细化至文件内容、权限位、所有者、时间戳（mtime/ctime/atime）、扩展属性（如SELinux上下文）。  

二、原理与关键机制  
1. 基线建立阶段采集文件原始状态，生成加密哈希（如SHA-256）并安全存储于只读或隔离位置。  
2. 增量扫描采用轮询或事件驱动（如inotify、Windows事件订阅），避免全盘遍历带来的性能开销。  
3. 哈希校验支持分块计算与增量更新，对大文件（如数据库文件）可跳过未变更区域以提升效率。  
4. 时间戳与元数据比对用于识别仅修改属性（如chmod）但未改内容的隐蔽操作，弥补哈希盲区。  
5. 异常判定需结合上下文：同一目录下多个文件同时变更、系统关键路径出现未知文件、签名验证失败均触发告警。  

三、典型类型与常见问题  
1. 主机端FIM（如AIDE、Tripwire）依赖本地代理，易受rootkit篡改基线数据库，需配合可信执行环境加固。  
2. 云原生FIM（如AWS GuardDuty文件监控、Azure File Integrity Monitoring）集成API调用日志，但无法覆盖容器临时文件系统。  
3. 误报高发场景：自动更新导致的合法二进制替换、日志轮转引发的文件重命名、时区同步引起的时间戳漂移。  
4. 漏报风险源于内存映射文件（mmap）写入不触发fsync、符号链接指向绕过监控、加密文件内容变更不可见。  
5. 基线污染是主要脆弱点：攻击者在部署FIM前植入后门，或利用提权漏洞篡改已签名的基线哈希库。  

四、防御措施与实践建议  
1. 基线初始化必须在干净系统完成，使用硬件信任根（如TPM）密封哈希值，禁止运行时写入基线存储区。  
2. 实施分层监控策略：核心系统文件启用实时哈希校验，日志类文件采用元数据+大小双因子比对降低开销。  
3. 告警需关联进程溯源：记录触发变更的PID、父进程、命令行参数及用户上下文，阻断孤立事件误判。  
4. 定期轮换密钥与哈希算法，禁用MD5/SHA-1，对基线数据库实施AES-256-GCM加密并绑定主机唯一标识符。  
5. 将FIM日志接入SIEM平台，设置规则检测“同一账户连续修改/etc/passwd与/var/log/auth.log”等攻击链特征。  
6. 在容器环境中，需在镜像构建阶段嵌入FIM探针，并监控挂载卷内文件，避免仅扫描只读镜像层导致盲区。
