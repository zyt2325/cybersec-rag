个人信息最小化收集原则

一、基本概念  
1. 个人信息最小化收集原则是指组织仅收集实现处理目的所必需的最少类型、最少数量、最短时限的个人信息。  
2. 该原则是《中华人民共和国个人信息保护法》第6条明确规定的法定合规义务，具有强制性法律效力。  
3. 最小化不等于“不收集”，而是要求每一项收集行为均需通过目的关联性、必要性与比例性三重检验。  
4. 收集范围须与具体业务功能强绑定，例如健康App记录步数无需获取通讯录权限。  
5. 时间维度上要求设定明确的数据保留期限，超期未脱敏或删除即构成违规。

二、原理与关键机制  
1. 基于目的限定原则衍生，强调收集行为必须服务于已明示且具体的处理目的，不可泛化预留。  
2. 依赖数据映射分析：对每项业务功能反向拆解所需字段，剔除冗余字段（如注册仅需手机号，无需身份证号）。  
3. 采用“默认不收集”机制，所有非核心字段须用户主动勾选授权，禁止预设默认同意。  
4. 通过权限动态申请实现最小化，例如地图App仅在导航启动时请求位置权限，非使用状态自动释放。  
5. 系统设计阶段嵌入隐私影响评估（PIA），识别并阻断非必要数据采集路径。

三、典型类型与常见问题  
1. 过度索权：App启动即申请存储、短信、联系人等无关权限，属典型违反最小化原则。  
2. 字段冗余：电商下单强制填写生日、学历、年收入等与履约无直接关联信息。  
3. 数据复用滥用：将注册环节收集的身份证号用于用户画像或第三方共享，超出原始目的。  
4. 缓存残留：前端JavaScript长期缓存用户输入的银行卡号、密码强度提示等敏感字段。  
5. 日志泄露：服务器日志记录完整手机号、身份证号明文，而非脱敏后的哈希值或掩码。

四、防御措施与实践建议  
1. 实施字段级最小化清单管理，按业务场景建立《必要字段白名单》，每季度审计更新。  
2. 前端采集层增加校验逻辑，拦截非白名单字段提交（如表单中自动禁用“紧急联系人电话”输入框）。  
3. 后端接口强制参数过滤，对HTTP请求体执行Schema校验，丢弃白名单外字段并记录告警。  
4. 采用差分隐私技术对聚合统计类数据加噪，避免从脱敏结果反推个体信息。  
5. 第三方SDK接入前进行权限扫描，禁用含非必要采集行为的SDK（如广告SDK读取剪贴板）。  
6. 用户界面提供实时权限仪表盘，显示当前各功能启用的具体权限及对应数据流向，支持一键关闭。
