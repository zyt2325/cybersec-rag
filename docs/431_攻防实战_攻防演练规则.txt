攻防演练规则

一、基本概念  
1. 攻防演练规则是组织在红蓝对抗活动中明确各方行为边界、操作权限与责任义务的强制性规范文件。  
2. 规则须经管理层审批并书面签署，覆盖演练全周期，包括筹备、执行、复盘及数据销毁阶段。  
3. 明确禁止行为清单（如不得攻击生产核心数据库、不得植入持久化后门、不得横向渗透至第三方系统）为规则核心内容。  
4. 参演单位需签署保密协议与免责承诺书，确保演练数据不外泄、不用于非授权用途。  
5. 规则定义红队（攻击方）、蓝队（防御方）、紫队（协调方）及裁判组的职责分工与协同流程。  

二、原理与关键机制  
1. 规则设计遵循最小权限原则，红队仅获授权资产清单及指定攻击窗口期，超范围操作即触发熔断机制。  
2. 采用“白名单+时间窗”双控机制：所有攻击行为必须匹配预设IP段、端口、协议及起止时间戳，否则自动阻断。  
3. 引入实时审计日志回传机制，红队每步操作需生成结构化日志并同步至独立仲裁系统，供裁判组溯源核查。  
4. 设置多级熔断阈值：单次服务中断超5分钟、关键业务响应延迟超30秒或检测到勒索特征行为时立即中止演练。  
5. 规则内置数据脱敏要求：红队获取的所有敏感信息（如身份证号、银行卡号）须在24小时内完成不可逆哈希或截断处理。  

三、典型类型与常见问题  
1. 红蓝对抗型规则易出现授权资产遗漏，导致红队误击未备案测试系统，引发真实业务中断。  
2. 渗透测试型规则常忽视API接口调用频次限制，造成目标Web应用被异常流量压垮。  
3. 演练中常因规则未明确定义“横向移动”判定标准（如仅凭SMB连接还是需实际执行命令），引发争议。  
4. 部分规则未覆盖云环境特有风险，如容器逃逸、元数据服务滥用等新型攻击路径缺乏约束条款。  
5. 裁判组缺乏技术验证能力时，难以判断红队是否违反“禁止提权至宿主机”等隐性规则，导致裁决失效。  

四、防御措施与实践建议  
1. 每次演练前72小时发布动态授权清单，包含资产IP、开放端口、允许协议及对应业务影响等级。  
2. 部署轻量级探针于关键链路，实时比对红队流量特征与规则库，发现偏离即告警并冻结其C2通信通道。  
3. 蓝队应启用演练专用SIEM规则集，屏蔽真实告警噪声，聚焦识别红队TTPs（战术、技术与过程）特征。  
4. 建立规则偏差快速响应流程：发现越界行为后15分钟内由紫队发起三方视频会审，2小时内出具处置指令。  
5. 演练结束后48小时内完成规则符合性审计报告，重点核查日志完整性、熔断触发记录及数据销毁凭证。  
6. 每季度更新规则库，纳入新出现的攻击面（如AI模型API、IoT设备固件接口）及对应约束条款。
