Webshell流量特征

一、基本概念  
1. Webshell是攻击者上传至Web服务器的恶意脚本，通过HTTP协议与C2服务器通信，实现远程控制。  
2. 流量特征指Webshell在客户端与服务端交互过程中表现出的异常网络行为模式。  
3. 典型载体为PHP、ASP、JSP等后门脚本，常伪装成正常图片、CSS或JS文件以绕过基础检测。  
4. 其通信本质是HTTP请求/响应，但载荷结构、参数命名、编码方式等显著偏离业务逻辑。  

二、原理与关键机制  
1. 命令执行类Webshell通常将用户输入经base64、hex或异或编码后嵌入HTTP参数，规避关键字过滤。  
2. 通信多采用POST方法，请求体含加密或混淆的指令，响应体返回执行结果的Base64编码内容。  
3. 长连接或心跳机制少见，多数采用短周期轮询（如每5–30秒发起一次请求），形成规律性低频请求流。  
4. URL路径常包含无意义字符串（如/a.php?x=1、/css/123.css）或模仿静态资源路径，但实际无对应文件。  

三、典型类型与常见问题  
1. 一句话木马（如<?php @eval($_POST['x']);?>）流量极简，请求体仅含少量加密参数，易被WAF规则漏报。  
2. 大马（如ChinaChopper）使用分块加密和动态密钥，请求头常伪造Referer、User-Agent，且响应状态码恒为200。  
3. 内存马不落地，通过Java Agent或Servlet Filter注入，其流量无文件上传阶段，仅表现为异常POST请求。  
4. DNS型Webshell将指令编码进子域名，通过DNS查询外泄数据，产生大量非常规DNS请求（如xxx.attacker.com）。  
5. 流量中常见异常：参数名含exec、cmd、system等敏感词变体；响应体长度高度一致（如固定128字节）；无Cookie会话关联。  

四、防御措施与实践建议  
1. 部署具备语义分析能力的WAF，识别参数深度混淆、多层编码及非业务路径访问模式。  
2. 启用Web服务器日志审计，重点监控HTTP状态码200下的异常POST请求、无Referer的后台路径访问。  
3. 实施严格的文件上传白名单策略，禁止执行权限赋予images/、css/等静态目录，定期扫描可写目录。  
4. 使用HIDS监控Web进程异常子进程调用（如php调用sh、curl、wget），结合网络层NetFlow分析外连行为。  
5. 对关键业务接口实施API网关级校验，拒绝无签名、无Token或参数结构不符合Schema的请求。  
6. 定期开展红蓝对抗，基于真实Webshell样本构建流量特征库，验证IDS规则对变种流量的检出率。
