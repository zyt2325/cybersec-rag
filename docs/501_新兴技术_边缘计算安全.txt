边缘计算安全

一、基本概念  
1. 边缘计算安全指在靠近数据源的网络边缘节点（如基站、网关、IoT设备）上保障计算、存储与通信过程的机密性、完整性、可用性及隐私性。  
2. 边缘节点资源受限（算力弱、内存小、供电不稳），难以直接复用传统云安全机制，需轻量化适配。  
3. 安全边界从集中式云中心前移至分布式边缘，导致信任模型由中心化向多级分域演进。  
4. 边缘层常作为云-端协同枢纽，承担数据预处理、本地决策与策略执行，其被攻破将引发级联风险。  

二、原理与关键机制  
1. 零信任架构在边缘落地需支持动态设备认证（如基于硬件可信根的TEE远程证明）与细粒度访问控制（ABAC模型）。  
2. 边缘节点间安全通信依赖轻量级协议（如DTLS 1.3、OSCORE），避免TLS完整握手开销，支持PSK或ECDHE密钥交换。  
3. 安全启动链要求从Boot ROM固件签名验证开始，逐级校验Bootloader、OS内核与边缘应用镜像完整性。  
4. 可信执行环境（TEE）如ARM TrustZone或Intel SGX，在边缘设备中隔离敏感计算任务（如密钥解封装、隐私求交）。  

三、典型类型与常见问题  
1. 物理暴露风险：部署于开放环境的边缘服务器易遭物理篡改、侧信道窃听（如功耗分析）或恶意固件替换。  
2. 设备异构性漏洞：不同厂商IoT终端驱动存在未修复CVE（如CVE-2022-23772），导致边缘网关被用作跳板攻击上游云平台。  
3. 边缘AI模型劫持：攻击者通过投毒训练数据或篡改本地推理模型参数，使视频分析系统漏检入侵行为。  
4. 时间同步失效：NTP服务在边缘网络中易受中间人攻击，导致日志时序错乱，阻碍安全事件溯源与关联分析。  

四、防御措施与实践建议  
1. 实施边缘设备全生命周期安全管理：出厂预置唯一设备证书，OTA升级强制签名验证与差分更新完整性校验。  
2. 部署轻量级入侵检测系统（如Suricata嵌入式模式），结合边缘流量特征（MQTT报文结构、CoAP请求频率）构建异常基线。  
3. 对跨边缘节点的数据共享启用属性基加密（ABE），策略密钥由边缘管理平台按角色动态分发，避免中心化密钥托管。  
4. 在边缘集群中配置最小权限容器运行时（如gVisor或Kata Containers），禁用CAP_SYS_ADMIN等高危能力，限制网络命名空间互通。  
5. 建立边缘安全事件分级响应机制：本地节点自主处置低危告警（如登录失败阈值超限），中高危事件经加密通道上报至区域安全运营中心。
