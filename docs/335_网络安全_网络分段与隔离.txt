网络分段与隔离

一、基本概念  
1. 网络分段指通过技术手段将大型网络划分为多个逻辑或物理子网，限制广播域范围并控制流量流向。  
2. 网络隔离是分段的深化目标，强调不同安全等级区域间的数据流必须经过显式授权与检查，禁止隐式互通。  
3. 分段对象包括用户终端、服务器、IoT设备、工业控制系统等，需按业务功能、数据敏感度和信任级别分类。  
4. 分段不是单纯划分IP子网，必须配合访问控制策略、状态检测及审计能力，否则仅具拓扑意义而无安全实效。  

二、原理与关键机制  
1. 基于边界控制：利用防火墙、下一代防火墙（NGFW）或微隔离平台，在分段交界处实施基于五元组+应用层协议的细粒度策略。  
2. 状态化会话跟踪：设备维持连接状态表，仅允许属于合法会话的返回流量通过，阻断非法初始连接尝试。  
3. 策略执行点（PEP）与策略决策点（PDP）分离：如SDN架构中，控制器集中定义策略，交换机/主机代理执行，提升策略一致性。  
4. 主机级微隔离：在操作系统内核或Hypervisor层拦截东西向流量，实现虚拟机、容器间进程级通信控制，绕过传统网络层限制。  

三、典型类型与常见问题  
1. 传统三层分段：按部门/角色划分VLAN，依赖ACL和路由器子接口，易因配置错误导致跨VLAN逃逸。  
2. 零信任网络分段：以身份和设备健康度为策略依据，每次访问均需动态鉴权，不默认信任内网任何节点。  
3. 工控网络分段：常采用单向网闸或协议剥离网关隔离OT与IT网络，但部分老旧PLC缺乏TLS支持，导致加密分段失效。  
4. 云环境分段：依赖安全组、网络ACL及服务控制策略（SCP），但多账户共享资源时易出现策略覆盖盲区。  
5. 常见问题包括：分段粒度粗导致横向移动风险未收敛；策略长期未审计形成“策略腐化”；DNS/ICMP等低风险协议被忽略导致隧道隐蔽通信。  

四、防御措施与实践建议  
1. 实施最小权限原则：每个分段仅开放必要端口与协议，禁用默认允许规则，策略默认拒绝。  
2. 启用网络流量可视化：部署NetFlow/sFlow或eBPF探针，持续监控跨分段流量模式，识别异常横向扫描行为。  
3. 定期执行分段有效性验证：使用自动化工具模拟攻击路径（如BloodHound分析AD信任关系），检验策略阻断能力。  
4. 关键系统强制启用微隔离：对数据库、域控制器等高价值资产，在主机侧部署基于主机防火墙或eBPF的运行时策略。  
5. 建立分段策略生命周期管理：新业务上线前完成分段影响评估，策略变更须经双人复核并留存审计日志。  
6. 混合环境统一策略编排：使用支持多云与本地数据中心的策略即代码（Policy-as-Code）框架，避免策略碎片化。
