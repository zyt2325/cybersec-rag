僵尸网络检测

一、基本概念  
1. 僵尸网络是由攻击者远程控制的大量被感染主机（僵尸机）组成的协同攻击平台。  
2. 检测目标是识别异常通信行为、恶意指令交互或资源滥用特征，而非仅发现单个恶意文件。  
3. 僵尸网络具备隐蔽性、分布式和命令-控制（C&C）依赖性三大核心属性。  
4. 检测范围覆盖网络层（如异常DNS请求）、主机层（如进程异常驻留）及协议层（如HTTP隧道化）。  

二、原理与关键机制  
1. 基于流量分析：识别C&C通信的周期性、低频高熵、非标准端口或域名生成算法（DGA）特征。  
2. 行为建模检测：构建正常主机/网络基线，通过偏差分析发现横向移动、扫描或DDoS反射行为。  
3. 协议语义解析：检查HTTP/HTTPS中异常User-Agent、非常规URI路径或TLS指纹异常等C&C伪装痕迹。  
4. DNS日志挖掘：检测高频NXDOMAIN响应、短生存期域名查询或与已知恶意DGA家族匹配的域名模式。  
5. 主机侧轻量代理：监控注册表启动项、服务创建、进程注入链及网络套接字绑定异常。  

三、典型类型与常见问题  
1. P2P型僵尸网络无中心C&C，依赖节点间加密广播通信，导致传统流量汇聚点检测失效。  
2. IoT僵尸网络常利用默认凭证暴力破解，设备资源受限使内存驻留型检测难以部署。  
3. 加密C&C通道（如Tor、Telegram Bot API）掩盖IP和内容，需结合元数据与行为关联分析。  
4. 混合型僵尸网络动态切换C&C协议（如HTTP→DNS→ICMP），规避单一协议规则检测。  
5. 误报率高：合法CDN、云服务心跳包或自动化运维脚本易被误判为C&C通信。  
6. 隐蔽信道滥用：利用DNS TXT记录、HTTP Header字段或图像LSB隐写传递指令，绕过内容审查。  

四、防御措施与实践建议  
1. 部署分层检测：网络边界用NetFlow/SIEM做宏观流量聚类，终端用EDR采集进程树与网络连接上下文。  
2. 维护动态威胁情报：集成IP、域名、证书哈希等IOC，并支持实时更新DGA模型与C&C域名TLD分布特征。  
3. 实施DNS审计策略：强制所有DNS查询经企业解析器，记录完整查询链并标记非常规递归深度与响应类型。  
4. 限制横向移动能力：关闭不必要的SMB/RDP服务，启用网络分段与微隔离策略，压缩攻击面。  
5. 定期固件安全评估：对IoT/OT设备验证签名机制、禁用调试接口、修补已知CVE漏洞（如CVE-2017-8225）。  
6. 开展红蓝对抗演练：模拟不同C&C协议切换场景，验证检测规则覆盖率与响应流程有效性。
