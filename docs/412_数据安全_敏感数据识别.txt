敏感数据识别

一、基本概念  
1. 敏感数据识别是指通过自动化或半自动化手段，从结构化与非结构化数据中定位符合预定义敏感属性的数据项。  
2. 其核心目标是发现个人身份信息（PII）、支付卡信息（PCI）、健康信息（PHI）等受法律或合规框架保护的数据。  
3. 识别结果需明确标注数据类型、置信度、位置（如数据库字段名、日志行号、文件路径）及上下文环境。  
4. 不同法规对敏感数据的定义存在差异，例如GDPR将生物识别数据列为特殊类别，而中国《个人信息保护法》明确“不满十四周岁未成年人信息”为敏感个人信息。  

二、原理与关键机制  
1. 基于规则的方法依赖正则表达式、关键词词典和格式模板（如16位连续数字+校验位匹配银行卡号）。  
2. 基于机器学习的方法利用标注样本训练分类器，识别上下文语义特征（如“身份证号：”后接18位字符序列）。  
3. 混合识别引擎通常串联规则初筛与模型精判，兼顾准确率与误报率平衡，支持动态阈值调整。  
4. 数据溯源机制记录识别过程元数据，包括扫描时间、策略版本、匹配规则ID及原始数据哈希，支撑审计追溯。  

三、典型类型与常见问题  
1. 静态数据识别失效：加密存储但密钥管理不当，导致密文仍可被模式分析推断（如固定IV下AES-ECB相同明文产生相同密文）。  
2. 动态数据漏检：API响应体中的临时令牌、JWT载荷内嵌的手机号未被实时解析识别。  
3. 影子数据风险：开发测试库误用生产脱敏数据，或员工本地Excel缓存含未加密身份证号。  
4. 多语言混淆绕过：使用全角数字、形近字（如“０”替代“0”）、Base64编码片段规避简单正则匹配。  

四、防御措施与实践建议  
1. 实施数据分类分级制度，按泄露影响程度划分L1–L4级，并为每级配置差异化识别策略与响应SLA。  
2. 在CI/CD流水线嵌入敏感数据扫描插件，对代码仓库提交的SQL脚本、配置文件、日志模板实施静态扫描。  
3. 对数据库执行动态脱敏策略：仅对具备特定RBAC权限的会话返回真实PII，其余返回泛化值（如“张*”）。  
4. 定期验证识别覆盖率，使用红队构造的对抗样本集（含编码变异、分段拼接、注释干扰等）检验引擎鲁棒性。  
5. 建立敏感数据登记台账，关联数据资产目录，明确责任人、存储位置、加密状态及最近一次识别时间戳。
