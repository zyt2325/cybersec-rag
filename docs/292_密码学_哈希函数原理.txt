哈希函数原理

一、基本概念  
1. 哈希函数是将任意长度输入映射为固定长度输出的确定性数学函数，输出称为哈希值或摘要。  
2. 具备单向性：由输入可高效计算哈希值，但无法从哈希值反推原始输入。  
3. 输入微小变化（如修改1比特）会导致输出显著不同，该特性称为雪崩效应。  
4. 理想哈希函数应满足强抗碰撞性：难以找到两个不同输入产生相同哈希值。  

二、原理与关键机制  
1. 哈希函数通常采用迭代结构，将输入分块处理，每轮使用压缩函数更新中间状态。  
2. 压缩函数是核心组件，接收前一轮状态和当前数据块，输出新状态，依赖非线性变换与位操作。  
3. 初始向量（IV）为预定义常量，确保相同输入在不同实现中生成一致哈希值。  
4. 填充机制（如MD结构中的长度附加）防止长度扩展攻击，保障消息完整性验证可靠性。  
5. 所有运算均在有限域或布尔代数上执行，避免浮点误差，确保跨平台结果一致性。  

三、典型类型与常见问题  
1. MD5（128位）与SHA-1（160位）已被证实存在实用碰撞攻击，禁止用于安全场景。  
2. SHA-2系列（如SHA-256、SHA-512）目前仍被广泛采用，具备良好抗碰撞性与性能平衡。  
3. SHA-3（Keccak）采用海绵结构，与SHA-2设计范式不同，提供额外算法多样性保障。  
4. 原始哈希不适用于密码存储：未加盐哈希易受彩虹表攻击，且无法抵御暴力枚举。  
5. 长度扩展攻击可利用MD结构缺陷，由H(M)和len(M)构造H(M||pad||M′)，破坏认证完整性。  

四、防御措施与实践建议  
1. 密码哈希必须使用专用方案（如Argon2、scrypt、bcrypt），强制引入盐值与可调计算成本。  
2. 数字签名与证书验证中优先选用SHA-256及以上强度哈希，禁用SHA-1及更弱算法。  
3. 实现HMAC时须使用标准密钥派生方式，避免直接拼接密钥与消息导致的安全降级。  
4. 对于需验证完整性的协议（如TLS 1.3），哈希函数必须与密码套件绑定，禁止运行时协商弱哈希。  
5. 开发中禁用自定义哈希逻辑，所有哈希操作应调用操作系统或主流密码库（如OpenSSL、libsodium）提供的经审计接口。  
6. 固件/固件更新包签名验证必须校验哈希值长度与算法标识符，防范算法降级攻击。
