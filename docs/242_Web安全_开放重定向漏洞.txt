开放重定向漏洞

一、基本概念  
1. 开放重定向漏洞指Web应用未经校验或校验不严，将用户提交的URL参数直接用于HTTP跳转响应（如302状态码）。  
2. 该漏洞本质是服务端对重定向目标地址缺乏可信性控制，导致攻击者可构造恶意跳转链接。  
3. 常见于登录后跳转、密码找回完成页、OAuth回调等需动态指定跳转地址的功能点。  
4. 漏洞本身不直接导致服务器入侵，但常作为钓鱼、CSRF、权限提升等攻击链的中间环节。  

二、原理与关键机制  
1. Web应用接收客户端传入的redirect_url、next、return_url等参数，未验证其协议、域名、路径合法性。  
2. 服务端直接拼接该参数值生成Location响应头，浏览器执行跳转时无二次校验。  
3. 攻击者可构造形如https://victim.com/login?next=https://evil.com/phish的URL诱导用户点击。  
4. 浏览器地址栏显示合法域名，但跳转后实际访问恶意站点，用户难以察觉。  
5. 若目标站点启用CORS且允许任意Origin，配合重定向可能绕过同源策略限制。  

三、典型类型与常见问题  
1. 白名单校验绕过：仅校验host开头匹配，忽略协议替换（如http://evil.com@victim.com）或Unicode欺骗。  
2. 相对路径滥用：未禁止//evil.com或/\\evil.com等非标准路径格式，被浏览器解析为绝对URL。  
3. 协议剥离缺陷：过滤http://但未拦截javascript:、data:等危险协议，导致XSS式跳转。  
4. 多层跳转链：前端JS解析后端返回的重定向URL再执行window.location，绕过服务端校验。  
5. OAuth授权流程中state参数缺失或校验失效，配合redirect_uri参数劫持实现账户接管。  

四、防御措施与实践建议  
1. 禁止直接使用用户输入的URL进行重定向，优先采用预定义跳转码（如REDIR_HOME=1）映射内部路径。  
2. 如必须支持动态跳转，实施严格白名单校验：仅允许协议为https?、域名在预置列表内、路径以/开头且不含特殊字符。  
3. 使用URL解析库（如Java的java.net.URL、Python的urllib.parse）进行标准化后再校验，避免解析歧义。  
4. 对所有重定向响应添加X-Frame-Options: DENY和Referrer-Policy: no-referrer，降低钓鱼页面利用价值。  
5. 在登录等敏感操作后跳转前，校验Referer是否来自本站且会话有效，阻断跨域诱导跳转。  
6. 将重定向功能独立为专用接口，要求调用方提供签名或短期Token，并在服务端验证其完整性与时效性。
