车联网安全  

一、基本概念  
1. 车联网（IoV）指通过V2X通信技术实现车辆与车、路、云、人之间的实时信息交互的动态网络系统。  
2. 核心组成包括车载终端（T-Box/IVI）、路侧单元（RSU）、蜂窝网络（4G/5G）、云端平台及智能交通管理系统。  
3. 安全边界涵盖车载ECU、通信链路、远程服务平台、移动App及第三方服务接口等多维攻击面。  
4. 与传统IT系统不同，车联网需同时满足功能安全（ISO 26262）与信息安全（ISO/SAE 21434）双重合规要求。  

二、原理与关键机制  
1. V2X通信依赖IEEE 802.11p（DSRC）或C-V2X（LTE-V2V/V2I）协议，其广播特性易受伪造与重放攻击。  
2. 车载网络采用CAN、LIN、FlexRay等总线协议，其中CAN无身份认证与加密机制，存在帧注入风险。  
3. 远程诊断与升级（OTA）依赖TLS 1.2+双向证书认证，密钥管理不当将导致固件劫持或降级攻击。  
4. TSP（Telematics Service Provider）平台作为车云枢纽，需实施严格API网关鉴权、请求限流与日志审计。  

三、典型类型与常见问题  
1. ECU固件漏洞：如未校验OTA包签名、Bootloader弱加密，可被用于持久化植入恶意固件。  
2. 无线接口暴露：蓝牙、Wi-Fi模块若启用调试模式或默认凭证，可能成为本地渗透入口。  
3. 云平台配置缺陷：S3存储桶公开、API密钥硬编码于App中、未启用WAF，导致用户数据批量泄露。  
4. 第三方SDK风险：导航、支付类SDK权限过度申请，或存在已知CVE漏洞，引发横向越权访问。  
5. 伪基站攻击：利用LTE协议缺陷伪造合法基站，劫持车辆蜂窝通信并篡改导航指令。  

四、防御措施与实践建议  
1. 实施纵深防御：在T-Box部署轻量级HSM芯片，对关键密钥进行硬件级保护与隔离运算。  
2. 强化车载网络防护：在CAN网关部署入侵检测系统（IDS），基于CAN帧ID/周期/负载熵值建模异常行为。  
3. OTA全流程管控：采用ECU级签名验证（RSA-3072+SHA-256）、差分升级包加密、回滚保护及失败自动擦除机制。  
4. 云侧最小权限原则：TSP平台数据库按车型/用户分库分表，敏感字段（VIN、位置）强制AES-256加密存储。  
5. 建立V2X证书生命周期管理体系：使用PKI架构签发短时效（≤24h）一次性证书，支持OCSP实时吊销查询。  
6. 开展红蓝对抗演练：针对TSP平台、车载App及V2X消息解析模块，每季度执行Fuzz测试与协议栈模糊测试。
