云存储桶配置错误

一、基本概念  
1. 云存储桶是对象存储服务（如AWS S3、阿里云OSS、Azure Blob Storage）中用于存放数据的逻辑容器。  
2. 桶本身无层级结构，但通过对象键名模拟路径，其访问控制独立于用户账户或应用权限体系。  
3. 配置错误指因策略设置不当导致桶或其中对象被非授权方发现、读取、写入甚至删除。  
4. 错误配置不依赖代码漏洞或身份认证绕过，仅由权限策略、ACL或CORS等元数据配置失误引发。  
5. 公共可读桶常被搜索引擎爬取，形成“云数据泄露”入口，已成为威胁情报平台重点监控目标。

二、原理与关键机制  
1. 对象存储采用基于策略的访问控制（如S3 Bucket Policy），策略优先级高于IAM策略和ACL。  
2. ACL（访问控制列表）支持对单个对象或整个桶设置READ、WRITE、FULL_CONTROL等细粒度权限。  
3. CORS配置若允许任意源（*）且启用credentials，可能被恶意网站利用发起跨域数据窃取。  
4. 存储桶版本控制与生命周期策略若配置不当，可能使已删除对象仍可通过版本ID恢复并暴露。  
5. 匿名访问开关（如S3的Block Public Access设置）为全局开关，关闭后需逐桶验证生效状态。

三、典型类型与常见问题  
1. 公共读取桶：Bucket Policy或ACL显式授予`"Principal": "*"`且`"Action": "s3:GetObject"`。  
2. 可列举桶：策略允许`s3:ListBucket`且Principal为`*`，攻击者可遍历全部对象键名。  
3. 错误继承策略：父级组织单元策略未显式拒绝公共访问，导致子桶默认继承宽松权限。  
4. 过期密钥残留：使用临时凭证上传对象后未清理预签名URL，导致长期有效公开链接。  
5. 静态网站托管误配：启用静态网站托管时未关闭索引文档和错误文档的公共读取权限。

四、防御措施与实践建议  
1. 默认禁用公共访问：在云平台启用Block Public Access全局开关，并定期审计例外白名单。  
2. 实施最小权限原则：使用显式拒绝策略（Deny）覆盖潜在宽松规则，避免依赖隐式拒绝。  
3. 自动化检测：部署CI/CD阶段扫描工具（如Checkov、tfsec）检查IaC模板中的桶策略硬编码风险。  
4. 启用服务器端加密（SSE）并强制加密：配置S3 SSE-S3或KMS密钥，阻止未加密对象上传。  
5. 日志与告警联动：开启S3 Server Access Logging与CloudTrail日志，对`ListBucket`和`GetObject`异常频次触发告警。  
6. 定期权限评审：每季度执行桶策略有效性验证，使用`aws s3api get-bucket-policy-status`等API确认实际生效策略。
