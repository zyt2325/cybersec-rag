业务逻辑漏洞

一、基本概念  
1. 业务逻辑漏洞指应用程序在实现业务流程时，因设计或实现缺陷导致安全策略被绕过，而非由传统输入验证缺失引起。  
2. 此类漏洞不依赖代码层缺陷（如SQL注入），而是源于对用户行为、状态流转或业务规则的错误假设。  
3. 攻击者通过合法功能组合、时序操控或状态篡改达成非预期操作，如越权购买、重复领取优惠券。  
4. 漏洞隐蔽性强，自动化扫描工具难以识别，需结合业务上下文进行人工逻辑分析。  
5. 影响范围覆盖电商、金融、身份认证等强业务耦合系统，常导致资金损失、数据泄露或服务滥用。

二、原理与关键机制  
1. 应用程序未对业务状态进行一致性校验，例如支付完成前允许重复提交订单。  
2. 依赖客户端控制流程（如隐藏字段、前端JS跳转）决定关键路径，而服务端未同步验证状态合法性。  
3. 并发处理缺失原子性保障，导致竞态条件，如库存超卖、优惠券重复核销。  
4. 业务规则硬编码且未做动态校验，例如仅检查用户登录状态，未验证其是否具备当前操作权限。  
5. 状态机设计不完整，缺少非法状态转移拦截，如跳过实名认证直接进入提现环节。

三、典型类型与常见问题  
1. 越权操作：水平越权（同角色用户间数据访问）、垂直越权（低权限用户执行高权限操作）。  
2. 流程绕过：跳过必要步骤（如未验证短信验证码即重置密码）、逆序执行（先发货后付款）。  
3. 数值篡改：修改价格参数、数量字段或折扣率，服务端未二次校验原始业务值。  
4. 时序攻击：利用操作时间差（如两次请求间隔）触发逻辑冲突，如抢购场景中并发下单成功。  
5. 状态残留：会话或事务异常终止后，服务端未清理临时状态，导致后续操作复用旧状态。

四、防御措施与实践建议  
1. 实施服务端强制状态校验，所有关键操作前验证当前业务状态、用户权限及上下文完整性。  
2. 关键业务流程采用服务端驱动的状态机，禁止客户端传递状态标识，仅接受动作指令。  
3. 对金额、数量、资格等敏感业务参数，服务端必须基于原始订单/账户数据实时计算并比对。  
4. 并发操作使用数据库行锁、乐观锁或分布式锁保障原子性，避免竞态引发逻辑错误。  
5. 建立业务逻辑威胁建模流程，在需求与设计阶段识别状态分支、权限边界和异常路径。  
6. 开发测试阶段引入业务逻辑专项用例，覆盖异常顺序、边界条件、多步组合及失败恢复场景。
