反射型XSS

一、基本概念  
1. 反射型XSS是一种非持久化跨站脚本攻击，恶意脚本通过URL参数传入服务器后立即返回给用户浏览器执行。  
2. 攻击载荷不存储于服务端，仅在单次HTTP响应中“反射”回客户端，依赖用户主动触发（如点击恶意链接）。  
3. 典型场景包括搜索框、错误提示页、跳转URL等直接将用户输入嵌入HTML响应体的接口。  
4. 与存储型XSS不同，其危害范围受限于传播能力，但利用门槛低、检测难度高。  

二、原理与关键机制  
1. 服务端未对HTTP请求参数（如GET/POST中的query string）进行充分校验或编码，直接拼接进HTML输出流。  
2. 浏览器解析响应时，将嵌入的恶意脚本（如<script>标签或事件处理器）当作合法JavaScript执行。  
3. 关键触发条件是输入数据未经HTML实体编码、JavaScript字符串转义或上下文感知处理即输出到页面。  
4. 攻击成功依赖浏览器同源策略未阻断脚本执行，且目标用户已登录受信站点（可窃取会话Cookie等敏感信息）。  

三、典型类型与常见问题  
1. URL参数型：攻击者构造含恶意脚本的URL（如?name=<script>alert(1)</script>），诱导用户访问。  
2. 错误消息反射：服务端将未过滤的错误参数（如?lang=zh"><svg/onload=alert(1)>）直接写入错误提示HTML。  
3. HTTP头部反射：部分应用将Referer、User-Agent等头字段内容输出至页面，形成隐式反射入口。  
4. 编码绕过问题：攻击者使用HTML实体编码（&#x3C;script&#x3E;）、URL编码（%3Cscript%3E）规避简单黑名单过滤。  
5. 上下文混淆漏洞：同一参数在HTML标签、属性、JavaScript字符串等不同上下文中输出，未做差异化编码处理。  

四、防御措施与实践建议  
1. 对所有动态输出到HTML页面的用户输入，严格实施上下文相关的输出编码：HTML实体编码、属性值引号转义、JS字符串转义等。  
2. 优先采用现代框架内置的自动转义机制（如React JSX、Vue模板、Thymeleaf），禁用不安全的原始HTML渲染API（如innerHTML、document.write）。  
3. 设置HTTP响应头Content-Security-Policy，明确限制脚本来源（如script-src 'self'），阻止内联脚本和eval执行。  
4. 对URL参数实施白名单校验（如正则匹配数字/字母组合），拒绝包含尖括号、引号、script、onerror等危险字符的输入。  
5. 使用HttpOnly标志保护Cookie，防止XSS窃取会话标识；配合SameSite=Lax/Cookie属性降低CSRF协同风险。  
6. 在开发阶段集成自动化扫描工具（如OWASP ZAP、Burp Suite被动扫描），覆盖常见反射点并验证编码有效性。
