SHA系列算法

一、基本概念  
1. SHA（Secure Hash Algorithm）是由美国NIST设计的一组密码学哈希函数，用于生成固定长度的消息摘要。  
2. 所有SHA算法均满足单向性、抗碰撞性和雪崩效应等密码学哈希基本安全属性。  
3. SHA-0于1993年发布但很快被弃用；SHA-1、SHA-2、SHA-3构成当前主流演进序列，彼此结构与设计原理差异显著。  
4. 输出长度是区分SHA变体的关键标识：SHA-1输出160位，SHA-2包含224/256/384/512位多种变体，SHA-3则基于Keccak结构提供相同长度选项。  

二、原理与关键机制  
1. SHA-1与SHA-2采用Merkle-Damgård构造，将消息分块后经多轮压缩函数迭代处理，最终输出摘要。  
2. SHA-2各变体共享核心逻辑，仅通过初始哈希值、轮数、消息扩展及压缩函数常量区分位宽，非简单截断。  
3. SHA-3采用海绵结构（sponge construction），以Keccak-f[1600]置换为核心，通过吸收-挤压两阶段实现哈希计算。  
4. 所有SHA算法均内置消息填充机制：在消息末尾追加‘1’比特、若干‘0’比特及64位原始消息长度（大端序）。  
5. 轮函数设计依赖非线性布尔函数（如SHA-2的Σ、σ、Ch、Maj）、循环移位及模加运算，增强扩散与混淆能力。  

三、典型类型与常见问题  
1. SHA-1已被证实存在理论碰撞攻击（如2017年SHAttered），实际碰撞可在2^63次哈希操作内构造，不再适用于数字签名。  
2. SHA-2目前未发现实用碰撞攻击，但SHA-224/256在TLS 1.2中仍广泛使用，而SHA-384/512更适用于高安全等级场景。  
3. SHA-3并非SHA-2的直接替代，而是作为结构多样性备份：其抗量子计算潜力略优，但性能与SHA-256相近。  
4. 常见误用包括：用SHA-1校验固件完整性、在证书签名中继续使用SHA-1、对短口令直接哈希而无盐值与迭代。  
5. 硬件实现中，SHA-256存在侧信道风险（如功耗分析可推断轮密钥），需部署掩码或恒定时间实现缓解。  

四、防御措施与实践建议  
1. 禁止在新系统中使用SHA-1，存量系统须制定迁移计划，优先升级至SHA-256或SHA-3-256。  
2. 数字签名场景应采用带随机化机制的方案（如RSA-PSS、ECDSA），避免确定性哈希直接参与签名运算。  
3. 密码存储必须结合强盐值（128位以上随机）、密钥派生函数（如Argon2、PBKDF2）及足够迭代次数，禁用裸SHA哈希。  
4. 固件/软件更新验证应使用多重哈希（如SHA-256+SHA-3-256）或数字签名，避免单一哈希算法失效导致信任链断裂。  
5. 在资源受限设备上部署SHA-2时，优先选用硬件加速模块并启用防侧信道固件补丁，禁用软件查表实现。  
6. 开发者应依赖操作系统或标准密码库（如OpenSSL 3.0+、BoringSSL）提供的抽象接口，避免自行实现SHA逻辑。
