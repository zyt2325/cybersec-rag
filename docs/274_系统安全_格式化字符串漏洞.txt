格式化字符串漏洞

一、基本概念  
1. 格式化字符串漏洞是因程序将用户可控数据直接作为格式化字符串参数传入printf等函数引发的内存安全缺陷。  
2. 该漏洞常见于C/C++语言中，源于对格式化函数参数校验缺失或不充分。  
3. 漏洞本质是攻击者通过构造含%符号的输入，干扰函数解析行为，进而读写任意内存地址。  
4. 不同于缓冲区溢出，其触发不依赖栈/堆布局破坏，而是利用格式化函数的参数解析机制。  
5. 即使无源码，也可通过二进制逆向识别可疑的printf-family调用点与用户输入拼接逻辑。

二、原理与关键机制  
1. printf类函数依据格式字符串中的转换说明符（如%x、%s、%n）从栈或寄存器中依次读取参数。  
2. 当格式字符串由用户控制且未固定时，函数会将栈上后续数据误认为参数，导致信息泄露或写操作。  
3. %n说明符可将已输出字符数写入指定地址，成为实现任意地址写入的关键原语。  
4. 利用%n配合栈偏移计算，可覆盖GOT表项、返回地址或函数指针，劫持控制流。  
5. %s和%x等读取类说明符可逐字节泄露栈/堆内容，用于绕过ASLR或定位敏感数据。

三、典型类型与常见问题  
1. 直接将用户输入拼接进格式字符串：sprintf(buf, "Error: " + user_input)。  
2. 使用未加引号的变量作为格式参数：printf(user_input)而非printf("%s", user_input)。  
3. 日志函数中错误地将用户输入作为格式串：log("User: %s", username) → log(username)。  
4. 宽字符函数（如wprintf）同样存在类似漏洞，需检查L"..."前缀与宽字符处理一致性。  
5. 静态分析工具常漏报间接调用场景，如通过函数指针调用printf且参数动态生成。

四、防御措施与实践建议  
1. 始终使用显式格式字符串：printf("%s", user_input)，禁止将用户数据置于第一个参数位置。  
2. 编译时启用-Wformat-security警告，并将-Werror=format-security纳入CI强制检查。  
3. 在GCC/Clang中启用-fstack-protector-strong和-fPIE -pie，增加利用难度。  
4. 对日志、调试输出等高风险接口实施输入白名单过滤，禁用%字符或转义处理。  
5. 使用安全替代函数：snprintf代替sprintf，fprintf_s（C11 Annex K）或自定义封装层。  
6. 在关键服务中启用FORTIFY_SOURCE=2，使部分格式化调用在运行时检测非法参数。
