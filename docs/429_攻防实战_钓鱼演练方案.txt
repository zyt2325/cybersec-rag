钓鱼演练方案

一、基本概念  
1. 钓鱼演练是组织在授权范围内模拟真实钓鱼攻击，用于检验人员安全意识与响应流程的实战化评估活动。  
2. 演练需明确范围、对象、时间、目标系统及合规边界，须经法务与管理层书面审批并留存记录。  
3. 不同于渗透测试，其核心评估指标为人因响应行为（如点击率、上报率、密码提交率），而非系统漏洞利用成功率。  
4. 演练前必须向全员发布《演练告知书》，说明活动性质、时间窗口及免责条款，避免引发恐慌或法律风险。  

二、原理与关键机制  
1. 利用认知偏差（如权威效应、紧迫感、社会认同）设计诱饵内容，触发非理性决策路径。  
2. 通过伪造可信信源（如仿冒内部邮箱域名、克隆OA登录页、伪装IT部门通知）降低用户警惕性。  
3. 采用分阶段诱导设计：首封邮件建立信任，后续链接跳转至高仿真钓鱼页面，部分场景嵌入无害JS行为日志采集。  
4. 所有钓鱼页面不收集真实凭证，仅记录访问IP、设备指纹、点击时间及表单提交动作，数据加密存储于内网专用平台。  

三、典型类型与常见问题  
1. 邮件钓鱼最常见，常伪造财务报销、会议纪要、系统升级等业务场景，附件含恶意宏或伪装PDF链接。  
2. 短信钓鱼（Smishing）多结合社保、快递、银行等公众服务名义，短链跳转至仿冒H5登录页。  
3. 语音钓鱼（Vishing）通过自动外呼提示“账户异常”，诱导回拨虚假客服号码并输入验证码。  
4. 演练中常见问题包括：未屏蔽测试邮件被误判为真实攻击、HR/高管账号成为高频靶标导致数据失真、第三方协作方未纳入演练范围形成盲区。  

四、防御措施与实践建议  
1. 建立分级演练机制：新员工入职首月必测，全员每季度覆盖，高危岗位（财务、采购）每月加测。  
2. 钓鱼页面必须强制启用HTTPS且证书有效，禁止使用HTTP或自签名证书，防止浏览器地址栏显红警告干扰效果。  
3. 演练后72小时内完成个体反馈：向点击者推送定制化微课（含本次诱饵解析、识别要点、上报路径），避免简单通报批评。  
4. 将演练数据与SIEM系统联动：对重复多次点击者自动触发安全意识强化任务，对未点击但未上报者推送举报流程实操训练。  
5. 每次演练后修订《钓鱼事件响应SOP》，明确IT部门隔离账号、安全部门溯源分析、HR介入复盘的协同时序与责任接口。
