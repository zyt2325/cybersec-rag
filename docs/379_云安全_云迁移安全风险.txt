云迁移安全风险

一、基本概念  
1. 云迁移安全风险指组织将IT系统、数据和应用从本地环境迁移到公有云、私有云或混合云过程中引发的新型安全威胁。  
2. 迁移过程涉及网络架构重构、权限模型变更与数据流动路径扩展，导致传统边界防护失效。  
3. 风险具有阶段性特征：评估期存在资产识别盲区，迁移期面临数据泄露与配置漂移，上线后暴露持续性配置缺陷。  
4. 云服务共享责任模型决定风险归属：云服务商负责底层基础设施安全，客户须承担操作系统、应用、数据及访问控制安全。  

二、原理与关键机制  
1. 虚拟化抽象层引入新攻击面，如Hypervisor逃逸可跨租户获取宿主机控制权。  
2. API驱动的云资源编排依赖身份凭证（如IAM密钥），凭证泄露即等同于账户完全失陷。  
3. 自动化迁移工具若未校验源端镜像完整性或目标端配置基线，会将本地漏洞与错误策略带入云环境。  
4. 云网络默认“东西向流量开放”，缺乏微隔离机制时，单点入侵易横向蔓延至其他业务系统。  

三、典型类型与常见问题  
1. 数据残留风险：块存储卷、快照或对象存储桶未彻底擦除旧数据，且权限设置为公开读取。  
2. 身份与访问管理失控：过度授权的IAM角色、硬编码在代码中的API密钥、未轮换的长期凭证。  
3. 网络配置错误：安全组规则允许0.0.0.0/0访问数据库端口，NAT网关暴露内部服务至公网。  
4. 合规断层：迁移后日志未启用CloudTrail或Azure Activity Log，无法满足等保2.0或GDPR审计要求。  
5. 供应链引入风险：使用未经安全评估的第三方云市场镜像，内置后门或过期组件。  

四、防御措施与实践建议  
1. 实施迁移前安全评估：使用CSPM工具扫描本地环境配置基线，并映射至云平台对应安全控制项。  
2. 采用最小权限原则配置IAM策略，禁用root账户，强制启用MFA，定期轮换访问密钥并监控异常调用。  
3. 对敏感数据实施静态加密（KMS托管密钥）与传输中加密（TLS 1.2+），禁用明文存储凭证。  
4. 在迁移流水线中嵌入IaC安全检查（如Checkov、tfsec），阻断含高危配置的Terraform模板部署。  
5. 部署云工作负载保护平台（CWPP），实时检测运行时异常行为，如非常规时间的数据导出或横向扫描。  
6. 建立迁移后验证清单：确认日志全量采集、WAF规则生效、备份策略覆盖RPO/RTO要求、渗透测试完成。
