蜜罐技术

一、基本概念  
1. 蜜罐是一种主动防御技术，通过部署诱饵系统、服务或数据，吸引攻击者进行探测与交互。  
2. 其核心目标是延缓真实资产暴露、收集攻击行为特征、识别新型攻击手法及溯源攻击者。  
3. 蜜罐本身不提供业务功能，所有对其的访问均视为可疑或恶意行为，具备高置信度告警价值。  
4. 与防火墙、IDS等被动防御不同，蜜罐以“可被利用”为设计前提，强调行为诱导与深度观测。  

二、原理与关键机制  
1. 利用攻击者的侦察惯性：开放常见端口（如21、22、80、3389）并模拟弱配置，触发自动化扫描与漏洞利用尝试。  
2. 采用低交互或高交互架构：前者仅模拟服务响应（如Telnet banner），后者运行真实操作系统与服务以捕获深层行为。  
3. 实施严格网络隔离与流量镜像，确保蜜罐活动不影响生产环境，并支持全流量捕获与会话还原。  
4. 集成日志审计、命令记录与进程监控模块，对shell执行、文件写入、横向移动等操作进行细粒度取证。  

三、典型类型与常见问题  
1. 低交互蜜罐（如Cowrie、Dionaea）资源消耗低、部署快，但易被高级攻击者识别为仿真环境。  
2. 高交互蜜罐（如Honeyd定制节点、虚拟机蜜罐集群）可捕获0day利用链和持久化行为，但运维复杂、逃逸风险高。  
3. 数据库蜜罐通过伪造MySQL/PostgreSQL服务响应SQL注入探测，识别拖库意图与工具指纹。  
4. Web蜜罐常部署虚假登录页、API接口或Git仓库，用于捕获凭证爆破、目录遍历及敏感信息泄露尝试。  
5. 常见问题包括：蜜罐被攻陷后反向渗透内网、误判合法扫描（如合规安全评估）、日志过载导致分析失效。  

四、防御措施与实践建议  
1. 禁止蜜罐直接接入生产网段，必须通过VLAN隔离、ACL策略及单向路由限制其出站能力。  
2. 在蜜罐前端部署透明代理或eBPF过滤器，实时阻断已知C2域名解析与恶意IP通信，防止失陷后成为跳板。  
3. 定期轮换蜜罐指纹（如SSH banner、HTTP Server头、TLS证书信息），避免被攻击者构建蜜罐特征库规避。  
4. 将蜜罐日志接入SIEM平台，关联分析源IP历史行为、攻击载荷相似性及多蜜罐协同攻击模式。  
5. 企业级部署应分层设计：外网边界用轻量低交互蜜罐快速发现扫描；内网关键区域部署高交互蜜罐监测横向移动。  
6. 所有蜜罐须配置自动快照与只读磁盘，每次交互后重置状态，确保环境一致性与证据链完整性。
