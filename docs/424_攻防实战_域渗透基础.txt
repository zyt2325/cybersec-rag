域渗透基础

一、基本概念  
1. 域渗透指攻击者在已获取域内一个或多个主机权限后，通过合法协议与信任关系横向移动并提升权限的过程。  
2. Windows域环境以Active Directory（AD）为核心，依赖Kerberos认证、LDAP目录服务和DNS解析协同工作。  
3. 域控制器（DC）存储所有用户、组、策略及密码哈希等核心安全数据，是域渗透的终极目标节点。  
4. 域内信任关系包括父子域、林信任及外部信任，可被利用实现跨域横向移动。  
5. 管理员账户（如Domain Admins、Enterprise Admins）拥有对整个域的完全控制权，是高价值提权目标。

二、原理与关键机制  
1. Kerberos协议中TGT与ST票据的重用或伪造（如黄金票据、白银票据）可绕过密码验证实现持久化访问。  
2. NTLM中继攻击利用NTLMv1/v2协议无签名保护缺陷，将客户端认证流量转发至其他服务完成身份冒用。  
3. LDAP查询可枚举用户、组、GPO、SPN等信息，为后续攻击提供目标画像与路径规划依据。  
4. GPO对象通过SYSVOL共享分发，若配置不当（如包含明文密码或脚本），可能被读取或篡改用于执行任意代码。  
5. DCSync攻击模拟域控制器行为，调用DRSUAPI接口从DC同步用户密码哈希，需具备Replicating Directory Changes权限。

三、典型类型与常见问题  
1. 凭据转储：通过Mimikatz等工具提取lsass进程内存中的明文密码、NTLM哈希或Kerberos票据。  
2. Pass-the-Hash：使用窃取的NTLM哈希替代密码进行SMB/WMI等协议认证，绕过密码复杂度限制。  
3. Pass-the-Ticket：导入窃取的Kerberos票据（如TGT）直接访问目标服务，无需原始密码或密钥。  
4. 常见配置风险包括：域管理员长期登录普通工作站、弱口令域账户、未禁用NTLMv1、SYSVOL脚本滥用。  
5. 服务主体名称（SPN）注册不当易引发Kerberoasting攻击，攻击者可离线爆破加密的TGS票据。

四、防御措施与实践建议  
1. 启用LSA保护（RunAsPPL）与Credential Guard，隔离lsass进程并虚拟化凭据存储空间。  
2. 强制启用Kerberos签名与通道绑定，禁用NTLMv1，对关键服务（如LDAP、SMB）启用LDAP签名和SMB签名。  
3. 实施最小权限原则：分离管理账户与日常账户，禁用域管理员账户的交互式登录，启用JIT特权管理。  
4. 定期审计DC上的敏感权限分配（如DS-Replication、GenericAll）、异常SPN注册及GPO修改日志。  
5. 部署EDR与SIEM系统，监控可疑行为：如非DC主机发起DCSync请求、高频Kerberos预认证失败、异常LDAP匿名绑定。  
6. 将域控制器置于专用网段，禁用不必要的服务端口（如135/139/445/389/636/3268/3269），严格控制入站访问策略。
