浏览器指纹识别

一、基本概念  
1. 浏览器指纹识别是通过采集客户端浏览器及设备的软硬件配置特征，生成唯一或高度可区分标识的技术。  
2. 不依赖Cookie或本地存储，属于无状态追踪手段，可在用户禁用第三方Cookie后仍持续识别。  
3. 指纹本身不直接包含身份信息，但结合行为日志可实现跨站点用户关联与长期跟踪。  
4. 属于被动式客户端侧探测技术，通常由网页JavaScript脚本在页面加载时静默执行特征采集。  
5. 全球主流网站中约20%使用至少一种指纹识别方案，常见于广告平台、反欺诈系统与访问控制模块。

二、原理与关键机制  
1. 基于浏览器环境的“熵值”差异：不同设备/配置组合产生的特征向量具有统计学唯一性。  
2. 特征采集分层进行：包括HTTP请求头（User-Agent、Accept-Language）、DOM属性（screen.width、navigator.plugins）、Canvas/WebGL渲染输出哈希等。  
3. Canvas指纹利用GPU驱动、字体渲染引擎和图形栈差异，使相同绘图指令在不同设备生成像素级不同的图像哈希。  
4. WebGL指纹通过查询显卡厂商、渲染器字符串及浮点数精度行为，暴露底层图形硬件抽象层细节。  
5. 字体枚举通过document.fonts.check()或CSS fallback检测，推断系统已安装字体集合，构成高区分度特征。

三、典型类型与常见问题  
1. 硬件级指纹：如AudioContext采样率偏差、电池API剩余容量（已废弃但历史影响显著）、陀螺仪噪声模式。  
2. 软件配置指纹：时区、语言偏好、屏幕缩放比例、触摸支持标志、WebRTC本地IP泄露（非公网地址）。  
3. 隐私合规风险：GDPR与CCPA将稳定可识别的指纹视为个人数据，未经明确同意采集可能构成违规。  
4. 误识别率受虚拟化环境影响：Docker容器、云桌面、远程浏览器隔离（RBI）常导致指纹异常集中或失真。  
5. 指纹稳定性矛盾：插件更新、系统升级、浏览器版本迭代会改变特征值，降低长期追踪可靠性。

四、防御措施与实践建议  
1. 浏览器层面：启用Firefox的resistFingerprinting=true配置，或使用Tor Browser默认启用的指纹混淆策略。  
2. 扩展防护：部署uBlock Origin配合高级过滤规则，阻止已知指纹脚本域名及Canvas/WebGL API调用钩子。  
3. 开发者规避：网站应避免主动调用navigator.plugins、window.outerWidth等高熵API；对必需特征做离散化处理（如仅保留时区偏移整小时数）。  
4. 企业级方案：部署前端代理服务统一重写User-Agent、标准化屏幕尺寸上报、注入随机化Canvas渲染噪声。  
5. 合规设计：实施指纹采集前须完成DPIA（数据保护影响评估），提供显式开关并记录用户授权状态。  
6. 测试验证：使用fpdetective、AmIUnique等开源工具定期扫描自身站点，量化指纹熵值并识别高风险API调用链。
