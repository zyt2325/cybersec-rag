IaaS安全

一、基本概念  
1. IaaS是云服务模型之一，提供虚拟化计算资源（如虚拟机、存储、网络），用户负责操作系统及上层安全。  
2. 共享责任模型明确划分云服务商与用户的安全边界：云厂商保障物理设施与虚拟化层安全，用户管理客户操作系统、应用与数据。  
3. IaaS环境的核心资产包括虚拟机镜像、实例元数据、API密钥、租户隔离状态及网络策略配置。  
4. 与PaaS/SaaS不同，IaaS中用户拥有完整的管理员权限（如root或Administrator），需自主实施补丁管理、防火墙配置和日志审计。  

二、原理与关键机制  
1. 虚拟化层（Hypervisor）是安全基石，其漏洞可能导致跨租户逃逸；主流方案如KVM、Xen、ESXi均依赖硬件辅助虚拟化（Intel VT-x/AMD-V）增强隔离。  
2. 元数据服务（如AWS IMDS、Azure Instance Metadata Service）通过本地HTTP端点向实例提供配置信息，若未限制访问或启用v2令牌机制，易被恶意进程窃取凭证。  
3. 软件定义网络（SDN）实现逻辑网络隔离，但VLAN/QinQ或VXLAN配置错误可能引发流量旁路或广播域越界。  
4. 镜像供应链存在风险：基础镜像若含后门、过期软件包或硬编码密钥，将污染所有衍生实例。  

三、典型类型与常见问题  
1. 虚拟机逃逸攻击利用Hypervisor漏洞突破隔离，获取宿主机控制权，进而影响其他租户实例。  
2. API密钥泄露常因开发人员硬编码于代码、配置文件或日志中，导致未授权调用创建高权限实例或导出敏感数据。  
3. 安全组/网络ACL配置宽松（如0.0.0.0/0开放SSH/RDP）使实例直接暴露于互联网扫描与暴力破解。  
4. 实例元数据服务未禁用v1或未启用IMDSv2强制令牌验证，允许任意进程读取IAM角色临时凭证。  
5. 快照与AMI未加密存储，且权限设置为公开，导致镜像被未授权下载并逆向分析。  

四、防御措施与实践建议  
1. 启用Hypervisor安全加固：关闭不必要的虚拟设备（如软驱、串口），禁用VMware Tools等工具的guest命令执行功能。  
2. 实施最小权限API密钥策略：使用短期凭证（STS AssumeRole）、禁用root密钥，结合IAM策略限制操作范围与资源条件。  
3. 强制启用实例元数据服务v2，并设置跳数限制（hop limit=1），禁止v1端点响应。  
4. 对所有启动镜像进行自动化安全扫描：检测CVE漏洞、弱密码账户、非标准SSH密钥及可疑进程。  
5. 网络层采用分层防护：安全组仅放行必需端口，配合网络ACL做子网级过滤，关键实例部署在私有子网并禁用公网IP。  
6. 加密静态数据：启用EBS卷、S3存储桶、快照的默认KMS加密，密钥轮换周期不超过90天。
