隐私计算技术

一、基本概念  
1. 隐私计算是在数据不离开本地前提下，实现多方协同建模与分析的密码学与分布式计算融合技术。  
2. 核心目标是保障原始数据“可用不可见、可算不可得”，满足GDPR、《个人信息保护法》等合规要求。  
3. 区别于传统脱敏或加密存储，隐私计算支持密态下的运算，输出结果不含原始敏感字段。  
4. 应用场景包括联合风控建模、跨机构医疗研究、政务数据共享等需打破数据孤岛但严守隐私边界的领域。  

二、原理与关键机制  
1. 安全多方计算（MPC）通过秘密分享、混淆电路或不经意传输协议，使各参与方仅获最终结果，无法反推他人输入。  
2. 同态加密（HE）允许在密文上直接执行加法/乘法运算，解密后结果等价于明文运算，但计算开销显著增加。  
3. 可信执行环境（TEE）利用CPU硬件级隔离区（如Intel SGX、ARM TrustZone）运行敏感代码，防止OS及管理员窥探内存。  
4. 差分隐私（DP）通过向查询结果注入可控噪声，使任意单条记录的存在与否对输出影响有严格数学界约束。  

三、典型类型与常见问题  
1. 联邦学习属于纵向/横向隐私计算架构，但客户端梯度上传仍存在模型反演或成员推理攻击风险。  
2. MPC协议在三元组预处理阶段若被篡改，可能导致协议失效或泄露中间状态；通信轮数多易引发延迟瓶颈。  
3. TEE面临侧信道攻击（如缓存时序、SGX分支预测漏洞），且依赖厂商固件可信，存在供应链信任风险。  
4. 同态加密密钥管理复杂，密钥泄露即导致全量密文被破解；部分方案不支持高效比较或分支操作。  
5. 差分隐私噪声强度与效用呈负相关，高隐私预算（ε>2）易致统计结果失真，低预算则防护能力下降。  

四、防御措施与实践建议  
1. 采用混合架构：如MPC+TEE组合，用TEE加速MPC预处理，同时规避纯软件协议的可信假设缺陷。  
2. 实施最小化噪声注入：依据具体查询敏感度动态调整差分隐私ε值，结合自适应采样降低效用损失。  
3. 对联邦学习客户端实施梯度裁剪与高斯噪声注入，并禁用原始梯度上传，强制使用安全聚合协议（SecAgg）。  
4. TEE应用须启用远程证明机制，每次启动校验飞地完整性，且禁止将敏感数据持久化至非受信内存。  
5. 同态加密部署中，优先选用CKKS方案处理浮点模型参数，密钥生命周期由HSM硬件模块托管。  
6. 所有隐私计算系统需通过第三方形式化验证（如ProVerif验证协议安全性）及渗透测试（聚焦旁路与协议逻辑漏洞）。
