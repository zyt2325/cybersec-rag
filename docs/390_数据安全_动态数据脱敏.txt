动态数据脱敏  

一、基本概念  
1. 动态数据脱敏（DDM）是在数据查询或访问过程中实时对敏感字段实施遮蔽、替换或泛化的技术，原始存储数据保持不变。  
2. 区别于静态脱敏（SDM），DDM不生成副本，而是依据访问者身份、角色、上下文等策略，在返回结果前即时处理数据流。  
3. 主要部署在数据库代理层、中间件或应用网关，对上层应用透明，无需修改业务逻辑或SQL语句。  
4. 适用于生产环境高频读取场景，如客服系统、BI报表平台及API接口，兼顾合规性与可用性。  

二、原理与关键机制  
1. 请求拦截：通过数据库驱动代理、SQL解析器或网络层hook捕获原始查询请求，提取目标表、字段、谓词条件等元信息。  
2. 策略匹配：基于预定义规则引擎，结合用户属性（如部门、权限等级）、会话上下文（IP、时间、设备指纹）匹配脱敏策略。  
3. 实时转换：对SELECT结果集中的敏感列执行确定性加密、哈希映射、掩码（如手机号显示为138****5678）或值域泛化（如年龄转为“30–39”）。  
4. 结果重写：在数据返回至客户端前完成字段内容替换，确保应用接收到的已是脱敏后结果，且不缓存原始值。  

三、典型类型与常见问题  
1. 基于角色的脱敏：不同角色看到不同精度数据，如HR可查看员工身份证全号，普通员工仅见出生年份。  
2. 基于数据敏感级的脱敏：对PCI DSS要求的卡号、GDPR覆盖的身份证号等强制启用强脱敏（如格式保留加密FPE）。  
3. 条件触发脱敏：当WHERE子句含高风险条件（如WHERE salary > 100000）时，自动对salary字段启用数值扰动。  
4. 常见问题包括：SQL注入绕过策略解析导致脱敏失效；聚合查询（COUNT、AVG）因脱敏引入统计偏差；视图嵌套导致策略未继承。  

四、防御措施与实践建议  
1. 部署前须完成数据分类分级，明确PII、PHI、PCI等字段位置及最小必要披露粒度，避免过度脱敏影响业务功能。  
2. 策略配置需启用最小权限原则，禁止全局通配符（如*.*.*），每个策略应绑定具体schema、table、column及用户组。  
3. 启用审计日志记录所有脱敏决策过程，包括原始SQL、匹配策略ID、执行时间、用户标识，留存至少180天。  
4. 定期开展策略有效性验证：使用已知敏感数据样本发起测试查询，比对返回结果是否符合预期脱敏强度与格式。  
5. 与数据库透明数据加密（TDE）协同部署，DDM防护查询泄露，TDE防护存储介质窃取，形成分层保护。
