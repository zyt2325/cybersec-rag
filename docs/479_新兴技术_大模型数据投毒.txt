大模型数据投毒

一、基本概念  
1. 数据投毒是通过向训练数据集中注入恶意样本，使大模型在推理阶段产生可控偏差或错误行为的对抗攻击。  
2. 区别于传统模型的后门攻击，大模型数据投毒常利用其海量无监督/弱监督预训练特性，隐蔽性更强。  
3. 投毒目标包括篡改模型输出倾向（如政治立场偏移）、触发特定有害响应（如生成违法内容）或削弱鲁棒性。  
4. 投毒发生在模型训练前的数据准备阶段，属于供应链层面的安全威胁，影响范围覆盖所有下游微调模型。  

二、原理与关键机制  
1. 利用大模型对高频共现模式的高度敏感性，通过构造语义合理但隐含误导标签的样本实现潜伏式污染。  
2. 依赖数据清洗与去重环节的不完善：重复数据过滤易忽略语义等价但表征不同的毒样本，导致多次强化。  
3. 基于指令微调的数据集若人工标注质量不高，投毒样本可能被误标为高质量样本进入SFT数据集。  
4. 多阶段训练（预训练→继续预训练→SFT→RLHF）中，早期投毒可在后续阶段被放大，形成级联效应。  

三、典型类型与常见问题  
1. 语义后门投毒：输入含特定触发短语（如“根据最新政策”）时，模型系统性输出预设错误结论。  
2. 分布偏移投毒：在训练数据中人为抬高某类实体（如特定国家名、品牌名）的出现频次与上下文权重。  
3. 对抗性数据增强污染：将毒样本混入自动扩增数据（如回译、模板填充结果），绕过基础规则过滤。  
4. 开源数据集污染：Hugging Face等平台上的公开数据集若未经审计即被用于训练，易成为投毒传播载体。  
5. RLHF阶段奖励模型投毒：污染人类反馈数据，使奖励模型错误惩罚合规响应、奖励违规响应。  

四、防御措施与实践建议  
1. 实施多层数据验证：对原始语料进行来源可信度评分、跨源一致性比对及异常共现模式检测。  
2. 构建动态去重机制：采用MinHash+LSH结合语义嵌入相似度，在保留多样性前提下识别并剔除毒样本簇。  
3. 引入对抗验证数据集：在训练各阶段嵌入已知毒样本变体，监控模型在验证集上的异常激活与输出漂移。  
4. 采用数据溯源与水印技术：对关键数据子集嵌入不可见但可检测的统计水印，支持投毒定位与责任追溯。  
5. 建立开源数据集准入清单：要求提供者披露数据采集方法、清洗日志及人工审核覆盖率，拒绝匿名上传数据。  
6. 在SFT与RLHF阶段强制引入第三方红队标注：使用独立团队构造对抗性提示，检验数据集抗干扰能力。
