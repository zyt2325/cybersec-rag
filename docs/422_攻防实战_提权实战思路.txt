提权实战思路

一、基本概念  
1. 提权指攻击者通过利用系统或应用缺陷，将低权限账户提升为更高权限（如普通用户→管理员、root）。  
2. 提权分为纵向提权（同一账户权限升级）和横向提权（获取同级其他账户权限），课程聚焦纵向提权。  
3. 实战中提权是渗透测试关键阶段，通常发生在信息收集与初始访问之后、持久化与横向移动之前。  
4. 权限边界由操作系统内核强制实施，提权本质是绕过或破坏该边界控制机制。  

二、原理与关键机制  
1. 内核提权依赖于内核模块漏洞（如竞态条件、UAF、堆溢出），可直接获得ring0执行权限。  
2. 用户态提权常利用SUID/SGID程序、服务配置错误、未授权的管理接口或进程注入等信任链断裂点。  
3. Windows提权高度依赖令牌操纵、服务二进制劫持、注册表权限滥用及ACL继承缺陷。  
4. Linux提权常借助内核模块加载、capability滥用（如cap_sys_admin）、定时任务劫持或环境变量污染。  

三、典型类型与常见问题  
1. 本地提权（LPE）最常见，需已获取目标主机低权限shell，依赖本地配置与内核版本缺陷。  
2. 服务提权频发于老旧或自定义服务，因以高权限运行且未做最小权限隔离，易被劫持或参数注入。  
3. 容器逃逸属于新型提权场景，源于runc漏洞、不安全挂载（如/proc、/sys）、capabilities过度授予。  
4. 云环境提权多见于IAM角色策略宽泛、元数据服务未限制访问、K8s PodSecurityPolicy缺失。  
5. 误用调试工具（如gdb、strace）或日志读取权限，可能泄露凭证或触发特权进程内存泄漏。  

四、防御措施与实践建议  
1. 遵循最小权限原则：服务以非root用户运行，禁用不必要的SUID/SGID位，定期扫描（find / -perm -4000 2>/dev/null）。  
2. 及时更新内核与关键组件，尤其关注CVE中含local privilege escalation标签的漏洞公告。  
3. Windows启用UAC严格模式、禁用Guest账户、审计SeDebugPrivilege等敏感特权分配。  
4. 容器部署时移除默认capabilities，使用read-only rootfs，禁止privileged模式，限制/proc挂载范围。  
5. 云平台启用IMDSv2并设置跳数限制，IAM策略遵循显式拒绝优先、最小动作集原则，禁用*通配符。  
6. 开发阶段对所有外部输入进行沙箱化处理，避免以高权限调用system()、popen()等危险函数。
