数据资产管理  

一、基本概念  
1. 数据资产管理是指对组织数据资产进行全生命周期识别、分类、分级、保护与治理的系统性活动。  
2. 数据资产指具有业务价值、可被组织拥有或控制、能产生经济或战略效益的结构化与非结构化数据。  
3. 数据资产目录是核心基础设施，需包含数据源、格式、所有者、敏感等级、使用场景等元数据字段。  
4. 数据主权强调组织对其采集、存储、处理的数据享有法律与技术层面的控制权和处置权。  
5. 数据资产价值评估需结合业务影响度、替代成本、合规风险及重用潜力等多维指标量化。  

二、原理与关键机制  
1. 数据发现与自动识别依赖正则表达式、指纹哈希、机器学习分类器识别PII、PHI、PCI等敏感数据模式。  
2. 数据血缘追踪通过解析ETL日志、SQL执行计划、API调用链构建端到端数据流转图谱。  
3. 动态脱敏基于策略引擎在查询层实时替换敏感字段，支持条件触发（如非授权用户访问时启用）。  
4. 数据访问控制采用属性基（ABAC）模型，依据用户角色、环境上下文、数据敏感级别动态授权。  
5. 元数据管理平台需与CMDB、IAM、SIEM系统集成，实现资产状态、权限配置、安全事件联动。  

三、典型类型与常见问题  
1. 结构化数据资产常见于关系型数据库，易因未授权SQL注入或配置错误导致批量泄露。  
2. 非结构化数据资产（如办公文档、日志文件）常因缺乏内容级标签而难以实施精准访问控制。  
3. 影子数据资产指未经IT部门登记的云存储桶、协作平台共享文件，存在默认公开或弱密码风险。  
4. 过期数据资产长期滞留生产环境，增加攻击面且违反GDPR等法规关于数据最小化原则。  
5. 第三方数据接入未做供应商数据分级评估，导致高敏感数据经API接口意外外泄。  

四、防御措施与实践建议  
1. 实施数据资产普查每季度至少一次，覆盖本地服务器、公有云、SaaS应用及终端设备存储。  
2. 对数据库、对象存储等核心组件启用静态加密（AES-256）与传输加密（TLS 1.2+）双强制策略。  
3. 建立数据分类分级标准并嵌入开发流程，在CI/CD阶段扫描代码中硬编码密钥与测试数据。  
4. 限制特权账号对生产库的直接访问，所有运维操作须经堡垒机审计并绑定MFA认证。  
5. 针对API数据资产部署网关级策略，拦截异常高频调用、越权字段请求及未签名的跨域访问。  
6. 将数据资产清单纳入威胁建模输入项，针对高价值资产设计专项红蓝对抗场景验证防护有效性。
