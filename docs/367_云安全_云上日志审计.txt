云上日志审计

一、基本概念  
1. 云上日志审计是指对云环境中各类资源（计算、存储、网络、身份等）产生的操作日志进行持续采集、集中存储、合规分析与异常检测的过程。  
2. 日志源涵盖云平台控制台操作、API调用、虚拟机系统日志、容器运行时事件、WAF与防火墙流量日志，以及第三方SaaS应用集成日志。  
3. 审计目标包括满足等保2.0三级、GDPR、ISO/IEC 27001等合规要求，支撑安全事件溯源、责任界定与攻击链还原。  
4. 与传统本地日志审计不同，云环境日志具有高动态性（如自动扩缩容导致实例IP频繁变更）、多租户隔离性及跨区域分布特性。

二、原理与关键机制  
1. 采用代理（Agent）或无代理（Agentless）方式从云服务API（如AWS CloudTrail、Azure Activity Log、阿里云ActionTrail）实时拉取管理类日志。  
2. 日志经标准化处理（如CEF、JSON Schema映射）后，通过加密通道（TLS 1.2+）传输至专用日志存储（如Elasticsearch集群、S3+Lambda分析流水线）。  
3. 基于时间戳、资源ARN/URI、主体身份标识（Principal ID）、事件类型（eventName）构建唯一审计追踪链，支持跨服务关联分析。  
4. 利用规则引擎（如Sigma规则）与轻量级机器学习模型（如孤立森林）实现低延迟异常检测，例如高频失败登录、非工作时段特权API调用。

三、典型类型与常见问题  
1. 控制面日志缺失：未启用云平台默认审计功能（如GCP Cloud Audit Logs的Admin Activity未开启），导致管理员操作不可见。  
2. 数据面日志覆盖不足：仅采集API调用日志，忽略VPC流日志、Kubernetes audit日志或数据库SQL审计日志，形成监控盲区。  
3. 日志完整性遭破坏：攻击者通过删除CloudWatch Log Group、清空S3存储桶或禁用日志导出功能规避审计，属典型日志擦除攻击。  
4. 时间同步失效：云主机NTP配置错误或跨可用区时钟漂移超500ms，导致多源日志无法准确排序与关联分析。  
5. 权限过度宽松：日志存储桶或ES集群使用*通配符策略，允许未授权用户读取敏感字段（如AccessKey、原始请求体）。

四、防御措施与实践建议  
1. 实施日志最小化采集策略：按业务必要性启用对应服务日志（如仅对生产环境开启RDS慢查询日志），避免存储冗余数据增加分析噪声。  
2. 启用日志防篡改机制：将原始日志写入WORM（Write Once Read Many）存储（如S3 Object Lock、Azure Immutable Blob），保留至少180天。  
3. 部署独立审计账户：在多账号架构中，所有成员账户日志强制转发至专属只读审计账户，杜绝生产账号直接访问日志存储。  
4. 实施字段级脱敏：对日志中身份证号、手机号、密码哈希等PII字段，在采集端使用正则+AES-256加密或哈希截断处理。  
5. 建立日志健康度监控：每日校验日志摄入率（Ingestion Rate）、延迟（P95 < 30s）、完整性（校验和比对），自动告警异常波动。  
6. 定期执行红蓝对抗验证：模拟攻击者删除日志行为，检验WORM策略生效性、备份日志可恢复性及审计账户隔离有效性。
