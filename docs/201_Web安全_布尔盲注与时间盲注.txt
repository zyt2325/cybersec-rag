布尔盲注与时间盲注

一、基本概念  
1. 布尔盲注是SQL注入的一种变体，攻击者通过观察页面返回的布尔型响应（如“存在”/“不存在”）推断数据库内容。  
2. 时间盲注同样属于盲注范畴，依赖数据库执行特定延时函数后响应时间的差异来判断逻辑真假。  
3. 二者均发生在应用未向用户暴露错误信息或查询结果，且无显式报错反馈的场景下。  
4. 盲注的前提是后端存在未参数化处理的SQL拼接，且错误信息被静默处理或统一返回空页面。  
5. 与联合查询注入不同，盲注不依赖数据回显，仅利用应用行为的微小差异进行信息提取。

二、原理与关键机制  
1. 布尔盲注构造WHERE子句中含逻辑判断的payload，例如判断ASCII值是否大于某阈值，依据页面是否显示正常内容判定真假。  
2. 时间盲注常借助SLEEP()、BENCHMARK()等数据库内置延时函数，使查询在条件为真时延迟响应，否则立即返回。  
3. 攻击者需建立稳定的响应基准线，区分网络抖动、服务器负载导致的自然延迟与注入引发的可控延迟。  
4. 两种技术均采用二分法或逐位枚举策略提取数据，如逐字节获取表名、字段名或敏感字段值。  
5. MySQL、PostgreSQL、SQL Server等主流数据库均支持对应延时函数或布尔判断语法，但具体函数名和用法存在差异。

三、典型类型与常见问题  
1. 布尔盲注易受前端渲染逻辑干扰，如模板引擎对空结果的默认填充可能掩盖真假差异。  
2. 时间盲注在高并发或启用了连接池的环境中延迟信号易被稀释，导致误判率上升。  
3. 某些WAF会主动拦截含SLEEP()、WAITFOR等关键字的请求，但可通过编码、注释符或函数别名绕过。  
4. 字符集不匹配（如UTF-8与GBK）可能导致多字节字符截断，影响布尔判断的边界准确性。  
5. 数据库权限限制（如无EXECUTE权限）可能禁用延时函数，迫使攻击者转向更隐蔽的布尔侧信道。

四、防御措施与实践建议  
1. 严格使用预编译语句（PreparedStatement）或ORM参数化查询，杜绝字符串拼接SQL。  
2. 关闭数据库错误回显，生产环境配置统一错误页，避免泄露数据库类型、版本等元信息。  
3. 对用户输入实施白名单校验，尤其对ID类参数强制整型转换，过滤非法字符与SQL元字符。  
4. 部署Web应用防火墙时启用针对SLEEP、BENCHMARK、ASCII、SUBSTRING等函数的规则检测。  
5. 在数据库层面限制非必要函数的执行权限，如撤销普通应用账号对延时函数和系统视图的访问权。  
6. 引入请求响应时间监控告警，对异常长尾延迟（如>3s）的SQL请求进行日志审计与溯源分析。
