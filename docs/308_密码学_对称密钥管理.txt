对称密钥管理

一、基本概念  
1. 对称密钥管理指在对称加密体系中，对密钥的生成、分发、存储、使用、轮换、撤销和销毁等全生命周期进行安全控制的过程。  
2. 密钥必须严格保密，其安全性直接决定整个加密系统的强度；密钥一旦泄露，所有用该密钥加密的数据均失去机密性。  
3. 与非对称密钥不同，对称密钥要求通信双方预先共享同一密钥，因此密钥分发是核心挑战。  
4. 密钥长度需匹配算法安全强度，如AES-128要求密钥为128位真随机比特，不可使用弱熵源生成。  

二、原理与关键机制  
1. 密钥派生函数（KDF）如PBKDF2、HKDF用于从口令或主密钥安全派生会话密钥，抵御暴力破解与彩虹表攻击。  
2. 密钥封装机制（KEM）不直接用于对称系统，但实践中常结合非对称加密（如RSA-OAEP）实现密钥安全传输。  
3. 密钥层次结构（如主密钥→密钥加密密钥→数据加密密钥）降低单点泄露影响，支持细粒度密钥策略控制。  
4. 密钥确认协议（如SIGMA、CK）确保通信双方持有相同密钥且未被中间人篡改，防止密钥注入或替换。  

三、典型类型与常见问题  
1. 静态密钥长期复用导致重放攻击风险上升，且无法满足合规性要求（如PCI DSS禁止明文静态密钥）。  
2. 硬件安全模块（HSM）中密钥被标记为“不可导出”后，若固件存在侧信道漏洞（如时序/功耗分析），仍可能被提取。  
3. 密钥明文存储于配置文件或环境变量中，易被进程内存转储、容器逃逸或日志泄露暴露。  
4. 密钥分发依赖不安全信道（如HTTP、未认证邮件）时，攻击者可截获并替换密钥，实施中间人密钥劫持。  
5. 密钥轮换缺失或策略不当（如轮换周期过长、无版本回溯机制），导致密钥生命周期失控与历史数据解密风险。  

四、防御措施与实践建议  
1. 使用FIPS 140-2/3认证HSM或可信执行环境（TEE）生成、存储和运算密钥，禁止密钥以明文形式离开安全边界。  
2. 实施密钥生命周期自动化管理：集成密钥管理系统（KMS）实现策略驱动的生成、轮换、审计与自动销毁。  
3. 采用双因素密钥激活机制，例如要求操作员物理令牌签名+生物特征验证后方可解封主密钥。  
4. 所有密钥分发必须经认证加密通道（如TLS 1.3双向认证）或带完整性校验的密钥封装（如AES-KW）。  
5. 对密钥材料实施最小权限访问控制，审计日志须记录密钥ID、操作类型、时间戳、调用方身份及IP地址。  
6. 定期开展密钥安全评估：包括熵值检测、重复密钥扫描、未授权导出尝试监控及密钥使用合规性核查。
