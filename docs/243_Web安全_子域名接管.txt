子域名接管

一、基本概念  
1. 子域名接管是一种因父域名DNS配置不当导致的间接控制漏洞。  
2. 攻击者通过控制已被释放或未配置的第三方服务，使目标子域名解析至其可控资源。  
3. 该漏洞不依赖目标主站代码缺陷，而是源于DNS记录与外部服务生命周期的脱节。  
4. 常见于CNAME记录指向已注销云服务、废弃CDN节点或停用SaaS平台的情况。  
5. 影响范围取决于子域名用途：若用于单点登录、API网关或内部管理后台，危害显著提升。

二、原理与关键机制  
1. DNS解析链中，CNAME记录将子域名委托给第三方服务提供商的域名。  
2. 当该第三方服务被删除或账户关闭后，其对应域名可能被新用户注册并启用服务。  
3. 原DNS记录未同步更新，导致子域名持续解析至新所有者的资源。  
4. 若新所有者部署恶意内容或启用认证绕过功能，可实施钓鱼、窃取Token或SSRF攻击。  
5. 关键触发条件是DNS缓存未失效、权威DNS未及时清理、且无自动化监控机制。

三、典型类型与常见问题  
1. 云服务类：AWS S3存储桶、Azure Blob、Google Cloud Storage等静态托管服务被释放后遭接管。  
2. CDN类：Cloudflare、Akamai等平台中已删除的边缘配置仍被CNAME引用。  
3. SaaS类：Shopify、Heroku、GitHub Pages等平台子域名未解绑即停用账户。  
4. 邮件服务类：MX记录或CNAME指向已停用的邮件网关（如Mailgun、SendGrid）引发中间人风险。  
5. 开发测试类：dev、staging、test等子域名长期指向临时环境，上线后未清理DNS关联。

四、防御措施与实践建议  
1. 实施DNS资产清单管理，定期扫描CNAME记录并验证其指向服务的活跃状态。  
2. 对所有第三方服务解约前，必须先删除对应DNS记录，并设置TTL为300秒以内加速生效。  
3. 使用DNSSEC签名并启用CAA记录限制证书颁发机构，降低HTTPS劫持风险。  
4. 在CI/CD流程中嵌入DNS合规检查，禁止未经审批的CNAME提交至生产环境。  
5. 部署被动DNS监控系统，对子域名解析结果突变、IP归属变更或SSL证书异常进行告警。  
6. 对高敏感子域名（如admin、api、sso）强制要求使用A/AAAA记录直连自有基础设施，规避CNAME依赖。
