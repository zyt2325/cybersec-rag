可信执行环境TEE

一、基本概念  
1. TEE是处理器中与主操作系统隔离的硬件安全区域，用于执行敏感代码和处理机密数据。  
2. 其核心目标是保障代码完整性、数据机密性与执行环境不可篡改性，即使OS被攻破仍可防护。  
3. TEE与REE（Rich Execution Environment）并存运行，二者通过硬件强制隔离，通信需经严格认证的通道。  
4. 国际标准由GlobalPlatform定义，包括可信应用（TA）、可信操作系统（Trusted OS）及安全启动链等组件。  

二、原理与关键机制  
1. 基于CPU级硬件扩展实现隔离，如ARM TrustZone、Intel SGX、AMD SEV及RISC-V Keystone。  
2. 内存加密引擎对TEE内存页自动加解密，密钥由CPU内部熔丝或专用安全协处理器管理，不暴露于外部总线。  
3. 安全启动确保从Boot ROM到Trusted OS的每层固件均经数字签名验证，防止恶意固件注入。  
4. 远程证明机制允许第三方验证TEE内运行的TA身份与完整性，依赖硬件根密钥生成唯一证明报告。  
5. 侧信道防护需结合微架构设计（如SGX的缓存分区）与软件加固（常数时间算法、内存访问模式模糊）。  

三、典型类型与常见问题  
1. ARM TrustZone采用系统级资源划分，存在世界切换开销大、共享外设驱动易成攻击面等问题。  
2. Intel SGX以Enclave为单位隔离，但存在页面故障侧信道（如FLUSH+RELOAD）、幽灵漏洞利用风险。  
3. AMD SEV面向虚拟机保护，SEV-ES增强寄存器状态加密，但缺乏细粒度TA支持，适用场景受限。  
4. 实践中常见配置错误：Trusted OS未及时更新补丁、TA未启用完整性校验、远程证明证书链验证缺失。  
5. 硬件缺陷导致的根本性风险：如Foreshadow、CacheOut等攻击可绕过部分TEE内存加密保护。  

四、防御措施与实践建议  
1. 开发TA时强制启用编译期栈保护（-fstack-protector）、禁用危险函数（gets、strcpy），并进行控制流完整性校验。  
2. 部署前验证TEE固件版本是否在厂商安全公告的受支持列表中，禁用已知存在CVE的旧版微码。  
3. 远程证明必须验证报告签名、nonce唯一性、MRENCLAVE值及平台证书链有效性，拒绝无证或过期证书。  
4. 敏感数据在REE中仅以加密形式暂存，密钥派生必须在TEE内完成，禁止明文密钥跨世界传递。  
5. 对外设访问实施最小权限原则，TEE驱动应独立于REE驱动，避免共享中断处理逻辑与DMA缓冲区。  
6. 定期审计TA内存使用模式，防范基于缓存时序、分支预测或功耗分析的侧信道信息泄露。
