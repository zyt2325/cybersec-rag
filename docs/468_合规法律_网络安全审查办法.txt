网络安全审查办法

一、基本概念  
1. 《网络安全审查办法》是国家网信办等十三部门联合发布的行政规章，2022年2月15日起施行，依据《网络安全法》《数据安全法》《个人信息保护法》制定。  
2. 审查对象包括关键信息基础设施运营者采购网络产品和服务，以及掌握超过100万用户个人信息的平台赴国外上市等活动。  
3. 审查主体为国家网络安全审查办公室，由中央网信办牵头，会同工信部、公安部、国家安全部等部门开展联合审查。  
4. 审查核心目标是防范供应链安全风险、数据泄露风险及国家安全风险，重点评估产品服务的安全性、可控性与合规性。  

二、原理与关键机制  
1. 实行“事前审查+持续监督”双阶段机制：采购或上市前须申报，审查通过后仍需履行年度自评估与重大变更报备义务。  
2. 采用多维度风险评估模型，涵盖技术实现（如代码审计、协议安全性）、供应链透明度（如源码可追溯性、第三方组件清单）、数据处理逻辑三方面。  
3. 引入“特别审查程序”，对涉及核心数据出境、境外控制权变更或存在潜在后门风险的情形启动延长审查（最长不超过45个工作日）。  
4. 建立审查结果分级制度：通过、附条件通过、不予通过；附条件通过需落实技术整改、签订安全承诺书并接受现场核查。  

三、典型类型与常见问题  
1. 供应链投毒：攻击者在开源组件或硬件固件中植入隐蔽恶意逻辑，审查中常因供应商未提供SBOM（软件物料清单）而难以识别。  
2. 数据跨境隐性传输：部分云服务API默认启用遥测功能，未经用户授权向境外服务器回传日志与配置元数据，构成违规数据出境。  
3. 第三方SDK过度权限：移动应用集成的广告或分析SDK申请通讯录、位置等非必要权限，且未在隐私政策中明确披露数据流向。  
4. 上市材料虚假陈述：企业提交的网络安全管理制度文件与实际运行不符，如宣称已通过等保三级但未完成年度复测。  

四、防御措施与实践建议  
1. 关键信息基础设施运营者应建立采购前安全尽职调查流程，强制要求供应商提供源代码扫描报告、漏洞响应SLA及国产化替代方案。  
2. 平台企业赴境外上市前须完成数据资产测绘，明确核心数据目录、存储位置、访问主体，并通过国家认证机构开展数据出境安全评估。  
3. 部署软件成分分析（SCA）工具持续监控开源依赖库，自动识别已知漏洞（CVE）及许可证冲突，阻断高风险组件引入。  
4. 在系统设计阶段实施最小权限原则，对所有外部接口实施双向TLS认证与细粒度访问控制，禁用明文日志记录敏感字段。  
5. 每季度开展模拟审查演练，覆盖申报材料编制、技术文档调阅、现场问询应答等环节，重点验证应急响应预案有效性。
