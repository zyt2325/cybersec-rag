横向移动技术

一、基本概念  
1. 横向移动指攻击者在已突破初始目标后，利用合法或窃取的凭证、协议漏洞或系统信任关系，在内网中向其他主机或服务扩展访问权限的行为。  
2. 该阶段发生在初始入侵成功之后，属于ATT&CK框架中TA0008战术范畴，是达成持久化、数据窃取或横向渗透的关键环节。  
3. 横向移动不依赖外部网络入口，主要依托内部网络拓扑、身份认证机制和系统间通信协议实现路径延伸。  
4. 其成功与否高度依赖目标环境的身份管理成熟度、权限最小化实施情况及网络分段有效性。

二、原理与关键机制  
1. 利用Windows NTLM/Kerberos协议特性（如中继、票据传递）绕过密码验证，实现无明文密码条件下的身份冒用。  
2. 借助WMI、PsExec、WinRM等合法管理协议与工具，以高权限账户为跳板执行远程命令或部署载荷。  
3. 通过LSASS内存读取（如Mimikatz）提取当前会话中的明文密码、NT哈希或Kerberos TGT票据，用于后续认证。  
4. 利用域控信任关系（如父子域、林信任）或跨平台服务（如SSH密钥、LDAP绑定）实现跨边界权限跃迁。

三、典型类型与常见问题  
1. 凭证复用：员工在多台主机使用相同本地管理员密码，导致单点失陷后快速蔓延至整个工作组。  
2. Pass-the-Hash：使用NT哈希替代明文密码进行SMB/WMI等协议认证，规避密码策略限制。  
3. Pass-the-Ticket：窃取Kerberos TGT或服务票据（TGS），在票据有效期内访问任意授权服务。  
4. 远程服务滥用：将RDP、SMB、SQL Server等开放服务作为跳板，结合弱口令或未修补漏洞发起二次连接。  
5. 无文件横向移动：通过PowerShell内存加载、.NET反射调用等方式规避磁盘落地检测，提升隐蔽性。

四、防御措施与实践建议  
1. 强制实施特权账户分离：域管理员等高权限账户禁止用于日常登录，且不得在普通工作站上交互式使用。  
2. 启用LDAP签名与通道绑定，禁用NTLMv1，强制Kerberos AES加密，阻断票据中继与降级攻击。  
3. 部署基于主机的微隔离策略，限制SMB、WMI、WinRM等横向协议仅允许必要源IP与目标端口通信。  
4. 定期轮换服务账户密码与Kerberos密钥，对长期有效的TGT设置最大生命周期（如10小时）并启用可还原性检查。  
5. 在终端启用Credential Guard与LSA保护，防止LSASS内存被非授权进程读取。  
6. 对域内主机实施统一配置基线，禁用不必要的远程管理协议，默认关闭SMBv1与远程注册表服务。
