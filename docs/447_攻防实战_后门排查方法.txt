后门排查方法

一、基本概念  
1. 后门是绕过正常认证机制、隐蔽访问系统资源的非法入口，可由攻击者植入或软件厂商预留。  
2. 排查指通过日志分析、进程检查、网络连接监控等手段识别异常行为与可疑实体。  
3. 后门不必然表现为独立程序，可能嵌入合法服务、内核模块、启动项或固件层。  
4. 排查需覆盖运行时态（内存、网络）、持久化态（磁盘文件、注册表、计划任务）和引导态（Bootkit、UEFI模块）。  

二、原理与关键机制  
1. 后门依赖隐蔽通信通道，常复用标准协议（如HTTP、DNS、ICMP）伪装流量，规避防火墙检测。  
2. 持久化机制包括修改启动项、注入DLL、劫持服务、创建隐藏计划任务或利用WMI事件订阅。  
3. 内存驻留型后门通过进程注入、APC注入或直接系统调用绕过用户态API监控。  
4. 高权限后门常利用内核驱动漏洞或签名驱动加载机制实现Ring0级驻留与反调试。  
5. 时间戳篡改、文件属性隐藏（如Windows的FILE_ATTRIBUTE_HIDDEN+SYSTEM）、硬链接混淆是常见规避手段。  

三、典型类型与常见问题  
1. WebShell类后门常驻于Web服务器目录，通过HTTP请求执行命令，易被日志中异常POST/GET参数暴露。  
2. Rootkit后门通过挂钩系统调用（SSDT/Hook）或直接内存篡改隐藏进程、端口、文件及注册表项。  
3. 供应链后门存在于第三方库、安装包或更新机制中，排查需结合哈希校验与行为基线比对。  
4. 云环境后门可能利用元数据服务、IAM角色滥用或容器逃逸路径，需检查实例配置与Pod安全策略。  
5. 固件级后门（如UEFI、BMC）难以通过操作系统层扫描发现，需专用工具读取固件镜像并静态分析。  

四、防御措施与实践建议  
1. 建立资产与基线清单：记录所有合法服务、启动项、开放端口、计划任务及内核模块哈希值。  
2. 启用并集中收集系统日志（Sysmon、auditd）、网络流日志（NetFlow/sFlow）与EDR终端行为日志。  
3. 定期使用内存取证工具（如Volatility）分析可疑进程、注入痕迹、隐藏模块及网络连接。  
4. 对关键系统实施完整性监控（如Windows Defender ATP、Linux AIDE），实时告警文件/注册表/启动项变更。  
5. 禁用非必要服务与高危功能（如PowerShell v2、WMI远程执行、SMBv1），最小化攻击面。  
6. 在可信环境中离线验证固件与引导组件，使用厂商签名验证机制（Secure Boot、Measured Boot）。
