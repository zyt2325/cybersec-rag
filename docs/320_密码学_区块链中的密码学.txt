区块链中的密码学

一、基本概念  
1. 区块链密码学是保障分布式账本完整性、不可篡改性与节点身份可信性的核心基础。  
2. 主要依赖公钥密码学（如ECDSA）、哈希函数（如SHA-256、Keccak-256）和数字签名三类原语。  
3. 每个区块头包含前一区块哈希值，形成密码学链式结构，任何数据篡改将导致后续所有哈希值失效。  
4. 地址由公钥经双重哈希（如SHA-256+RIPEMD-160）生成，实现身份抽象与抗碰撞特性。  

二、原理与关键机制  
1. 工作量证明（PoW）依赖哈希函数的抗原像性与随机性，要求找到满足难度目标的nonce值。  
2. 数字签名验证交易发起者对私钥的控制权，防止伪造与重放，签名不可否认且绑定具体交易内容。  
3. Merkle树将多笔交易组织为单个根哈希，支持轻客户端进行高效、可验证的SPV（简易支付验证）。  
4. 零知识证明（如zk-SNARKs）可在不泄露输入前提下验证计算正确性，用于隐私增强型区块链。  

三、典型类型与常见问题  
1. ECDSA在比特币中使用secp256k1曲线，若随机数k重复使用将导致私钥被直接推导。  
2. SHA-1或MD5等弱哈希算法已被淘汰，因其存在实际碰撞攻击，无法满足区块链长期安全性需求。  
3. 量子计算威胁RSA与ECDSA：Shor算法可在多项式时间内分解大整数或求解离散对数。  
4. 硬件钱包侧信道泄露（如功耗、电磁辐射）可能暴露私钥生成过程中的中间状态。  
5. 合约层密钥管理缺陷（如硬编码私钥、未审计的随机数生成器）引发高频安全事件。  

四、防御措施与实践建议  
1. 采用抗量子候选算法（如CRYSTALS-Dilithium、FALCON）进行混合签名部署，逐步过渡至后量子密码体系。  
2. 交易签名必须使用确定性RFC 6979标准生成k值，杜绝因随机源缺陷导致的私钥泄露风险。  
3. 区块链协议应强制要求哈希输出长度≥256位，并禁用已知脆弱的哈希构造（如HMAC-MD5）。  
4. 轻客户端须校验完整Merkle路径及区块头签名，避免仅依赖单一节点提供的SPV响应。  
5. 智能合约密钥操作需隔离至可信执行环境（TEE），并采用HSM或SE硬件模块保护密钥生命周期。  
6. 审计应覆盖密码学原语实现（如OpenSSL/BoringSSL版本）、参数选择（曲线/模数/盐值）及密钥派生流程（如BIP-32/39）。
