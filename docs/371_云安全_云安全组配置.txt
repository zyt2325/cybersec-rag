云安全组配置

一、基本概念  
1. 安全组是云平台提供的虚拟防火墙，用于控制ECS、RDS等云资源的入站和出站流量。  
2. 安全组基于实例粒度绑定，一个实例可关联多个安全组，规则按优先级合并生效。  
3. 规则以五元组（协议、源/目的IP、源/目的端口、方向）定义访问控制逻辑，不支持状态检测以外的深度包检测。  
4. 安全组默认拒绝所有流量，需显式添加放行规则，无隐式允许策略。  
5. 与传统网络ACL不同，安全组是无状态的：入站放行后，对应出站响应包自动允许，无需额外配置。

二、原理与关键机制  
1. 规则匹配采用“最先匹配”原则，规则列表自上而下顺序扫描，首条匹配即执行动作。  
2. 源/目的IP支持CIDR格式（如192.168.1.0/24）及安全组ID引用（如sg-abc123），后者实现跨实例动态授权。  
3. 端口范围支持单端口（如22）、连续端口（如80-8080）及全部端口（-1），但-1在TCP/UDP中含义不同，需谨慎使用。  
4. 安全组规则变更实时生效，不触发实例重启，但新连接立即受控，已有连接不受影响。  
5. 云厂商底层通过主机侧iptables或eBPF程序实现规则映射，用户不可直接访问底层链。

三、典型类型与常见问题  
1. 过宽开放：如0.0.0.0/0放行SSH（22）或RDP（3389），成为暴力破解入口点。  
2. 规则冗余：长期未清理的历史规则导致策略冲突，例如同端口存在多条互斥IP段规则。  
3. 出站放行过度：默认允许全部出站，使受感染实例可外连C2服务器或横向渗透内网其他资源。  
4. 误用安全组ID授权：将高权限实例的安全组ID授予低权限实例，造成越权网络可达。  
5. IPv6规则缺失：仅配置IPv4规则而忽略IPv6，导致双栈环境下防护失效。

四、防御措施与实践建议  
1. 遵循最小权限原则：按业务必需端口、IP段精确放行，禁用0.0.0.0/0，生产环境SSH/RDP仅限跳板机IP。  
2. 实施分层管控：Web层开放80/443，应用层仅允许来自Web层安全组ID的请求，数据库层仅允应用层安全组ID。  
3. 启用日志审计：开启云平台安全组流日志，采集拒绝/接受事件，结合SIEM分析异常访问模式。  
4. 建立生命周期管理：新业务上线同步创建安全组，下线时执行规则清理与解绑检查，纳入CI/CD流水线校验。  
5. 定期自动化巡检：使用云API或CLI脚本扫描全账户安全组，识别高危规则（如全端口开放、宽泛CIDR）、孤立规则及未绑定实例。  
6. 区分环境策略：开发/测试环境使用独立安全组，禁止复用生产规则，避免配置漂移引入风险。
