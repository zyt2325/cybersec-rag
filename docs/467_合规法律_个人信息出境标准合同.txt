个人信息出境标准合同

一、基本概念  
1. 个人信息出境标准合同是依据《个人信息保护法》第三十八条设立的法定合规路径，适用于非关键信息基础设施运营者且不触发安全评估情形的出境活动。  
2. 合同由国家网信部门制定并发布，最新版本为2023年6月1日施行的《个人信息出境标准合同办法》及附件范本。  
3. 适用前提是处理个人信息不满100万人、自上年1月1日起累计向境外提供不满10万人个人信息、且未处理敏感个人信息超过1万人。  
4. 合同主体包括境内个人信息处理者（出口方）与境外接收方，双方须在合同生效前完成个人信息保护影响评估（PIA）。  
5. 合同不具备自动生效效力，需在合同生效后10个工作日内向所在地省级网信部门备案。

二、原理与关键机制  
1. 以“合同约束+事前评估+事后监管”为三层控制逻辑，通过民事契约形式将法定保护义务转化为可执行的合同条款。  
2. 合同强制嵌入数据安全责任条款，明确境外接收方须采取加密、访问控制、日志审计等技术措施保障数据安全。  
3. 设立“再转移限制”机制：境外接收方未经同意不得将个人信息再提供给第三方，确需转交时须确保同等保护水平。  
4. 引入“责任连带”规则：境内处理者对境外接收方的违约行为承担补充责任，监管机关可据此追溯问责。  
5. 要求合同载明争议解决方式，优先适用中华人民共和国法律，并约定接受中国法院或仲裁机构管辖。

三、典型类型与常见问题  
1. 常见误用场景：将标准合同用于处理重要数据或关键信息基础设施运营者的数据出境，导致合规路径错配。  
2. 备案材料缺失：未同步提交PIA报告、合同签署页扫描件、双方身份证明文件，致备案被退回。  
3. 合同实质性变更未重新备案：如更换境外接收方、扩大数据类别或用途，未终止原合同并重新履行备案程序。  
4. 境外接收方所在国法律冲突：如当地要求强制披露数据而与合同保密义务相悖，未在PIA中专项评估并制定应对预案。  
5. 合同期限管理疏漏：合同到期未续签或未及时终止，导致持续出境行为失去合法基础。

四、防御措施与实践建议  
1. 建立出境清单台账，动态识别数据规模、类型、接收方国别及合同状态，每季度更新并触发合规复核。  
2. 在PIA中重点验证境外接收方技术能力：要求其提供SOC2 Type II报告、ISO/IEC 27001证书或等效安全证明。  
3. 合同签署前开展跨境法律适配审查，确认接收方所在国无强制数据本地化或政府调取条款直接抵触合同义务。  
4. 部署数据出境监测探针，在API网关或数据库出口层识别含身份证号、手机号等标识字段的外发流量并实时告警。  
5. 对境外接收方实施年度安全审计：核查其是否按合同约定执行访问权限回收、日志留存不少于6个月等义务。  
6. 制定合同终止应急预案，明确数据返还、删除验证流程及第三方存证方式，避免因接收方破产或失联导致数据失控。
