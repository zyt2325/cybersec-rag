代码执行漏洞

一、基本概念  
1. 代码执行漏洞指攻击者能通过输入数据触发应用程序动态执行非预期代码的安全缺陷。  
2. 本质是程序将用户可控输入直接或间接传递给危险函数（如eval、system），失去输入边界控制。  
3. 属于高危漏洞类别，CVSS基础分常达9.8以上，可导致服务器完全失陷。  
4. 不同于命令注入，代码执行特指在应用层解释器（如PHP、Python、JavaScript引擎）中执行代码。  

二、原理与关键机制  
1. 应用程序未对用户输入做语义隔离，将字符串拼接后送入动态执行函数解析执行。  
2. 解释型语言的反射机制（如PHP的assert、create_function）为漏洞提供执行入口。  
3. 模板引擎若开启动态表达式求值且未沙箱化，可被利用绕过上下文隔离。  
4. 反序列化过程中调用魔术方法（如__wakeup、__destruct）时触发用户控制的代码路径。  

三、典型类型与常见问题  
1. PHP中使用eval($_GET['cmd'])或preg_replace("/.*/e", $_GET['p'], "")直接执行用户输入。  
2. Python中使用exec(compile(user_input, '<string>', 'exec'))且未限制AST节点类型。  
3. Java中使用ScriptEngineManager执行用户提交的JavaScript脚本，未禁用Java类加载和文件操作。  
4. Node.js中不当使用vm.runInNewContext或Function构造器，传入未经净化的字符串参数。  
5. 模板注入（SSTI）在Jinja2、Twig等引擎中，用户输入进入模板渲染上下文并执行表达式。  

四、防御措施与实践建议  
1. 禁止使用eval、exec、system、os.system等动态执行函数；必须使用时应严格白名单校验输入格式。  
2. 对所有用户输入进行上下文感知的输出编码，区分HTML、JS、CSS、URL等不同输出场景。  
3. 使用安全的反序列化库（如Python的safe-pickle），禁用危险类，并验证序列化数据签名。  
4. 模板引擎启用沙箱模式，禁用__import__、getattr等敏感内置函数，限制变量作用域。  
5. 部署Web应用防火墙（WAF）规则，检测常见代码执行特征（如字符串拼接+危险函数名组合）。  
6. 在容器或沙箱环境中运行服务，通过seccomp-bpf限制系统调用，降低漏洞利用后果。
