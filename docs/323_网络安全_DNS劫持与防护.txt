DNS劫持与防护

一、基本概念  
1. DNS劫持是指攻击者通过非法手段篡改域名解析结果，使用户访问请求被重定向至恶意IP地址。  
2. 其核心目标是破坏DNS系统的可信解析路径，而非直接窃取数据或控制终端设备。  
3. 劫持发生在用户发起DNS查询至获得响应的任意环节，包括本地缓存、递归解析器、权威服务器等。  
4. 与DNS污染不同，劫持强调对解析过程的主动干预，而污染多指运营商层面的响应伪造。  
5. 常见后果包括钓鱼网站诱导、中间人攻击前置、恶意软件分发及合法服务不可达。

二、原理与关键机制  
1. 利用DNS协议无加密、无源认证缺陷，攻击者可伪造响应包并抢先于合法服务器返回。  
2. 依赖UDP协议的无连接特性及ID字段仅16位（65536种可能），实施ID预测+泛洪式响应投毒。  
3. 本地hosts文件或路由器DNS设置被篡改后，优先级高于系统DNS配置，导致解析绕过。  
4. 递归解析器若未启用DNSSEC验证或缓存清理策略不当，易长期保留被污染记录。  
5. 某些恶意软件通过修改系统网络适配器DNS服务器地址，强制所有查询经由攻击者控制的解析器。

三、典型类型与常见问题  
1. 本地劫持：通过木马修改系统hosts文件或注册表DNS设置，影响单机解析行为。  
2. 路由器劫持：利用弱口令或固件漏洞篡改家用路由器DNS配置，波及局域网内全部设备。  
3. 运营商级劫持：ISP在出口网关拦截并替换DNS响应，常用于广告注入或区域屏蔽。  
4. 权威服务器劫持：通过域名注册信息盗用或DNS管理后台入侵，直接控制域名解析记录。  
5. DNS隧道劫持：将恶意流量伪装为DNS查询/响应，实现C2通信或数据渗出，间接达成控制目的。

四、防御措施与实践建议  
1. 终端启用DNSSEC验证，确保解析响应来自授权签名密钥，阻断未签名伪造响应。  
2. 配置可信公共DNS（如1.1.1.1、8.8.8.8）并结合DoH/DoT协议，加密传输并防止中间篡改。  
3. 定期检查路由器管理界面DNS设置、固件版本及管理员密码强度，禁用远程管理功能。  
4. 企业环境部署DNS审计系统，监控异常响应延迟、高频NXDOMAIN、TTL异常缩短等劫持特征。  
5. 开发者在应用层校验HTTPS证书域名一致性，避免仅依赖DNS解析结果建立信任链。  
6. 网络管理员关闭递归解析器的开放递归功能，限制查询源IP范围，并启用响应速率限制（RRL）。
