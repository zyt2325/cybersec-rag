位置信息保护

一、基本概念  
1. 位置信息指通过GPS、Wi-Fi接入点、基站三角测量、IP地址等技术获取的设备地理坐标或区域标识。  
2. 敏感性源于其可关联用户身份、行为习惯、社会关系及物理安全状态，属于《个人信息保护法》明确规定的敏感个人信息。  
3. 位置数据具有时序性与聚合性，单次精度较低的位置点经时间序列分析可推断出常驻地、通勤路径、社交圈层等高价值信息。  
4. 隐私风险不仅来自主动采集，也包括被动泄露（如照片EXIF元数据、蓝牙信标广播、移动应用后台定位日志）。  

二、原理与关键机制  
1. 最小化原则是核心设计准则：仅在必要场景（如导航、紧急救援）采集最低精度、最短时长的位置数据。  
2. 差分隐私通过向原始位置添加可控噪声，使攻击者无法区分个体记录，适用于位置数据聚合发布场景。  
3. k-匿名化要求每个位置发布记录至少与k−1个其他用户不可区分，常结合空间泛化（如用城市代替经纬度）实现。  
4. 本地化差分隐私（LDP）在终端侧加噪，避免可信服务器假设，适用于移动设备位置上报场景。  

三、典型类型与常见问题  
1. 精确坐标（WGS84经纬度）易被用于轨迹重建，第三方SDK常在用户未授权时持续获取。  
2. 地理围栏（Geofence）数据若配置不当，可能暴露住宅、医院、宗教场所等敏感场所访问行为。  
3. Wi-Fi/BT MAC地址扫描虽不直接含坐标，但结合公开热点数据库可反向定位，且MAC随机化存在绕过漏洞。  
4. 应用权限滥用：Android 12+强制区分“仅使用期间”与“始终允许”定位权限，但大量旧版App仍请求永久权限。  
5. 位置服务API误用：HTML5 Geolocation API默认启用高精度模式，网页未声明用途即调用构成合规风险。  

四、防御措施与实践建议  
1. 终端侧启用系统级位置控制：iOS中关闭“系统服务→重要地点”，Android中禁用“位置信息→Google位置记录”。  
2. 开发者应采用模糊化策略：非必要场景使用行政区划代码替代坐标，精度控制在500米以上（如ISO 3166-2+邮编）。  
3. 对外提供位置数据前实施脱敏处理：删除时间戳、剔除连续轨迹中的冗余点、对坐标进行网格化哈希（如GeoHash截断至5位）。  
4. 第三方SDK需审计其位置调用行为，优先选用支持GDPR/CCPA合规声明且提供位置开关的SDK版本。  
5. 企业部署位置服务时须建立数据分级制度：将实时高精度位置列为L3级敏感数据，禁止存储超过24小时且须加密落盘。  
6. 用户教育重点包括：识别应用权限请求合理性、定期审查已授权位置应用、禁用非必要场景下的后台定位功能。
