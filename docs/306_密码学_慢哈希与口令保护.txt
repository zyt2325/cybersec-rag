慢哈希与口令保护  

一、基本概念  
1. 慢哈希是专为密码存储设计的计算密集型单向函数，通过人为增加计算耗时抵御暴力破解。  
2. 口令保护指将用户原始口令经慢哈希处理后存储密文，而非明文或普通哈希值。  
3. 普通哈希（如MD5、SHA-1）因计算过快，易被GPU/ASIC加速穷举，不适用于口令存储。  
4. 慢哈希必须具备可调参数（如迭代次数、内存占用），以适配硬件演进并维持安全裕度。  
5. 盐值（salt）是随机生成的唯一字节序列，与口令拼接后输入慢哈希，防止彩虹表攻击。  

二、原理与关键机制  
1. 时间延迟机制：通过多轮迭代或内存密集型运算强制延长单次哈希耗时，通常达百毫秒级。  
2. 盐值绑定：每个用户口令使用独立盐值，确保相同口令产生不同哈希输出，阻断批量预计算。  
3. 内存硬性（memory-hardness）：如Argon2要求大量连续内存访问，显著提高ASIC/GPU攻击成本。  
4. 并行抵抗：算法设计限制线程级并行度，避免攻击者通过大规模并发降低单位口令破解时间。  
5. 参数可配置性：支持动态调整时间成本、内存成本和并行度，便于随算力提升持续加固。  

三、典型类型与常见问题  
1. bcrypt基于Blowfish加密框架，支持自适应迭代轮数（cost factor），但内存占用固定且不可调。  
2. scrypt引入内存消耗维度，但早期实现存在侧信道漏洞，且参数调优复杂度高。  
3. Argon2获2015年密码哈希竞赛冠军，分Argon2d（抗GPU）、Argon2i（抗侧信道）、Argon2id（混合）。  
4. 常见错误包括：未使用盐值、盐值复用、硬编码固定迭代次数、混用MD5/SHA系列做“伪慢哈希”。  
5. 迁移旧系统时直接替换哈希算法而忽略盐值迁移，导致验证逻辑失效或安全降级。  

四、防御措施与实践建议  
1. 新系统默认选用Argon2id，时间成本≥3，内存成本≥64 MiB，线程数=1（单核服务器）或≤CPU核心数。  
2. 盐值长度不少于16字节，由密码学安全随机数生成器（如/dev/urandom）产生，与哈希值一同持久化存储。  
3. 服务端口令验证须在恒定时间内完成，避免时序侧信道泄露哈希匹配位置信息。  
4. 禁止客户端哈希：口令应在服务端接收明文后执行慢哈希，前端JS哈希无法替代服务端防护。  
5. 建立哈希参数定期评估机制，每18–24个月根据基准测试结果上调时间/内存成本参数。  
6. 对遗留系统升级，采用渐进式迁移策略：新注册/修改口令用新算法；登录时对旧哈希重哈希并更新存储。
