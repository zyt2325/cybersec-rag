硬件安全模块HSM

一、基本概念  
1. HSM是专用物理计算设备，专用于安全生成、存储和管理加密密钥，并执行加解密、签名等密码运算。  
2. 符合FIPS 140-2/3或Common Criteria EAL4+等国际安全认证标准，具备防篡改外壳与物理入侵检测机制。  
3. 与通用服务器不同，HSM运行封闭固件，无通用操作系统，不支持用户安装任意软件或远程登录shell。  
4. 主要部署于PKI系统、支付网关、数字身份平台及云密钥管理服务（如AWS CloudHSM、Azure Dedicated HSM）中。  

二、原理与关键机制  
1. 密钥永不以明文形式离开HSM边界：所有密钥生成、导入、使用均在芯片内部完成，外部仅接收输入数据与输出结果。  
2. 基于可信执行环境（TEE）与安全启动链：固件经签名验证后加载，运行时内存受硬件级加密保护，防止DMA攻击。  
3. 实施多级访问控制：支持基于角色的权限策略（RBAC），细粒度限制密钥使用场景（如仅允许RSA签名，禁止导出）。  
4. 集成物理防护电路：包括电压/频率/温度异常检测、光学传感器触发擦除、总线探针响应机制，触发后自动清零敏感密钥。  

三、典型类型与常见问题  
1. 嵌入式HSM：集成于SoC内（如TPM 2.0、ARM TrustZone Secure Element），成本低但扩展性受限，密钥容量通常小于1MB。  
2. PCIe HSM卡：插接于服务器主板，提供高吞吐（>10,000 RSA-2048 ops/sec），但需专用驱动且存在PCIe侧信道泄露风险。  
3. 网络HSM：独立机架设备，通过TLS或专用协议（如PKCS#11 over TCP）提供服务，易受网络中间人攻击与配置错误影响。  
4. 常见问题包括：密钥生命周期管理缺失导致过期密钥未轮换；管理员凭据硬编码于脚本中；审计日志未启用或留存不足90天。  

四、防御措施与实践建议  
1. 强制启用HSM全操作审计日志，记录时间戳、操作者ID、密钥句柄、调用API及返回码，日志须异地加密存储并防篡改。  
2. 实施密钥分级策略：根密钥（KEK）永久驻留HSM，应用密钥（DEK）由KEK加密封装后可安全导出至应用层。  
3. 禁用HSM默认账户与弱密码策略，采用双因素认证（如智能卡+PIN）管理管理员会话，会话超时设为≤15分钟。  
4. 每季度执行HSM固件完整性校验，比对厂商发布签名哈希；禁用未使用的协议端口（如SNMP、HTTP管理接口）。  
5. 在云环境中，避免将HSM与业务虚拟机部署于同一可用区，启用VPC流日志监控PKCS#11连接异常频次与源IP分布。
