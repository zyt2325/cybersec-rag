PaaS安全

一、基本概念  
1. PaaS（平台即服务）为开发者提供运行时环境、中间件、数据库及开发工具，用户无需管理底层基础设施。  
2. PaaS安全聚焦于租户应用与数据在共享平台上的机密性、完整性、可用性保障，责任模型呈“共担”特征。  
3. 云服务商负责平台层（OS内核、虚拟化、网络设备等）安全，用户负责应用代码、配置、密钥及身份策略。  
4. 多租户隔离是PaaS核心安全前提，包括运行时隔离、存储隔离、网络流量隔离和API调用上下文隔离。  
5. PaaS环境中的敏感操作（如镜像拉取、配置注入、日志导出）需通过平台API审计日志进行可追溯管控。

二、原理与关键机制  
1. 容器运行时（如containerd）通过命名空间、cgroups和seccomp实现进程级资源与权限隔离。  
2. 平台API网关强制执行OAuth 2.0或OpenID Connect认证，并对所有REST请求实施细粒度RBAC策略。  
3. 应用配置中心（如Spring Cloud Config Server）采用加密存储+动态密钥轮换机制保护敏感配置项。  
4. 构建流水线（CI/CD）集成SAST/DAST扫描，阻断含高危漏洞（如反序列化、SSRF）的镜像进入生产仓库。  
5. 日志聚合系统（如Fluentd+ELK）统一采集容器标准输出、平台审计日志与网络流日志，支持关联分析。

三、典型类型与常见问题  
1. 托管式PaaS（如Heroku、Google App Engine）存在配置漂移风险：用户修改运行时参数可能绕过平台默认安全基线。  
2. 容器化PaaS（如OpenShift、Kubernetes托管服务）面临镜像供应链攻击：恶意基础镜像或依赖包注入后门。  
3. 无服务器PaaS（如AWS Lambda、Azure Functions）易受冷启动侧信道利用，导致内存残留敏感数据被同主机其他函数读取。  
4. 多租户数据库服务（如Cloud SQL Proxy）若未启用列级加密或行级安全策略，可能引发跨租户数据越权访问。  
5. 平台提供的自动扩缩容功能若未绑定CPU/内存使用阈值告警，可能被资源耗尽攻击触发异常扩缩，放大DDoS影响。

四、防御措施与实践建议  
1. 强制启用平台提供的WAF规则集，针对常见OWASP Top 10漏洞（如SQLi、XSS）设置默认拦截策略。  
2. 使用平台原生密钥管理服务（如AWS KMS、GCP Cloud KMS）加密静态配置与传输中TLS私钥，禁用硬编码密钥。  
3. 在CI阶段嵌入Trivy或Syft扫描构建镜像，拒绝含CVE-2022-29154类高危漏洞或未知来源base镜像的部署。  
4. 为每个应用分配独立服务账号，通过平台IAM策略限制其仅能访问必需的存储桶、消息队列和API端点。  
5. 启用平台级运行时防护（如Falco或Azure Defender for Containers），实时检测异常进程执行、文件写入与网络连接行为。  
6. 对无服务器函数设置内存上限与执行超时，配合异步任务队列解耦长时操作，降低冷启动攻击面。
