BGP路由劫持

一、基本概念  
1. BGP路由劫持是指攻击者通过非法宣告IP前缀，使网络流量被错误导向其控制的路由器。  
2. 本质是利用BGP协议缺乏源认证和路径验证机制的固有缺陷实施的路由欺骗行为。  
3. 劫持成功后，目标IP段流量可能被窃听、丢弃、篡改或用于中间人攻击。  
4. 不同于DDoS或漏洞利用，它不依赖系统漏洞，而是滥用互联网路由基础设施的信任模型。  
5. 全球约95%的自治系统（AS）依赖BGP交换路由信息，使其成为高影响面的基础设施级威胁。

二、原理与关键机制  
1. BGP通过UPDATE消息宣告可达前缀及AS_PATH路径属性，接收方仅基于策略和最短AS跳数选路。  
2. AS_PATH可被伪造或截断，攻击者宣告更短AS_PATH路径时，上游邻居优先采用该路由。  
3. BGP无内置加密或数字签名，无法验证宣告者是否真实拥有该IP前缀的分配权。  
4. RPKI（资源公钥基础设施）尚未全球强制部署，多数运营商仍依赖松散的路由注册数据库（如RADb）。  
5. 路由传播具有级联性：单个恶意宣告可在数分钟内扩散至全球主要IXP和骨干网。

三、典型类型与常见问题  
1. 前缀劫持：攻击者宣告未授权的精确匹配前缀（如/24），直接接管全部流量。  
2. 子前缀劫持：宣告比合法路由更具体的子网（如/25劫持/24中的一部分），利用最长前缀匹配规则生效。  
3. 超网劫持：宣告覆盖多个合法前缀的更大范围前缀（如/16劫持多个/24），导致大范围流量偏移。  
4. 某些劫持源于配置错误（如意外宣告客户前缀），但危害等同恶意行为。  
5. 2018年Amazon Route 53 DNS劫持事件即由土耳其ISP误宣告192.0.2.0/24引发，波及全球加密货币交易所。

四、防御措施与实践建议  
1. 部署RPKI并启用ROA（路由源授权），在BGP路由器上配置RTR协议验证宣告合法性。  
2. 实施BGP前缀过滤：基于IRR数据库或本地策略，严格限制客户AS可宣告的前缀范围与最大长度。  
3. 启用BGPsec尚处试验阶段，当前应优先落实AS_PATH限制、最大前缀数约束及宣告速率限制。  
4. 运营商需加入MANRS（Mutually Agreed Norms for Routing Security）并定期审计路由策略一致性。  
5. 网络运营者应监控BGP更新流（如使用BGPMon、GlobaLeaks），对异常AS_PATH长度突变或新来源宣告实时告警。  
6. 关键服务（如DNS、证书分发）应采用多宿主+Anycast+HTTP Strict Transport Security等纵深防护降低单点劫持风险。
