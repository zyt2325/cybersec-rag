密码协议设计原则

一、基本概念  
1. 密码协议是两个或多个参与者为完成特定安全目标（如密钥交换、身份认证）而执行的、基于密码学原语的交互步骤序列。  
2. 协议安全性不仅依赖底层密码算法强度，更取决于消息结构、时序控制、状态管理等协议层设计细节。  
3. 形式化验证是评估协议正确性的核心方法，需建模攻击者能力（如Dolev-Yao模型）并证明其满足机密性、完整性、认证性等目标属性。  
4. 协议实体必须明确标识自身角色（如发起方/响应方）、生命周期（会话密钥有效期）及失败处理机制（如重传阈值、会话终止条件）。  

二、原理与关键机制  
1. 完整性保护须绑定所有相关字段：时间戳、随机数、主体标识、密钥派生参数均需纳入MAC或数字签名覆盖范围。  
2. 抗重放攻击依赖不可预测且单次有效的抗重放因子，如强伪随机数（nonce）、单调递增序列号或带有效期的时间戳。  
3. 密钥分离原则要求不同安全目标使用独立密钥：如加密密钥与MAC密钥不可复用，长期密钥与会话密钥须通过密钥派生函数（KDF）隔离。  
4. 消息认证必须验证全部协议上下文，避免“认证粘贴”漏洞——攻击者将合法消息片段拼接到其他会话中。  

三、典型类型与常见问题  
1. 认证密钥协商协议（如SIGMA、TLS 1.3 PSK模式）易因缺少显式密钥确认步骤导致未知密钥共享（UKS）攻击。  
2. 简单挑战-响应协议若未绑定通道参数（如IP地址、端口），可能遭受中间人劫持或跨协议重放。  
3. 基于口令的协议（如SRP）若未对口令哈希加盐且迭代不足，易受离线字典攻击。  
4. 隐私敏感协议（如匿名凭证系统）若未隐藏用户标识符或访问模式，可能被流量分析或关联攻击去匿名化。  

四、防御措施与实践建议  
1. 强制使用经标准化验证的协议构造（如RFC 8446 TLS 1.3），禁用已知脆弱变体（如SSLv3、TLS 1.0中的CBC填充模式）。  
2. 所有协议消息必须包含版本号字段并执行严格版本协商，拒绝低版本降级请求以防范降级攻击。  
3. 实现时需校验所有输入长度与格式（如RSA签名长度、ECC点坐标有效性），防止解析歧义引发逻辑绕过。  
4. 会话密钥生成必须调用密码学安全随机数生成器（CSPRNG），禁止使用时间、PID等可预测熵源。  
5. 协议实现应提供可配置的算法套件策略，支持按安全等级分级启用（如仅允许AEAD密码套件，禁用无认证加密模式）。  
6. 日志记录须剥离敏感字段（如密钥、口令哈希），仅保留审计所需元数据（时间、操作类型、主体ID、结果状态）。
