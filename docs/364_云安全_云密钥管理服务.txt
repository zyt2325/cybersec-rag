云密钥管理服务

一、基本概念  
1. 云密钥管理服务（Cloud KMS）是云服务商提供的托管式密钥生命周期管理平台，支持对称与非对称密钥的生成、存储、轮换、销毁及访问控制。  
2. KMS不直接加密用户数据，而是通过密钥加密密钥（KEK）机制保护数据加密密钥（DEK），实现分层密钥保护架构。  
3. 密钥材料默认由云厂商硬件安全模块（HSM）或FIPS 140-2/3 Level 3认证模块保护，用户无法导出主密钥明文。  
4. 所有密钥操作均通过API调用完成，每次请求生成不可篡改的审计日志，记录调用者身份、时间、密钥ID及操作类型。  

二、原理与关键机制  
1. 密钥分层结构：根密钥（Root Key）固化于HSM内，用于派生密钥加密密钥（KEK），KEK再加密用户数据密钥（DEK）。  
2. 加密即服务（EaaS）模式：应用调用KMS Encrypt API传入明文DEK，KMS返回密文DEK；解密时仅返回明文DEK，不接触原始业务数据。  
3. 基于属性的访问控制（ABAC）：策略可基于IAM角色、标签、IP地址、TLS证书状态等多维属性动态授权密钥操作权限。  
4. 自动密钥轮换：启用后KMS每90天生成新密钥版本，旧版本仍可用于解密，但新加密强制使用最新版本，保障前向安全性。  

三、典型类型与常见问题  
1. 托管式KMS（如AWS KMS、Azure Key Vault）：密钥材料由云厂商完全托管，符合合规要求但缺乏物理控制权。  
2. 客户托管HSM（如AWS CloudHSM、GCP External Key Manager）：用户独占HSM实例或接入外部HSM，满足金融等强监管场景。  
3. 密钥滥用风险：未配置密钥使用限制（如仅允许加密/解密）可能导致密钥被用于签名验证等非预期操作。  
4. 权限过度分配：将kms:Decrypt权限授予无须解密能力的服务角色，扩大攻击面，易被横向提权利用。  
5. 日志监控缺失：未启用CloudTrail或Key Management Audit Logs，导致密钥异常调用行为无法及时检测。  

四、防御措施与实践建议  
1. 实施最小权限原则：为每个应用分配独立密钥，并通过资源级策略限定其仅能访问指定密钥及特定操作（如kms:Encrypt）。  
2. 启用密钥自动轮换并设置密钥有效期策略，对静态密钥强制执行90天轮换，对临时密钥设定TTL（如JWT签名密钥设为24小时）。  
3. 集成密钥使用监控：订阅KMS审计日志至SIEM系统，对高频Decrypt调用、跨区域密钥访问、非工作时间操作设置告警阈值。  
4. 敏感密钥禁用导出：创建密钥时明确设置KeyUsage为ENCRYPT_DECRYPT或SIGN_VERIFY，禁止启用kms:ReEncryptFrom权限。  
5. 混合云场景下采用外部密钥管理器（EKM）：通过gRPC接口对接本地HSM，确保密钥控制权保留在企业侧，满足GDPR或等保三级要求。
