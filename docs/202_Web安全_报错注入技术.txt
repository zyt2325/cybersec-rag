报错注入技术

一、基本概念  
1. 报错注入是一种利用数据库系统在SQL语法或语义错误时返回详细错误信息的漏洞，实现数据窃取的注入技术。  
2. 该技术不依赖布尔响应或时间延迟，而是直接从数据库错误消息中提取目标数据。  
3. 常见于MySQL、PostgreSQL、SQL Server等支持丰富错误提示的数据库系统。  
4. 属于带外（out-of-band）注入的补充手段，适用于回显受限但错误信息未被过滤的Web应用环境。  

二、原理与关键机制  
1. 攻击者构造非法SQL语句，触发数据库异常，使错误消息中嵌入可控的查询结果（如通过函数拼接）。  
2. 利用数据库内置错误生成函数（如MySQL的extractvalue()、updatexml()，SQL Server的xp_dirtree）强制报错并携带数据。  
3. 错误消息经Web服务器未过滤地返回至前端，形成数据泄露通道。  
4. 关键前提是应用未对数据库错误信息做统一脱敏处理，且未启用自定义错误页面。  
5. 依赖数据库对错误上下文的详细输出能力，不同版本间错误信息粒度存在差异。  

三、典型类型与常见问题  
1. XML函数报错型：在MySQL中利用extractvalue()或updatexml()触发XPath解析错误，将子查询结果注入错误消息。  
2. 数据类型转换报错型：在SQL Server中使用convert()或cast()强制类型转换失败，使错误信息包含转换值。  
3. 几何函数报错型：PostgreSQL中利用st_geomfromtext()等空间函数传入非法WKT格式，触发含查询结果的错误。  
4. 常见问题包括：错误信息被WAF截断、PHP display_errors关闭导致无回显、数据库配置log_errors=off影响本地调试。  
5. 应用层日志若记录原始错误，可能造成敏感信息二次泄露，扩大攻击面。  

四、防御措施与实践建议  
1. 生产环境禁用数据库详细错误输出，配置show_errors=off（MySQL）、SHOWPLAN=OFF（SQL Server）等参数。  
2. Web应用统一使用自定义错误页面，确保所有数据库异常均返回泛化提示（如“系统繁忙”），不暴露技术栈细节。  
3. 对用户输入实施严格白名单校验，尤其过滤XML路径符号（/、@）、类型转换关键字（CONVERT、CAST）及空间函数名。  
4. 使用预编译参数化查询，从根本上阻断SQL结构被篡改的可能性，避免动态拼接SQL语句。  
5. 数据库账户遵循最小权限原则，禁用xp_cmdshell、xp_dirtree等高危扩展存储过程，限制information_schema访问权限。  
6. 部署WAF时启用SQL注入规则集，并针对extractvalue、updatexml、st_geomfromtext等特征函数设置正则拦截策略。
