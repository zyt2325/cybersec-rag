HTTP响应拆分

一、基本概念  
1. HTTP响应拆分是一种Web应用层注入攻击，攻击者通过操控用户可控输入，向HTTP响应头中注入恶意换行符（CRLF）。  
2. 该漏洞本质是服务端未对输入中的\r\n序列进行过滤或转义，导致响应头与响应体边界被非法篡改。  
3. 攻击成功后，服务器可能发送两个或多个独立HTTP响应，后续响应内容完全由攻击者控制。  
4. 漏洞成因与HTTP协议的文本解析特性直接相关，依赖于服务端使用用户输入动态构造响应头（如Location、Set-Cookie）。  

二、原理与关键机制  
1. HTTP协议以CRLF（\r\n）作为头部字段分隔符，且用空CRLF标记头部结束、正文开始。  
2. 当用户输入被拼接到响应头值中（如重定向URL），若含\r\n，将提前终止当前头字段并开启新字段或响应体。  
3. 攻击者可利用\r\n\r\n组合跳过头部区，直接注入伪造的响应体内容（如HTML、JavaScript）。  
4. 若响应头存在缓存代理，拆分后的第二个响应可能被缓存并返回给其他用户，造成缓存污染。  
5. 该攻击不依赖服务端代码执行，仅需响应头构造逻辑存在CRLF注入点即可触发。  

三、典型类型与常见问题  
1. 重定向劫持：在Location头注入CRLF，插入额外Set-Cookie或HTML响应体，诱导用户执行恶意操作。  
2. 缓存投毒：通过代理服务器缓存拆分后的第二个响应，使其他用户接收攻击者定制的内容。  
3. XSS协同攻击：注入包含<script>标签的响应体，在受害者浏览器中执行任意脚本。  
4. 常见高危函数包括Java的HttpServletResponse.setHeader()、PHP的header()、Node.js的res.setHeader()等未校验输入的调用。  
5. 日志伪造：部分场景下CRLF注入可干扰WAF或日志系统解析，掩盖攻击痕迹或触发解析错误。  

四、防御措施与实践建议  
1. 对所有用户输入中的\r、\n、\r\n字符进行严格过滤或统一替换为空格、下划线等安全字符。  
2. 使用白名单机制校验重定向URL等头字段值，仅允许ASCII字母、数字及预定义安全符号。  
3. 避免将用户输入直接拼接进HTTP响应头；优先采用框架内置的安全重定向方法（如Spring的RedirectView）。  
4. 在设置响应头前，对输入调用标准化清理函数（如Apache Commons Text的StringEscapeUtils.escapeHtml4不适用，应专用于CRLF）。  
5. 启用Web应用防火墙（WAF）规则检测响应头中异常CRLF序列，但不可替代服务端输入验证。  
6. 对输出到响应头的数据实施双重编码检查：先做CRLF过滤，再验证是否符合RFC 7230规定的字段值格式。
