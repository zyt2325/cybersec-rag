不安全的直接对象引用

一、基本概念  
1. 不安全的直接对象引用（IDOR）指应用程序使用用户可控输入直接访问内部对象（如文件、数据库记录、账户ID），且未校验访问权限。  
2. IDOR属于OWASP Top 10中“失效的访问控制”类漏洞的典型表现形式，本质是授权缺失而非认证缺陷。  
3. 常见于Web应用中通过URL参数、表单字段或API请求体传递对象标识符（如?id=123、/file?name=report.pdf）的场景。  
4. 漏洞影响范围广，可导致敏感数据泄露、越权操作、账户劫持等高风险后果，但通常不涉及代码执行。  

二、原理与关键机制  
1. 应用程序将未经验证的用户输入（如URL中的user_id）直接拼入数据库查询或文件路径，跳过权限检查逻辑。  
2. 对象标识符（如整数ID、UUID、文件名）本身无内在安全性，其语义和访问约束完全依赖服务端权限策略。  
3. 权限校验若仅在前端或中间件层进行，而服务端未对每个请求重新验证主体与目标对象的授权关系，即构成IDOR风险。  
4. 当系统采用顺序分配ID（如1,2,3…）或可预测命名规则时，攻击者可通过枚举快速发现合法对象引用。  

三、典型类型与常见问题  
1. 基于数字ID的枚举：如GET /api/user?id=1001→1005，可批量获取他人用户资料。  
2. 文件路径遍历结合IDOR：如/download?file=invoice_2023_001.pdf，替换为他人发票编号即可下载。  
3. RESTful资源ID滥用：/orders/789中789为订单ID，若未校验该订单归属当前用户，则存在越权查看风险。  
4. API响应中暴露敏感引用：返回JSON含"avatar_url":"/images/user_556.png"，攻击者可尝试修改556为其他值。  
5. 多租户环境隔离失效：SaaS平台中客户A通过修改tenant_id或org_id访问客户B的配置数据。  

四、防御措施与实践建议  
1. 强制实施基于角色或属性的服务器端访问控制（RBAC/ABAC），每次请求均校验主体对目标对象的显式权限。  
2. 避免在客户端暴露原始对象标识符，改用不可预测的间接引用（如映射表token、哈希化ID、短期有效凭证）。  
3. 对所有直接对象引用入口（URL参数、POST body、HTTP头）实施白名单校验，拒绝非预期格式或范围外值。  
4. 数据库查询应绑定用户上下文，例如SELECT * FROM orders WHERE id = ? AND user_id = current_user_id。  
5. 日志记录所有对象引用访问行为，对高频ID枚举、跨租户ID访问等异常模式实施实时告警。  
6. 在开发阶段启用自动化检测工具（如Burp Suite插件、ZAP主动扫描），并纳入CI/CD流程进行IDOR用例回归测试。
