数据防泄漏DLP

一、基本概念  
1. DLP（Data Loss Prevention）是通过策略驱动的技术手段，识别、监控和保护敏感数据在存储、传输和使用过程中的非授权外泄。  
2. 敏感数据包括个人身份信息（PII）、支付卡信息（PCI）、受保护健康信息（PHI）、源代码、商业秘密等结构化与非结构化数据。  
3. DLP系统不替代访问控制或加密，而是补充性防护层，聚焦于数据内容本身而非仅凭位置或权限判断风险。  
4. 泄漏路径涵盖终端外设（USB/打印）、网络通道（邮件/Web上传/即时通讯）、云应用同步及内部恶意操作等场景。  

二、原理与关键机制  
1. 内容识别依赖多维检测技术：正则表达式匹配、关键词字典、文件指纹（如SHA-256哈希比对）、机器学习分类器（如文档主题建模）。  
2. 策略引擎执行实时策略评估，依据数据类型、用户角色、设备状态、地理位置、通信协议等上下文动态决策阻断、告警或加密。  
3. 深度内容解析支持主流格式：PDF元数据提取、Office文档属性与隐藏文本扫描、图像OCR识别（含截图与扫描件）、压缩包递归解压分析。  
4. 网络DLP常部署于代理服务器或网关，通过SSL/TLS解密（需合法证书部署）检测HTTPS流量中的敏感内容载荷。  

三、典型类型与常见问题  
1. 终端DLP在员工设备部署代理，可管控剪贴板、截屏、外设读写及本地文件操作，但易受高权限用户绕过或卸载。  
2. 网络DLP部署于边界出口，覆盖邮件网关、Web代理、防火墙集成模块，对加密流量依赖中间人解密能力，存在性能瓶颈与隐私合规风险。  
3. 云DLP通过API对接SaaS应用（如O365、Google Workspace），扫描共享链接权限、协作文档内容及第三方应用数据导出行为。  
4. 常见失效原因包括：策略粒度粗（如全公司禁用所有USB）、未更新敏感数据特征库、忽略影子IT应用接入、误报率高导致策略被管理员禁用。  

四、防御措施与实践建议  
1. 实施数据分级分类：按法规要求（如GDPR、等保2.0）定义数据敏感等级，结合业务影响评估确定保护优先级。  
2. 分阶段部署：先启用监控模式（仅审计不阻断），收集基线行为数据，再逐步启用阻断策略，避免业务中断。  
3. 集成身份与终端管理：将DLP策略与AD/LDAP角色绑定，结合EDR终端状态（如是否开启全盘加密、是否安装防病毒软件）动态调整策略强度。  
4. 定期验证策略有效性：使用模拟测试数据（如嵌入测试信用卡号的PDF）触发策略，检查日志记录、告警推送与阻断动作是否完整生效。  
5. 建立数据流转图谱：绘制核心业务系统间的数据接口、API调用与文件交换路径，针对性部署DLP传感器，避免防护盲区。
