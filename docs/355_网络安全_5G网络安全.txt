5G网络安全

一、基本概念  
1. 5G网络安全指保障第五代移动通信系统在接入、传输、核心网及服务层免受未授权访问、数据泄露、服务中断等威胁的综合防护体系。  
2. 相比4G，5G引入网络切片、边缘计算、服务化架构（SBA）和网络功能虚拟化（NFV），安全边界从固定拓扑转向动态逻辑隔离。  
3. 3GPP TS 33.501定义了5G安全架构，明确认证与密钥协商（AKA）增强、用户面完整性保护、永久订阅标识符（SUPI）隐私保护等基础要求。  
4. 5G安全责任模型为“共享责任”，运营商负责基础设施与核心网防护，垂直行业客户需对其切片配置、终端接入策略及应用层安全负责。

二、原理与关键机制  
1. 5G AKA协议采用SUCI（订阅隐藏标识符）替代明文SUPI，通过公钥加密隐藏用户真实身份，防范IMSI捕获攻击。  
2. 网络切片间实行严格逻辑隔离，基于UPF（用户面功能）分流与NRF（网络存储功能）服务发现实现切片专属认证与策略控制。  
3. 用户面支持可选完整性保护（仅控制面强制），由PDCP层执行，密钥派生于5G-SEPP（安全锚点）生成的KgNB或KgNB*。  
4. 服务化接口（如Nudm、Nausf）采用TLS 1.3双向认证与OAuth 2.0令牌授权，防止API越权调用与中间人劫持。  
5. ME（移动设备）与SEAF（安全锚功能）协同完成二次认证，支持EPS-AKA’向5G-AKA平滑演进，并兼容EAP-TLS等扩展认证方式。

三、典型类型与常见问题  
1. SUCI解密攻击：攻击者利用弱加密配置或侧信道信息还原SUPI，进而实施位置追踪或伪装注册。  
2. 切片越界访问：因UPF策略配置错误或NSSF（网络切片选择功能）鉴权缺失，导致低保障切片用户访问高保障业务资源。  
3. 信令风暴与泛洪：恶意终端伪造大量NAS（非接入层）注册请求，耗尽AMF（接入管理功能）会话资源，引发拒绝服务。  
4. 边缘计算节点劫持：MEC平台若未启用可信启动与远程证明，可能被植入恶意容器镜像，窃取本地卸载业务数据。  
5. 开放RAN（O-RAN）接口风险：近实时RIC与非实时RIC间E2接口若缺乏证书绑定与消息签名，易遭篡改或重放。

四、防御措施与实践建议  
1. 运营商应强制启用SUCI加密并定期轮换公钥，禁用明文SUPI传输；对SUPI解密能力实施最小权限管控与审计日志留存。  
2. 切片部署须遵循“零信任”原则：UPF策略按切片ID+DNN+QoS等级三维匹配，NSSF返回结果需经AMF二次校验。  
3. AMF应配置NAS信令速率限制与异常行为检测模型，对高频注册/去附着请求触发自动隔离与人工复核流程。  
4. MEC平台须集成TPM 2.0或TEE（可信执行环境），所有容器镜像签名验证通过后方可加载，日志同步至集中SIEM系统。  
5. O-RAN部署中，E2接口必须启用X.509双向证书认证，RIC间通信使用SM4-GCM加密，且每30分钟刷新一次会话密钥。  
6. 垂直行业客户需在切片订购时明确定义安全等级（如3GPP定义的NSSAIs），并在终端侧启用5GS（5G系统）专用安全策略配置文件（SPC）。
