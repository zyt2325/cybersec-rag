接口未授权访问

一、基本概念  
1. 接口未授权访问是指攻击者在未通过身份认证或权限校验的情况下，直接调用系统API接口并获取敏感数据或执行越权操作。  
2. 该漏洞本质是服务端对请求来源缺乏有效访问控制，常见于Web API、RESTful接口、GraphQL端点及内部微服务通信接口。  
3. 不同于传统Web页面未授权访问，接口未授权更易被自动化工具批量探测，且响应数据结构化程度高，信息泄露风险更大。  
4. 漏洞成因多源于开发阶段忽略权限设计，将“前端隐藏”误认为安全措施，或测试环境配置残留导致接口暴露。  

二、原理与关键机制  
1. 服务端未在接口入口处校验用户身份（如缺失JWT解析、Session验证或OAuth2令牌校验逻辑）。  
2. 权限控制粒度粗放，仅校验登录状态而未校验角色、租户ID或资源归属关系，导致横向越权（如用户A访问用户B的订单接口）。  
3. 接口路径未纳入统一网关鉴权策略，绕过API网关或反向代理的认证中间件直接访问后端服务。  
4. 敏感操作接口未强制要求二次认证（如修改密码、删除账户），仅依赖单次会话凭证。  

三、典型类型与常见问题  
1. 管理后台接口暴露：如/admin/users、/api/v1/config等未设访问限制，可枚举用户列表或读取系统配置。  
2. IDOR类漏洞：通过修改URL路径参数（如/user?id=1001）或请求体字段（如{"target_id":"admin"}）越权访问他人资源。  
3. GraphQL内省查询启用：未禁用__schema和__type元字段，导致攻击者自动发现全部接口、参数及数据模型。  
4. 调试接口遗留：如/actuator/env（Spring Boot）、/debug/pprof（Go）等未移除或未加访问控制，泄露环境变量或内存信息。  
5. 文件上传/下载接口无校验：/api/upload、/file/download?path=../etc/passwd 类接口未校验路径合法性，引发任意文件读写。  

四、防御措施与实践建议  
1. 实施最小权限原则：每个接口须明确声明所需认证方式（如Bearer Token）、角色权限（如ROLE_ADMIN）及资源级约束（如owner_id=${user.id}）。  
2. 统一接入API网关：所有外部接口必须经网关进行身份认证、速率限制、IP黑白名单及请求头校验（如检查Origin、Referer）。  
3. 禁用非生产环境功能：上线前关闭调试端点、GraphQL内省、Swagger UI文档自动发布，并移除测试账号与默认凭证。  
4. 强制服务端资源归属校验：对GET/PUT/DELETE请求中的资源标识符（如user_id、order_no），须在业务逻辑层二次比对当前用户上下文。  
5. 定期开展接口资产测绘：使用Burp Suite或自研爬虫扫描未注册接口路径，结合OpenAPI规范比对实际暴露面，及时下线废弃接口。  
6. 日志审计全覆盖：记录所有接口的请求方IP、用户标识（若存在）、接口路径、响应状态码及耗时，异常高频401/403请求需触发告警。
