日志分析与溯源

一、基本概念  
1. 日志分析是通过解析系统、网络设备、应用等产生的结构化或半结构化日志，识别异常行为、安全事件及攻击痕迹的过程。  
2. 溯源是在日志分析基础上，结合时间线重建、IP关联、账户行为链等手段，定位攻击者入口点、横向移动路径及最终影响范围的技术活动。  
3. 日志源包括操作系统审计日志（如Linux auditd、Windows Event Log）、防火墙会话日志、IDS/IPS告警、Web服务器访问日志（access.log）及数据库审计日志。  
4. 时间同步（NTP）是日志分析的前提，时钟偏差超过5分钟将导致多源日志无法准确对齐时间线。  
5. 日志完整性保障依赖防篡改机制，如WORM存储、日志签名或基于区块链的哈希链存证。

二、原理与关键机制  
1. 关联分析通过规则引擎或图计算模型，将分散在不同日志源中的孤立事件（如登录失败→SSH成功→sudo提权）聚合成攻击链。  
2. 时间窗口滑动技术用于检测高频异常，例如10分钟内同一IP触发5次401响应后出现200响应，可能指示暴力破解成功。  
3. 用户实体行为分析（UEBA）建立基线模型，将账户登录时段、地理跳变、命令序列等作为特征，识别隐蔽的横向移动。  
4. 日志归一化将不同格式日志（如Syslog、JSON、CEF）映射为统一字段结构（如src_ip、event_type、timestamp），支撑跨设备查询。  
5. 原始日志保留原始时间戳、进程ID、完整命令行参数（含空格转义），避免解析过程丢失关键上下文。

三、典型类型与常见问题  
1. Web日志中User-Agent字段伪造普遍，需结合Referer、Cookie有效期、TLS指纹交叉验证真实客户端。  
2. Windows事件ID 4624（登录）需关注Logon Type字段：Type 3表示网络登录，Type 10表示远程桌面，二者权限路径差异显著。  
3. 防火墙日志缺失连接关闭标志（FIN/RST）时，易将长连接误判为持续攻击，应结合会话超时策略校验。  
4. 日志轮转配置不当（如仅保留7天）导致APT攻击的早期侦察阶段痕迹被覆盖，无法完成全周期溯源。  
5. 应用日志未记录操作对象标识（如文件绝对路径、数据库表名），使权限滥用行为难以定位具体受损资产。

四、防御措施与实践建议  
1. 部署集中式日志平台（如ELK或Splunk）时，必须启用传输加密（TLS 1.2+）与接收端证书双向认证。  
2. 对特权操作日志实施实时监控，例如Linux sudoers配置变更、Windows本地管理员组成员增删，触发即时告警。  
3. 建立日志留存策略：核心系统审计日志至少保存180天，符合等保2.0三级系统要求。  
4. 定期执行日志有效性验证，使用已知攻击载荷（如SQLi测试字符串）注入测试环境，确认日志是否完整捕获并标记为高危事件。  
5. 运维人员须禁用日志中明文记录密码、密钥、令牌等敏感信息，采用字段脱敏或正则过滤规则（如掩码API_KEY=.*?）预处理。  
6. 溯源报告需包含可验证证据链：原始日志片段（含时间戳、主机名、事件ID）、关联推理逻辑、排除其他可能性的依据。
