SaaS安全

一、基本概念  
1. SaaS（软件即服务）是通过互联网提供可配置应用的云服务模式，用户无需管理底层基础设施。  
2. SaaS安全指保障多租户架构下数据保密性、完整性、可用性及合规性的技术与管理措施集合。  
3. 共享责任模型明确划分云服务商与客户的安全边界：厂商负责平台层安全，客户负责配置、身份与数据层安全。  
4. 租户隔离是SaaS核心安全前提，依赖逻辑隔离机制（如命名空间、数据库分片）防止跨租户数据泄露。  
5. API接口是SaaS主要交互通道，其暴露面广、调用频次高，成为攻击者重点利用目标。

二、原理与关键机制  
1. 身份联合（如SAML/OIDC）实现单点登录，降低密码复用风险，但需严格校验断言签名与受众字段。  
2. 细粒度访问控制（RBAC/ABAC）依据角色或属性动态授权，避免权限过度分配导致横向移动。  
3. 数据加密采用分层策略：传输中使用TLS 1.2+，静态数据按租户密钥加密，密钥由HSM或KMS托管。  
4. 日志审计需覆盖API调用、配置变更、登录行为，日志须不可篡改且留存≥180天以满足GDPR等合规要求。  
5. 自动化配置扫描工具持续检测SaaS应用中的高危设置，如公开共享链接、禁用MFA、宽泛的管理员权限。

三、典型类型与常见问题  
1. 协作类SaaS（如Office 365、Slack）易因误共享文档或频道权限配置过松导致数据外泄。  
2. CRM类SaaS（如Salesforce）常存在自定义字段未脱敏、导出功能绕过DLP策略等数据泄露路径。  
3. 配置漂移现象普遍：管理员手动修改生产环境设置后未同步至IaC模板，造成安全基线失效。  
4. 第三方集成应用（OAuth授权）可能获取超出业务所需的API权限，形成隐蔽持久化入口。  
5. 供应链风险突出：SaaS厂商使用的开源组件漏洞（如Log4j）可影响全部租户，修复延迟达数周。

四、防御措施与实践建议  
1. 强制实施条件访问策略，对非常规地理位置、设备合规性或风险登录行为实时阻断或触发MFA。  
2. 使用CASB（云访问安全代理）实现影子IT发现、DLP策略执行及异常API流量检测。  
3. 对所有OAuth集成执行最小权限原则，定期轮换令牌并审计授权范围，禁用长期有效的refresh token。  
4. 将SaaS配置纳入IaC管理（如Terraform + Sentinel），通过代码评审与自动化测试保障配置一致性。  
5. 开展SaaS专属红蓝对抗：模拟凭证填充、API滥用、权限提升等场景，验证租户隔离与审计响应有效性。  
6. 要求SaaS供应商提供SOC 2 Type II报告、渗透测试摘要及加密算法清单，拒绝使用弱随机数生成器的实例。
