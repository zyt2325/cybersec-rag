物联网安全

一、基本概念  
1. 物联网安全指保障物联网设备、通信链路、云平台及数据在采集、传输、存储、处理全生命周期中的机密性、完整性和可用性。  
2. 物联网系统通常由感知层（传感器/执行器）、网络层（LPWAN/蓝牙/Wi-Fi/5G）、平台层（IoT云平台）和应用层（移动端/Web端）构成。  
3. 设备资源受限性（如MCU内存＜256KB、无硬件加密模块）是物联网安全区别于传统IT安全的核心约束条件。  
4. 身份认证粒度细，需支持海量设备（百万级/单平台）的轻量级唯一标识与动态凭证管理。  

二、原理与关键机制  
1. 轻量级密码学机制：采用基于ECC的TLS 1.2/1.3精简栈（如mbed TLS）、AES-128-CTR用于设备端加密，避免RSA等重载算法。  
2. 设备身份可信根（RoT）依赖硬件安全模块（HSM）或PUF（物理不可克隆函数）实现密钥安全生成与存储，防止固件提取后密钥泄露。  
3. OTA升级需强制签名验证（ECDSA-SHA256），且支持差分升级与回滚保护，防止降级攻击或恶意固件注入。  
4. 网络层采用MAC层加密（如LoRaWAN AES-128）与应用层加密（AES-GCM）双重保护，规避协议栈中间层解密风险。  

三、典型类型与常见问题  
1. 设备端漏洞：默认凭证未修改（如admin:123456）、调试接口（JTAG/SWD）未禁用、固件未签名导致刷机劫持。  
2. 协议脆弱性：MQTT未启用TLS时明文传输设备状态；CoAP使用UDP且缺乏重放防护，易受消息重放与反射放大攻击。  
3. 平台层风险：云平台API密钥硬编码在设备固件中；设备影子（Device Shadow）服务未设访问策略，导致越权读写设备状态。  
4. 供应链隐患：第三方SDK含已知CVE漏洞（如glibc幽灵漏洞变种）、芯片厂商预置后门固件（如某些Wi-Fi SoC的隐藏AT指令）。  

四、防御措施与实践建议  
1. 设备启动阶段实施Secure Boot：验证Bootloader→OS→应用固件的逐级签名，任一环节失败即停机。  
2. 通信强制双向mTLS认证：设备证书由私有CA签发，有效期≤1年，并集成OCSP Stapling减少握手延迟。  
3. 最小权限原则配置设备能力：关闭未使用服务（如Telnet/FTP）、限制HTTP API仅开放必要端点与HTTP方法（禁用PUT/DELETE）。  
4. 日志与异常检测下沉至边缘：设备本地记录关键事件（如连续3次认证失败），通过LWM2M协议上报至SIEM系统。  
5. 建立设备全生命周期密钥管理体系：密钥生成于HSM内，轮换周期≤90天，报废设备执行密钥擦除指令（如ARM TrustZone TZASC锁存）。  
6. 渗透测试覆盖物理层：检查设备外壳防拆开关有效性、UART引脚电平是否暴露调试信息、电源侧边信道是否可推断密钥操作。
