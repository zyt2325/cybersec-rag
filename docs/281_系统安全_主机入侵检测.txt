主机入侵检测

一、基本概念  
1. 主机入侵检测系统（HIDS）是部署在单台主机上的安全监控软件，用于实时分析本地系统活动以识别潜在入侵行为。  
2. HIDS核心目标是发现未授权访问、恶意代码执行、权限提升、配置篡改等违反安全策略的异常操作。  
3. 区别于网络入侵检测（NIDS），HIDS直接采集操作系统内核日志、进程树、文件完整性哈希、注册表（Windows）或sysctl参数（Linux）等宿主层数据源。  
4. 典型HIDS包括OSSEC、Wazuh、Tripwire及现代EDR平台中的检测引擎模块，均依赖主机代理程序持续采集与分析。  

二、原理与关键机制  
1. 基于签名检测：匹配已知攻击行为特征（如特定恶意进程命令行参数模式、rootkit系统调用序列），依赖高质量规则库更新。  
2. 异常检测：通过建立主机正常行为基线（如CPU/内存使用率分布、登录时间规律、文件访问频率），识别显著偏离的统计异常。  
3. 完整性校验：定期计算关键系统文件（/bin/ls、/sbin/init等）、配置文件（/etc/passwd、/etc/shadow）的SHA-256哈希值，比对预存基准值。  
4. 日志关联分析：聚合分析系统日志（auth.log、secure）、应用日志（Apache error_log）和审计子系统（Linux auditd）事件，识别跨组件攻击链。  

三、典型类型与常见问题  
1. 文件完整性监控型HIDS易受高级持久化攻击绕过，攻击者可能篡改哈希数据库或禁用监控服务本身。  
2. 行为分析型HIDS存在高误报风险，例如批量脚本运维可能被误判为横向移动，需结合上下文白名单机制优化。  
3. 内核级HIDS（如基于eBPF的检测器）可捕获系统调用级行为，但需适配不同内核版本，且在容器环境中面临命名空间隔离挑战。  
4. 云主机场景下，HIDS常因虚拟化层抽象导致部分硬件事件（如DMA访问）不可见，降低对固件级攻击的检出能力。  

四、防御措施与实践建议  
1. 启用操作系统原生审计框架（Linux auditd、Windows Event Tracing），确保记录关键事件如execve调用、sudo权限获取、计划任务创建。  
2. 将HIDS代理部署为高权限守护进程，并通过SELinux/AppArmor策略限制其仅能读取必要路径与系统调用，防止被劫持。  
3. 对HIDS自身配置文件、规则库及签名数据库实施只读挂载与数字签名验证，阻断攻击者篡改检测逻辑。  
4. 结合终端行为分析（TBA）与威胁情报源（如MISP），动态更新YARA规则与IOA指标，覆盖0day利用后的横向渗透阶段行为。  
5. 在CI/CD流水线中集成HIDS配置检查，确保新部署主机自动加载合规基线策略（如禁止SSH空密码、限制root远程登录）。
