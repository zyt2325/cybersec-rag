网络流量分析

一、基本概念  
1. 网络流量分析指对网络中传输的数据包进行捕获、解析、统计与行为建模，以理解通信模式、识别异常及评估安全状态。  
2. 流量可按粒度分为包级（原始帧）、流级（五元组会话）和会话级（应用层交互序列），分析目标决定粒度选择。  
3. 常见数据源包括镜像端口（SPAN）、网络分路器（TAP）、NetFlow/sFlow/IPFIX导出流、主机内核抓包接口（如AF_PACKET）。  
4. 流量特征包含协议类型、载荷长度分布、时间间隔、TLS握手参数、DNS查询频率与域名熵值等可观测指标。  

二、原理与关键机制  
1. 深度包检测（DPI）通过解析OSI二至七层字段实现协议识别与内容匹配，依赖特征库与正则规则，但易受加密和混淆规避。  
2. 流记录生成基于五元组（源IP、目的IP、源端口、目的端口、协议）聚合报文，形成带时间戳、字节数、包数的结构化流条目。  
3. 统计建模利用滑动窗口计算流量速率、连接并发数、重传率等时序指标，结合基线偏差检测突变行为。  
4. 机器学习方法常采用LSTM或图神经网络建模流量时序依赖或主机间通信拓扑，需标注样本训练异常检测模型。  

三、典型类型与常见问题  
1. 加密流量分析（ECA）通过TLS握手特征（SNI、ALPN、证书字段、握手指纹）推断应用类型，但QUIC和ESNI降低其有效性。  
2. DNS隧道利用子域名编码隐蔽传输，表现为高频率短查询、非常规TTL、域名长度异常及与已知恶意域名相似性。  
3. C2信标常呈现周期性心跳（固定间隔HTTP GET/POST）、低频高熵载荷、User-Agent异常或使用CDN IP作为跳板。  
4. 横向移动流量在内网中体现为非业务时段的SMB/WMI/RDP连接暴增、源IP与权限角色不匹配、NTLM认证失败率骤升。  
5. DDoS攻击流量特征包括SYN洪泛导致半连接队列溢出、UDP反射放大的源IP随机化、ICMP Flood的高包速低负载比。  

四、防御措施与实践建议  
1. 部署分层流量采集：核心出口用TAP保障完整性，接入层用sFlow采样降低开销，关键服务器启用eBPF实时过滤。  
2. 建立动态基线：按业务时段、部门、资产等级分别建模流量均值与标准差，避免单一全局阈值误报。  
3. TLS解密需严格管控：仅对明确授权的内部业务流量实施SSL/TLS中间人解密，并确保私钥离线存储与审计日志完整。  
4. 结合上下文增强研判：将流量告警与终端进程行为、EDR日志、AD登录事件关联，排除扫描误报与合法运维流量。  
5. 定期更新协议解析器与特征库：适配HTTP/3、gRPC等新协议头部结构，修复因协议演进导致的DPI漏检。  
6. 对于云环境，启用VPC流日志并配置NetFlow导出至SIEM，重点监控跨可用区与跨账户流量异常。
