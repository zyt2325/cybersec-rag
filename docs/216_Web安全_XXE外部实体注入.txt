XXE外部实体注入

一、基本概念  
1. XXE（XML External Entity）是一种利用XML解析器对外部实体引用处理不当导致的安全漏洞。  
2. 攻击者通过构造恶意XML文档，诱导应用加载并解析受控的外部实体内容。  
3. 该漏洞属于服务端请求伪造（SSRF）与信息泄露的交叉型漏洞，常见于SOAP、RSS、配置文件解析等场景。  
4. XML标准允许定义内部实体和外部实体，外部实体可指向本地文件、远程HTTP/FTP资源或特殊协议URI。  
5. 漏洞触发前提是应用程序使用了不安全配置的XML解析器（如Java的DocumentBuilder、Python的xml.etree.ElementTree默认行为）。  

二、原理与关键机制  
1. XML解析器在启用外部实体解析且未禁用DOCTYPE声明时，会递归解析<!ENTITY>中定义的外部URI。  
2. 解析器将外部实体内容内联替换到XML文档中，后续业务逻辑可能直接输出、执行或存储该内容。  
3. 协议支持差异导致不同危害：file://可读取本地敏感文件（如/etc/passwd），http://可发起内网探测或带外回传。  
4. 实体嵌套与参数实体（%name;）可绕过简单关键词过滤，实现更隐蔽的内容提取。  
5. 基于错误消息的XXE（error-based XXE）利用解析异常返回的错误信息泄露数据，无需回显响应。  

三、典型类型与常见问题  
1. 文件读取型：通过file://协议读取服务器本地文件，常用于获取源码、配置凭证、SSH私钥。  
2. 带外型（OOB-XXE）：将敏感数据编码后通过DNS或HTTP请求外发至攻击者可控服务器，规避无回显限制。  
3. DOS型：利用递归实体展开（billion laughs攻击）或超大实体消耗内存与CPU，导致服务拒绝响应。  
4. SSRF扩展型：结合XML解析器对ftp://、gopher://等协议的支持，实现内网端口扫描或与内网服务交互。  
5. 二次注入型：外部实体内容被存入数据库或缓存后，在其他功能点渲染时触发XSS或命令执行。  

四、防御措施与实践建议  
1. 禁用外部实体解析：在解析器初始化时显式关闭DOCTYPE、外部DTD及外部实体加载（如Java设置FEATURE_SECURE_PROCESSING）。  
2. 使用白名单驱动的XML解析：优先采用JSON等轻量格式替代XML；若必须用XML，选用不支持外部实体的库（如Python的defusedxml）。  
3. 输入验证与输出编码：对用户提交的XML进行结构校验（如限制根元素、禁止DOCTYPE声明），响应内容严格编码后再输出。  
4. 最小权限运行解析器：XML解析进程应以低权限用户运行，限制其访问文件系统与网络的能力。  
5. 部署WAF规则：配置针对SYSTEM、PUBLIC、file://、http://等关键词的正则拦截策略，并监控异常XML请求频率。  
6. 定期审计依赖组件：检查所用XML解析库版本，及时升级至已修复XXE缺陷的稳定版（如libxml2 ≥2.9.0）。
