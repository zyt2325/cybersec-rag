固件与BIOS安全

一、基本概念  
1. 固件是嵌入在硬件设备中的持久性软件，直接控制底层硬件行为，如BIOS/UEFI、网卡固件、硬盘控制器固件等。  
2. BIOS是传统PC启动时运行的固件，负责硬件初始化和引导操作系统；UEFI是其现代替代标准，支持模块化架构与安全启动机制。  
3. 固件存储于非易失性存储器（如SPI Flash芯片）中，具有高权限、低可见性、更新频率低等特点。  
4. 固件层位于操作系统之下，可绕过OS级安全机制直接访问物理内存、CPU寄存器及I/O设备。  
5. UEFI固件由多个可执行模块（PEI、DXE、BDS阶段）组成，各阶段具备独立签名验证能力。

二、原理与关键机制  
1. 安全启动（Secure Boot）通过验证引导链中每个组件的数字签名，确保仅加载可信固件与引导加载程序。  
2. SPI Flash写保护由硬件引脚（WP#）和寄存器（Status Register WPEN位）双重控制，防止未经授权的固件擦写。  
3. UEFI变量存储区（NVRAM）受平台密钥（PK）、密钥交换密钥（KEK）和签名数据库（db/dbx）分级保护。  
4. SMM（System Management Mode）是x86 CPU的最高特权模式，SMM代码运行于SMRAM中，但存在SMM漏洞可被用于持久化攻击。  
5. Intel Boot Guard与AMD Secure Boot ROM通过熔丝配置和硬件根密钥实现启动前固件完整性校验。

三、典型类型与常见问题  
1. BIOS/UEFI固件漏洞包括缓冲区溢出、任意代码执行（如CVE-2017-5731）、SMM提权（如CVE-2019-6260）。  
2. 供应链攻击可植入恶意固件更新包，利用厂商签名机制绕过Secure Boot验证（如LoJax攻击）。  
3. 网卡固件（如Intel i210）存在远程DMA风险，配合PCIe ACS配置缺陷可实现跨设备内存读取。  
4. 嵌入式设备BootROM通常不可更新，若存在漏洞（如某些ARM SoC的USB DFU模式缺陷），将导致永久性后门。  
5. 固件调试接口（如JTAG、SWD）若未在量产中禁用，可能被用于固件提取与逆向分析。

四、防御措施与实践建议  
1. 启用并严格管理Secure Boot策略，定期更新密钥数据库（dbx），禁用测试签名（Setup Mode）。  
2. 部署固件完整性监控工具（如CHIPSEC、fwts），定期扫描SPI Flash内容与UEFI变量异常。  
3. 在BIOS设置中启用SPI写保护、禁用Legacy Boot、关闭未使用的调试接口（如Serial Over LAN、JTAG）。  
4. 采用厂商提供的带哈希校验与签名验证的固件更新机制，避免使用第三方或破解版BIOS工具。  
5. 对关键系统实施固件供应链审计，要求供应商提供SBOM（软件物料清单）及固件签名证书透明度报告。  
6. 在虚拟化环境中启用Intel TXT或AMD SVM的固件信任链扩展，构建基于TPM的远程证明基础。
