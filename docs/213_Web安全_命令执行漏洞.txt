命令执行漏洞

一、基本概念  
1. 命令执行漏洞指Web应用未对用户输入做严格过滤，导致攻击者可操控后端系统执行任意操作系统命令。  
2. 本质是服务端将不可信输入拼接进shell命令或系统调用中，造成执行上下文失控。  
3. 属于高危注入类漏洞，CVSS基础分常达9.8以上，可直接导致服务器完全失陷。  
4. 区别于代码注入（如PHP eval）：命令执行作用于OS层，影响范围覆盖整个宿主系统权限边界。  

二、原理与关键机制  
1. 触发依赖于语言/框架的危险函数调用，如PHP的system()、exec()，Java的Runtime.getRuntime().exec()，Python的os.system()。  
2. 输入未经过滤或转义即参与命令拼接，尤其当使用字符串格式化（如%s、+连接）构造命令时风险极高。  
3. 系统命令解析器（如bash、cmd.exe）会处理特殊字符（;、&、|、$()、``），形成命令链或子命令注入。  
4. 某些场景下，即使单条命令被限制，也可通过重定向（>、>>）、管道（|）或环境变量间接实现任意命令执行。  

三、典型类型与常见问题  
1. 直接命令执行：用户输入作为完整命令参数传入，如ping工具中注入“127.0.0.1;id”。  
2. 间接命令执行：输入经多次处理后进入危险函数，如日志文件路径可控→logrotate配置注入→触发shell。  
3. 二次编码绕过：对%20、%3B等URL编码字符未在解码后重新校验，导致WAF规则失效。  
4. 白名单机制缺陷：仅校验命令前缀（如“ping”）而忽略后续空格及参数拼接，仍可注入分隔符。  
5. Windows特有风险：cmd.exe对^转义支持不一致，且存在start、for等易被利用的内置命令。  

四、防御措施与实践建议  
1. 优先采用安全API替代系统命令调用，如用Socket通信替代curl调用，用ImageMagick库替代convert命令。  
2. 若必须调用外部命令，使用参数化接口（如PHP的proc_open配合数组参数），禁止字符串拼接构造命令。  
3. 对输入实施白名单校验：仅允许数字、字母、指定分隔符（如-、_），并严格限制长度与语义（如IP地址需经inet_pton验证）。  
4. 降权运行Web服务：以非root/非SYSTEM账户启动应用，配合容器命名空间或chroot限制系统访问面。  
5. 启用内核级防护：Linux启用seccomp-bpf过滤危险系统调用（如execve、clone），Windows启用AppLocker限制可执行程序。  
6. 日志审计全覆盖：记录所有命令执行函数的调用源IP、参数哈希、执行结果码，接入SIEM进行异常模式检测。
