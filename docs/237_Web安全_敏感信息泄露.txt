敏感信息泄露

一、基本概念  
1. 敏感信息指一旦未授权披露即可能造成个人权益受损或组织安全风险的数据，如身份证号、银行卡号、密钥、内部API密钥等。  
2. 信息泄露不局限于网络传输过程，也包括存储、处理、日志、备份及开发调试等全生命周期环节。  
3. 泄露主体既可能是攻击者主动窃取，也可能是系统配置错误、开发疏忽或管理失效导致的被动暴露。  
4. 法律定义依据《个人信息保护法》《数据安全法》及行业标准（如GB/T 35273），明确敏感个人信息范围与处理要求。  

二、原理与关键机制  
1. 应用层常见成因：错误配置的HTTP响应头（如X-Powered-By暴露技术栈）、未过滤的错误页面堆栈信息、调试模式启用。  
2. 服务端配置缺陷：Web服务器目录遍历漏洞、未禁用的默认文件（如.git、.DS_Store、backup.zip）、数据库配置文件误置于Web根目录。  
3. 日志机制风险：应用日志记录明文密码、令牌或用户身份标识，且日志文件可被直接访问或未脱敏归档。  
4. 客户端侧泄露：前端JavaScript硬编码API密钥、敏感配置写入HTML注释或data属性、源码映射文件（source map）暴露原始代码结构。  

三、典型类型与常见问题  
1. 配置型泄露：云存储桶（如S3）权限设置为public-read，导致数据库备份、员工花名册等文件被公开索引。  
2. 开发残留泄露：测试环境使用生产密钥、Git提交历史中包含.env文件、IDE临时文件（如.vscode/settings.json）上传至公开仓库。  
3. 接口与文档泄露：Swagger UI在生产环境未关闭，暴露全部API路径、参数及示例请求；OpenAPI规范中未移除敏感字段描述。  
4. 第三方依赖风险：NPM/PyPI包中嵌入硬编码凭证、开源组件日志模块默认输出敏感上下文、SDK初始化时明文传递密钥。  

四、防御措施与实践建议  
1. 实施最小权限原则：生产环境禁用调试模式、关闭详细错误页、限制HTTP响应头信息、定期扫描并清理冗余配置文件。  
2. 建立敏感数据识别与分级机制：使用正则+语义规则（如信用卡Luhn校验）自动识别，按等级实施加密存储与动态脱敏。  
3. 强化CI/CD流程管控：在代码提交阶段集成Secret Scanner（如Gitleaks、TruffleHog），阻断含密钥、证书的推送。  
4. 日志治理标准化：禁止记录原始密码、令牌、身份证号；采用结构化日志并配置字段级掩码策略；日志存储独立于Web可访问路径。  
5. 客户端安全加固：前端密钥交由后端代理分发，禁用source map上线，构建时剥离调试注释与敏感元数据。  
6. 定期开展泄露面测绘：使用Shodan/Censys探测暴露资产，人工验证HTTP状态码、目录索引、响应体敏感内容，建立泄露台账闭环处置。
