网络攻击面管理  

一、基本概念  
1. 攻击面指组织所有可能被利用的软硬件资产、服务接口、用户行为及第三方连接点的总和。  
2. 攻击面管理（ASM）是持续发现、分类、评估、监控和缩减组织暴露于外部威胁的数字资产集合的过程。  
3. ASM聚焦于外部可观测视角，即攻击者无需授权即可探测和分析的资产，如公网IP、域名、SSL证书、云存储桶等。  
4. 与传统漏洞管理不同，ASM不依赖内部扫描或代理部署，而是通过互联网侧主动测绘与情报聚合实现资产可见性。  
5. 攻击面具有动态性：新域名注册、云资源配置变更、员工误传敏感文件至公开平台均会实时扩大攻击面。  

二、原理与关键机制  
1. 资产发现依赖多源数据融合，包括DNS解析记录、SSL/TLS证书透明日志、BGP路由公告、云API元数据抓取等。  
2. 自动化指纹识别通过HTTP响应头、JS库特征、WAF签名、CDN标识等推断技术栈与配置状态。  
3. 暴露风险评分综合资产类型、服务版本、已知CVE关联度、证书过期状态、CSP缺失等维度量化风险等级。  
4. 关联分析将孤立资产映射至业务系统，例如识别某测试子域实际指向核心CRM系统的后端API网关。  
5. 变更检测基于时间序列比对，当新增未授权CDN节点或意外开放22/3389端口时触发告警。  

三、典型类型与常见问题  
1. 域名影子资产：离职员工注册的关联域名、过期未回收的营销活动子域、测试环境遗留的dev.*域名。  
2. 云配置漂移：S3存储桶权限设为public-read、RDS实例绑定公网IP且未启用VPC安全组限制。  
3. 第三方风险：供应商SDK嵌入恶意JS、CDN缓存泄露调试页面、OAuth回调URL未校验导致开放重定向。  
4. 员工行为暴露：GitHub代码库硬编码API密钥、LinkedIn个人资料披露内部系统路径、Zoom会议链接含可预测ID。  
5. 技术债积累：仍在运行的Windows Server 2008 R2服务器、使用SHA-1签名的旧版客户端证书、未更新的Log4j 1.x组件。  

四、防御措施与实践建议  
1. 建立跨部门资产清单责任制，明确域名、云账号、CDN服务商等资产的所有者与下线流程。  
2. 将ASM工具接入CI/CD流水线，在代码合并前自动检测硬编码密钥、敏感路径提交及错误的Dockerfile暴露指令。  
3. 对所有公网暴露资产实施最小权限原则：禁用默认账户、关闭非必要端口、强制HTTPS并启用HSTS。  
4. 定期执行红队式外部验证，模拟攻击者视角开展DNS枚举、子域爆破、证书日志爬取，检验ASM覆盖完整性。  
5. 设置自动化处置策略，如检测到新注册域名立即触发SOAR流程：暂停DNS解析、通知法务、启动品牌保护程序。  
6. 每季度审计第三方供应商安全协议，要求其提供ASM报告，并在合同中约定违规暴露导致数据泄露的连带责任条款。
