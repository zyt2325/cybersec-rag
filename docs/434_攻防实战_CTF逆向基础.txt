CTF逆向基础  
一、基本概念  
1. CTF逆向指在网络安全竞赛中，通过静态分析、动态调试等手段还原被混淆、加壳或编译后的二进制程序逻辑与关键行为。  
2. 逆向对象主要为x86/x64 ELF（Linux）、PE（Windows）及ARM/MIPS嵌入式可执行文件，常见于Pwn、Reverse、Misc类题目。  
3. 核心目标包括提取密钥、绕过验证逻辑、定位flag生成函数、还原加密算法或触发隐藏功能路径。  
4. 基础依赖汇编语言理解能力（如AT&T/Intel语法差异）、程序内存布局知识（.text/.data/.bss节作用）及调用约定（cdecl/stdcall等）。  

二、原理与关键机制  
1. 程序执行依赖指令流控制，逆向需识别分支跳转（jmp、je、jne）、循环结构（loop、cmp+jl）及函数调用/返回（call/ret）模式。  
2. 加壳技术通过修改入口点（OEP）、加密代码段、运行时解密实现保护，脱壳需定位OEP并dump内存镜像。  
3. 混淆手段包括控制流扁平化、虚假分支、字符串加密、函数内联与间接跳转，增加CFG重建与语义还原难度。  
4. 调试器利用断点（int3指令）、单步执行（TF标志位）和内存监视（硬件断点）捕获寄存器状态与内存读写行为。  

三、典型类型与常见问题  
1. 算法还原题：给出加密后输出与输入约束，需逆向识别AES、RC4、自定义异或轮转等逻辑并编写解密脚本。  
2. 许可证验证题：分析序列号校验函数，常含多层条件判断、哈希比对（如SHA256）或时间戳校验，需patch跳转或爆破输入。  
3. 虚拟机保护题：程序内置解释器执行自定义字节码，需先逆向指令集结构，再解析字节码逻辑还原原始算法。  
4. 反调试检测题：通过IsDebuggerPresent、ptrace(PTRACE_TRACEME)、时间差检测或异常处理机制干扰分析流程。  
5. Go/Rust/Python打包题：需识别运行时特征（如Go的runtime·morestack符号、PyInstaller的pyc解包结构）提取原始逻辑。  

四、防御措施与实践建议  
1. 初学者应熟练使用Ghidra进行反编译，结合IDA Pro交叉引用（Xrefs）追踪关键变量与函数调用链。  
2. 动态分析优先采用GDB（Linux）或x64dbg（Windows），设置内存断点监控关键数据结构读写，避免仅依赖源码级断点。  
3. 遇到加壳样本，先用file、strings、checksec识别壳类型，再用upx -d或手动ESP定律/Import重建辅助脱壳。  
4. 对混淆代码，借助LLVM IR反编译（如RetDec）或符号执行工具（Angr）辅助路径约束求解，减少人工推导错误。  
5. 实践中坚持“动静结合”：静态定位可疑函数，动态验证其参数与返回值；记录每处跳转条件与寄存器变化，构建执行路径图。  
6. 定期复现经典CTF Reverse题（如PlaidCTF、DEF CON Quals），重点训练从汇编片段抽象出高级逻辑（如识别斐波那契递归或Base64查表）的能力。
