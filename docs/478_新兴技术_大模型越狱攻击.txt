大模型越狱攻击

一、基本概念  
1. 大模型越狱攻击指绕过大语言模型内置安全对齐机制，诱导其生成本应被拒绝的有害、违法或违规内容。  
2. “越狱”并非突破物理或系统层隔离，而是利用提示工程手段规避模型的内容安全策略与价值观约束。  
3. 该攻击针对的是模型在推理阶段的行为控制失效，不涉及模型权重篡改或训练数据污染。  
4. 越狱成功率高度依赖模型架构、对齐方法（如RLHF、DPO）、安全护栏（guardrail）部署强度及上下文理解能力。  

二、原理与关键机制  
1. 利用模型对指令语义的敏感性差异：将禁止请求伪装为虚构场景、学术探讨或角色扮演任务。  
2. 借助多步推理链稀释风险信号，使中间输出不触发安全模块，最终合成违规结果。  
3. 利用模型对非标准语法、外语混写、符号替换等输入形式的鲁棒性缺陷，干扰安全分类器判断。  
4. 针对基于规则或轻量分类器的实时过滤层，构造语义合法但意图恶意的对抗性提示。  

三、典型类型与常见问题  
1. 角色扮演类：要求模型“以黑客导师身份回答”，利用角色设定弱化责任归属，规避伦理约束。  
2. 间接请求类：通过“分析某段恶意代码的执行逻辑”等学术化表述，诱导生成实际可运行的攻击载荷。  
3. 上下文污染类：在长对话中嵌入大量无害信息，逐步偏移模型响应倾向，降低安全模块激活概率。  
4. 多模态协同类：结合文本提示与图像描述（如ASCII艺术图），绕过纯文本安全检测机制。  
5. 模型特异性漏洞：某些越狱技巧仅对特定厂商模型有效，反映其对齐策略存在未覆盖的语义盲区。  

四、防御措施与实践建议  
1. 实施分层防护：前端提示预处理（敏感词+语义检测）+ 中端推理时动态安全评分 + 后端输出后置过滤。  
2. 引入对抗性提示测试集，在模型上线前持续评估越狱鲁棒性，覆盖角色扮演、隐喻表达等高危模式。  
3. 采用多模型协同校验：主模型生成后，由专用安全模型重审输出，二者决策不一致时触发人工复核。  
4. 限制长上下文中的权限继承：禁止用户通过历史对话逐步获取越权能力，定期重置安全上下文状态。  
5. 公开透明披露模型能力边界与已知越狱路径，避免用户因误判安全性而产生过度信任。  
6. 在API服务中强制启用最小权限原则，对高风险操作（如代码生成、系统指令模拟）实施二次确认与审计日志留存。
