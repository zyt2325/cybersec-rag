目录扫描与信息收集

一、基本概念  
1. 目录扫描是通过向目标Web服务器发送大量路径请求，探测其上存在的未公开目录或文件的技术。  
2. 信息收集是渗透测试初始阶段的核心环节，旨在获取目标系统架构、技术栈、服务版本等基础情报。  
3. 目录扫描属于被动式信息收集的延伸，常与子域名枚举、端口扫描协同构成攻击面测绘基础。  
4. 扫描结果可能暴露敏感资源，如备份文件、配置文件、管理后台、API文档等高价值入口点。  
5. 合法授权前提下，该技术可用于红队评估和蓝队自查，未经授权使用违反《网络安全法》第27条。

二、原理与关键机制  
1. 基于HTTP状态码判断资源存在性：200表示成功访问，403暗示路径存在但受限，401提示需认证。  
2. 利用Web服务器默认行为差异：如Apache对不存在路径返回404，而Nginx可能返回403或自定义页面。  
3. 依赖字典驱动：使用预置路径词典（如common.txt）逐条构造请求，匹配响应特征进行筛选。  
4. 支持递归扫描机制：发现新目录后自动将其作为父路径，继续探测其子级路径结构。  
5. 结合响应头与响应体分析：检查Content-Length突变、Server字段、HTML标题标签等辅助识别真实资源。

三、典型类型与常见问题  
1. 暴力扫描：使用全量路径字典无差别探测，易触发WAF速率限制或日志告警。  
2. 智能扫描：依据响应指纹（如HTML结构相似度、JS文件引用路径）过滤误报，提升准确率。  
3. 备份文件泄露：扫描到.git、.svn、.DS_Store或.zip/.bak等扩展名文件，导致源码或配置外泄。  
4. 管理后台暴露：常见路径如/admin、/wp-admin、/phpmyadmin被识别后成为后续攻击跳板。  
5. 路径遍历干扰：部分扫描器未正确处理../编码，导致误判或绕过边界检测。  
6. 动态路径失效：基于URL参数生成的路径（如?id=123）无法通过静态字典有效覆盖。

四、防御措施与实践建议  
1. 配置Web服务器禁止列出目录索引，关闭Options Indexes指令并设置默认403响应。  
2. 删除生产环境中的调试文件、备份文件、版本控制元数据及临时上传文件。  
3. 对管理后台实施IP白名单、多因素认证与强访问控制策略，避免使用通用路径名。  
4. 部署WAF并启用目录扫描行为检测规则，对高频404/403响应组合进行速率封禁。  
5. 使用robots.txt仅作提示而非安全控制，禁止在其中暴露真实敏感路径。  
6. 定期执行自动化目录扫描自查，结合人工验证结果，纳入DevSecOps持续监控流程。
