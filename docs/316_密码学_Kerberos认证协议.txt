Kerberos认证协议

一、基本概念  
1. Kerberos是由MIT设计的基于对称密钥的网络身份认证协议，遵循RFC 4120标准。  
2. 采用可信第三方（KDC）架构，KDC由认证服务器（AS）和票据授权服务器（TGS）组成。  
3. 所有通信实体（用户、服务）均需在KDC注册并预共享密钥，密钥派生自密码或长期密钥。  
4. 认证过程不传输明文密码，仅交换加密票据（Ticket）与会话密钥，实现密码隔离。  
5. 票据具有时间戳和有限生命周期（默认8–10小时），支持重放攻击防护与自动过期机制。

二、原理与关键机制  
1. 认证流程分三阶段：AS_REQ/AS_REP获取TGT；TGS_REQ/TGS_REP获取服务票据；AP_REQ/AP_REP完成服务访问。  
2. TGT由KDC用TGS密钥加密，客户端无法解密，仅用于向TGS证明已通过初始认证。  
3. 服务票据（Service Ticket）由KDC用目标服务密钥加密，客户端仅转发，服务端解密验证。  
4. 客户端与服务端共享会话密钥（SK），该密钥由KDC生成并分别用TGT密钥和服务密钥加密分发。  
5. 时间同步至关重要：KDC与客户端时钟偏差通常限制在5分钟内，否则票据被拒收。

三、典型类型与常见问题  
1. 黄金票据攻击：攻击者伪造TGT，利用离线窃取的krbtgt账户NT哈希生成长期有效票据。  
2. 白银票据攻击：绕过KDC直接伪造服务票据，依赖目标服务账户哈希，无需域控权限但需服务定位信息。  
3. AS-REP Roasting：针对未启用预认证的账户，暴力破解AS_REP中加密的会话密钥部分。  
4. 票据传递（Pass-the-Ticket）：窃取内存中的TGT或服务票据，在无密码情况下横向移动。  
5. PAC校验绕过：若服务端未严格验证票据中的特权属性证书（PAC），可能导致权限提升或组策略绕过。

四、防御措施与实践建议  
1. 强制启用Kerberos预认证（UF_DONT_REQUIRE_PREAUTH禁用），阻断AS-REP Roasting。  
2. 定期轮换krbtgt账户密码（至少每180天），且执行两次连续重置以使旧哈希彻底失效。  
3. 启用Kerberos armoring（FAST）和PKINIT，结合TLS通道与公钥加密增强初始认证安全性。  
4. 部署凭证防护（Credential Guard）或虚拟化安全（VBS）隔离LSASS进程，防止票据内存提取。  
5. 限制高权限账户登录工作站，禁用其交互式登录，降低黄金/白银票据攻击面。  
6. 监控异常Kerberos事件ID：如4769（票据请求失败）、4768（TGT请求成功但源IP异常）、4624（登录类型3含票据）等。
