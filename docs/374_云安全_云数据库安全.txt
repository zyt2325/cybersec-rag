云数据库安全

一、基本概念  
1. 云数据库是部署在公有云、私有云或混合云环境中的数据库服务，由云服务商托管或用户自主管理。  
2. 其安全边界从传统本地数据库的物理网络扩展至云平台、虚拟化层、API接口及多租户隔离环境。  
3. 数据主权与合规责任呈共担模式：云服务商保障基础设施安全，用户负责配置、访问控制与数据加密等应用层安全。  
4. 核心风险包括配置错误暴露、API密钥泄露、跨租户数据残留及云原生身份认证链脆弱性。  

二、原理与关键机制  
1. 多租户隔离依赖虚拟化层（如Hypervisor）与网络策略（VPC、安全组）实现逻辑资源分离。  
2. 动态访问控制基于属性基（ABAC）或角色基（RBAC）模型，结合云平台IAM系统实时校验权限。  
3. 传输加密强制使用TLS 1.2+，静态加密默认启用AES-256，密钥可由云KMS托管或用户自管（BYOK）。  
4. 审计日志由云平台统一采集数据库连接、查询、权限变更等操作，支持与SIEM系统集成分析。  

三、典型类型与常见问题  
1. 托管型（如Amazon RDS、Azure SQL Database）易因默认配置开放公网端口导致未授权访问。  
2. Serverless型（如AWS Aurora Serverless）存在冷启动时IAM角色临时凭证缓存不当引发越权风险。  
3. NoSQL云服务（如MongoDB Atlas）常因宽松的网络ACL和未禁用HTTP管理接口被扫描利用。  
4. 跨区域复制功能若未同步加密配置，可能导致副本数据以明文形式存储于目标区域。  
5. 自动备份快照若设为公开可读，可能成为数据泄露入口点。  

四、防御措施与实践建议  
1. 禁用数据库公网访问，所有连接通过VPC内网、私有链接（PrivateLink）或堡垒机跳转。  
2. 启用细粒度审计并设置告警规则，对高频失败登录、非工作时间SELECT *、权限提升操作实时响应。  
3. 使用云平台提供的自动密钥轮换功能，禁止将数据库凭据硬编码于应用配置或CI/CD脚本中。  
4. 对敏感字段实施应用层加密（如AES-GCM），确保即使备份或快照泄露也无法直接还原明文。  
5. 每季度执行配置合规扫描，重点检查安全组入站规则、IAM策略最小权限、SSL强制选项及日志保留周期。  
6. 在开发测试环境使用脱敏数据集，禁止镜像生产数据库完整结构与样本数据。
