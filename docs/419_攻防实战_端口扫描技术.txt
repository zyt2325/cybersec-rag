端口扫描技术

一、基本概念  
1. 端口扫描是探测目标主机TCP/UDP端口状态（开放、关闭、过滤）的网络侦察行为，属于信息收集阶段的核心技术。  
2. 扫描对象为传输层端口号（0–65535），其中0–1023为熟知端口，常对应HTTP、SSH、FTP等标准服务。  
3. 扫描本身不利用漏洞或执行攻击载荷，但为后续渗透提供关键资产画像和入口线索。  
4. 合法用途包括安全评估、合规审计与网络资产管理；非法使用则构成《网络安全法》第27条所禁止的入侵预备行为。  

二、原理与关键机制  
1. 依赖TCP三次握手机制：向目标端口发送SYN包，根据响应（SYN-ACK/RESET/RST）判断端口状态。  
2. UDP扫描基于“无连接”特性：发送探测包后，若收到ICMP端口不可达报文，通常表明端口关闭；无响应可能表示开放或被过滤。  
3. 扫描器通过源IP伪装、随机化端口顺序、调节发包速率等方式规避基于流量特征的IDS检测。  
4. 主机响应延迟、防火墙策略、中间设备（如NAT、负载均衡）会显著影响扫描结果准确性，需结合多轮验证。  

三、典型类型与常见问题  
1. TCP SYN扫描（半开扫描）：只完成握手前两步，隐蔽性高，需root权限，易被现代IPS识别为异常行为。  
2. TCP Connect扫描：调用系统connect()函数完成全连接，无需特权，但日志记录完整、易被审计发现。  
3. NULL、FIN、XMAS等标志位扫描：利用RFC 793对异常标志组合的响应差异推断状态，对Windows无效，仅适用于部分UNIX系统。  
4. 综合扫描常混用多种技术，但存在误报风险——如防火墙丢弃SYN包导致“过滤”误判为“开放”。  
5. 大规模扫描易触发速率限制、IP封禁或蜜罐诱捕，且可能违反ISP服务条款及《刑法》第285条相关规定。  

四、防御措施与实践建议  
1. 部署状态化防火墙，默认拒绝所有入站连接，仅对必需端口配置最小化访问策略并启用连接数限制。  
2. 关闭非必要服务，定期核查监听进程（如netstat -tuln），禁用高危默认端口（如Telnet 23、SNMP 161）。  
3. 启用TCP Wrappers、fail2ban等工具，对高频连接尝试实施自动IP封锁，并将日志接入SIEM平台分析。  
4. 使用端口敲门（Port Knocking）或单包授权（SPA）机制，使关键服务端口在未认证前对扫描完全不可见。  
5. 在DMZ区部署低交互蜜罐，对扫描流量进行捕获与行为建模，提升威胁感知时效性。  
6. 定期开展授权扫描演练，结合Nmap脚本引擎（NSE）检测服务版本、SSL配置等深层风险，避免仅依赖端口状态判断。
