缓存欺骗攻击

一、基本概念  
1. 缓存欺骗攻击是一种Web缓存机制被恶意利用的安全威胁，攻击者诱导缓存服务器存储并分发错误或恶意内容。  
2. 该攻击不直接入侵后端服务器，而是通过操控HTTP请求特征，使缓存系统误判资源的可缓存性与对应关系。  
3. 攻击目标通常是CDN、反向代理（如Nginx、Varnish）或浏览器缓存，影响范围可覆盖大量用户。  
4. 其核心前提在于缓存系统未严格校验请求路径、查询参数、请求头及响应头中缓存控制字段的一致性。  

二、原理与关键机制  
1. 利用缓存键（Cache Key）生成逻辑缺陷：缓存系统若忽略Host、X-Forwarded-Host或特定请求头，将不同域名/路径的响应混存。  
2. 借助响应头中的Cache-Control、Vary等字段配置不当，导致本应私有或不可缓存的内容被共享缓存存储。  
3. 通过构造含歧义路径（如/path/与/path/.js）或大小写差异（如/ADMIN/与/admin/），触发缓存系统路径规范化不一致。  
4. 利用服务器对404页面、重定向响应或错误页面的缓存策略宽松，将错误响应错误地缓存并返回给其他用户。  

三、典型类型与常见问题  
1. 主机头欺骗缓存：攻击者篡改Host头，使缓存服务器将某站点的敏感响应（如登录页）关联到另一域名下。  
2. 查询参数忽略型欺骗：缓存系统忽略URL中关键参数（如?lang=zh或?user_id=123），导致个性化内容被错误共享。  
3. Vary头缺失或错误配置：未在Vary中声明User-Agent、Accept-Language等影响响应内容的头字段，引发内容混淆。  
4. 静态资源劫持：攻击者诱导缓存存储伪造的CSS/JS文件，后续访问者加载时执行恶意脚本。  
5. 错误页面缓存污染：403/404响应被缓存后，真实合法请求被返回错误页面，形成拒绝服务或信息误导。  

四、防御措施与实践建议  
1. 显式定义缓存键：在CDN或反向代理中精确配置缓存键组成，强制包含Host、必要查询参数及关键请求头。  
2. 合理设置Vary响应头：对依赖客户端特征生成内容的资源，必须在Vary中列出所有相关请求头字段。  
3. 敏感内容禁用共享缓存：对含用户身份、会话或动态数据的响应，设置Cache-Control: private, no-store。  
4. 校验并标准化Host头：后端应用须验证Host头是否在白名单内，并拒绝X-Forwarded-Host等不可信头参与路由或缓存决策。  
5. 对错误响应实施缓存排除：配置缓存系统默认不缓存4xx/5xx状态码响应，或显式设置Cache-Control: no-cache。  
6. 定期审计缓存行为：使用curl配合不同请求头组合测试缓存键一致性，验证Vary生效情况与错误响应缓存策略。
