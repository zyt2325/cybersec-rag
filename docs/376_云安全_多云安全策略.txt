多云安全策略

一、基本概念  
1. 多云安全策略指组织在同时使用两个及以上公有云服务商（如AWS、Azure、GCP）时，为保障数据、应用与身份统一安全而制定的协同防护框架。  
2. 区别于混合云，多云特指多个独立公有云环境并存，不强制包含私有云或本地数据中心。  
3. 核心目标是消除云间安全策略碎片化，实现跨云可见性、一致性的访问控制与合规基线。  
4. 策略覆盖范围包括跨云网络流量、共享身份源、密钥生命周期、日志聚合及配置合规审计。  
5. 云服务共担责任模型在多云场景下需逐云明确：IaaS/PaaS/SaaS层的安全职责边界随服务商和部署模式动态变化。

二、原理与关键机制  
1. 统一身份联邦：基于SAML 2.0或OIDC，将企业IdP（如Azure AD、Okta）作为可信源，向各云平台分发短时效令牌，避免多套凭据管理。  
2. 跨云网络微隔离：通过服务网格（如Istio）或云原生CNI插件，在容器跨云迁移时维持零信任策略，依据标签而非IP实施策略执行。  
3. 集中式密钥管理：采用HSM-backed密钥服务（如HashiCorp Vault或云厂商托管KMS跨云同步），确保加密密钥不绑定单一云环境。  
4. 策略即代码（PiC）驱动：使用OPA/Rego或Crossplane定义跨云资源配置策略，自动校验新部署是否符合预设安全规则（如禁止开放SSH至公网）。  
5. 日志联邦分析：通过标准化日志格式（如CIS AWS/Azure/GCP日志规范）接入SIEM，实现跨云威胁行为关联检测（如同一主体在多云中异常权限提升）。

三、典型类型与常见问题  
1. 策略漂移：各云平台默认配置差异导致安全组、存储桶策略、IAM权限随时间偏离基线，形成隐性攻击面。  
2. 身份爆炸：为适配不同云的细粒度权限模型，人为创建大量角色/策略，引发权限过度分配与继承链混乱。  
3. 加密孤岛：各云KMS密钥无法互通，导致跨云数据迁移时需解密再加密，增加明文暴露窗口与密钥轮换复杂度。  
4. 可见性盲区：云原生监控工具（如CloudWatch、Azure Monitor）仅限本云，缺失跨云API调用链与横向移动路径追踪能力。  
5. 合规割裂：GDPR、等保2.0等要求的数据驻留、审计日志保留周期，在多云中因各云SLA差异难以统一满足。

四、防御措施与实践建议  
1. 实施云安全态势管理（CSPM）工具，支持多云API集成，每日扫描配置偏差并自动修复高风险项（如公开S3桶、未加密磁盘）。  
2. 建立跨云最小权限矩阵：基于业务角色映射各云原生权限集（如AWS IAM Permission Boundaries + Azure PIM Just-In-Time），禁用通配符权限。  
3. 部署跨云WAF与API网关集群，对南北向流量统一执行OWASP Top 10防护策略，并注入云环境标识头用于溯源。  
4. 使用eBPF技术在节点层采集跨云容器网络流日志，结合Falco规则引擎实时检测跨云横向渗透行为（如异常DNS隧道请求）。  
5. 制定多云事件响应手册，明确各云厂商取证接口调用顺序（如AWS Artifact、Azure Security Center导出）、日志保留时限及司法协查流程。  
6. 每季度开展多云红蓝对抗演练，重点验证跨云身份冒用、配置错误连锁触发、密钥泄露后横向扩散阻断有效性。
