IPSec VPN技术

一、基本概念  
1. IPSec是IETF制定的网络层安全协议套件，用于在IPv4/IPv6环境中提供端到端的数据机密性、完整性、认证和抗重放保护。  
2. 它工作在OSI模型第三层，可透明保护上层所有协议（如TCP、UDP、ICMP），无需修改应用程序或终端配置。  
3. 主要由AH（认证头）和ESP（封装安全载荷）两个协议构成，AH仅提供认证与完整性，ESP支持加密、认证及完整性。  
4. IPSec通过安全关联（SA）定义通信双方的密钥、算法、生命周期等参数，SA为单向逻辑连接，双向通信需两个SA。  

二、原理与关键机制  
1. 密钥交换依赖IKE（Internet Key Exchange）协议，分IKEv1和IKEv2两代，其中IKEv2支持更优的NAT穿越与会话恢复能力。  
2. SA建立过程分为两个阶段：阶段一建立IKE SA（认证对等体并生成主密钥），阶段二协商IPSec SA（生成会话密钥并确定保护策略）。  
3. ESP支持传输模式（仅保护载荷，适用于主机到主机）和隧道模式（保护整个IP包，常用于网关间VPN），后者是企业广域网部署主流方式。  
4. 抗重放机制通过序列号字段与滑动窗口实现，接收方拒绝超出窗口范围的重复或过期数据包。  

三、典型类型与常见问题  
1. 站点到站点VPN（Site-to-Site）最常见，用于连接分支机构与总部，通常由防火墙或专用VPN网关实现。  
2. 远程访问VPN（Remote Access）允许移动用户通过客户端软件接入内网，需配合XAuth或EAP扩展实现用户级认证。  
3. IKEv1主模式易受暴力破解攻击，因预共享密钥（PSK）强度不足或弱密码策略导致身份泄露风险上升。  
4. NAT穿越问题源于ESP不携带端口信息，需启用UDP封装（端口500/4500）及NAT-T机制，否则隧道无法建立。  
5. SA重协商时若密钥更新不同步，可能引发短暂通信中断或数据包丢弃，影响VoIP等实时业务连续性。  

四、防御措施与实践建议  
1. 强制使用IKEv2替代IKEv1，启用证书认证替代PSK，结合CRL或OCSP验证证书有效性。  
2. 限制IKE协商参数：禁用MD5/SHA1哈希、DES/3DES加密，强制使用AES-GCM或AES-CBC+HMAC-SHA2组合。  
3. 配置SA生命周期时，加密密钥生存期建议≤8小时，认证密钥≤24小时，避免长期密钥暴露风险。  
4. 在边界设备启用反重放窗口检测，并设置合理窗口大小（默认64），防止资源耗尽型DoS攻击。  
5. 对远程访问场景，实施双因素认证（如TOTP+证书）与终端合规检查（如杀毒状态、磁盘加密），阻断高风险接入。  
6. 定期审计IPSec日志中的SA建立失败、认证拒绝、策略不匹配事件，识别潜在扫描或中间人试探行为。
