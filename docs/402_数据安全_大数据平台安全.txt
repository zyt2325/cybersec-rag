大数据平台安全

一、基本概念  
1. 大数据平台安全指保障Hadoop、Spark、Flink等分布式计算框架及其存储组件（如HDFS、HBase、Kafka）在数据采集、存储、处理、分析全生命周期中的机密性、完整性与可用性。  
2. 其核心挑战源于数据规模大、来源多、格式杂、处理链路长，且传统边界防护模型难以适配动态弹性扩缩容的集群环境。  
3. 安全责任主体涵盖平台运维方、数据提供方、应用开发方及最终使用者，需通过策略协同实现跨层管控。  
4. 数据分类分级是基础前提，须依据敏感程度（如PII、PCI、GDPR字段）对数据资产打标，并映射至访问控制策略。

二、原理与关键机制  
1. 认证采用Kerberos协议实现服务间强身份验证，所有组件（NameNode、ResourceManager等）均需通过票据交换完成双向认证。  
2. 授权依赖基于属性的访问控制（ABAC）或细粒度RBAC模型，如Apache Ranger或Sentry，支持列级、行级及UDF调用级权限控制。  
3. 数据传输加密通过TLS 1.2+保障组件间通信（如YARN NodeManager与ResourceManager），禁用明文RPC协议。  
4. 存储加密分为静态加密（HDFS透明加密，使用KMS托管密钥）与动态加密（Spark shuffle阶段内存/磁盘数据AES-256加密）。  
5. 审计日志需覆盖用户操作（如HiveQL执行）、服务行为（如HDFS文件块读写）及系统事件（如Kerberos票据发放），并集中汇聚至SIEM平台。

三、典型类型与常见问题  
1. 配置错误：HDFS默认开启WebHDFS REST接口且未启用认证，导致未授权用户可直接PUT/GET任意路径文件。  
2. 权限滥用：YARN队列资源配额未隔离，恶意作业可耗尽CPU/内存引发拒绝服务，影响同集群其他租户。  
3. 数据残留：Spark临时shuffle文件、Hive本地MapReduce中间结果未自动清理，可能含敏感字段且权限设置为777。  
4. 组件漏洞：Apache Kafka旧版本存在JNDI注入风险，攻击者可通过恶意序列化数据触发远程代码执行。  
5. 第三方集成风险：Flume采集Agent若配置HTTP Source未启用SSL和IP白名单，易被伪造日志注入污染数据湖。

四、防御措施与实践建议  
1. 实施最小权限原则：为每个服务主体（Service Principal）分配仅够运行的Kerberos角色，禁用hdfs超级用户直接登录DataNode。  
2. 启用端到端数据血缘追踪，集成Apache Atlas采集元数据变更、作业依赖与访问路径，支撑影响分析与合规审计。  
3. 对外部数据源接入强制执行Schema校验与内容扫描（如正则匹配身份证号、银行卡号），阻断高敏数据入湖。  
4. 定期轮换KMS主密钥及数据加密密钥，密钥生命周期不超过90天，并确保密钥导出受HSM硬件保护。  
5. 在YARN上部署容器化沙箱（如Docker+cgroups），限制单作业CPU/内存上限及网络出口，防止横向渗透。  
6. 建立大数据平台专属威胁建模流程，针对数据湖架构识别STRIDE威胁（如篡改Hive Metastore表定义），并逐项验证缓解措施有效性。
