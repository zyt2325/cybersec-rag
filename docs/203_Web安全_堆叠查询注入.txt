堆叠查询注入

一、基本概念  
1. 堆叠查询注入是一种SQL注入变体，攻击者通过在用户输入中注入分号（;）来终止当前语句并追加额外SQL语句。  
2. 该漏洞依赖后端数据库支持多语句执行，如MySQL、PostgreSQL、SQL Server默认允许；而SQLite和部分配置下的Oracle则不支持。  
3. 与联合查询注入不同，堆叠查询不要求前后查询结果集结构一致，可执行INSERT、UPDATE、DELETE、CALL等任意语句。  
4. 常见于Web应用中未严格过滤分号、注释符或未使用参数化查询的动态拼接SQL场景。  

二、原理与关键机制  
1. 数据库驱动层解析SQL字符串时，将分号视为语句分隔符，依次执行分号分隔的多个独立语句。  
2. 应用程序若直接将用户输入拼入SQL模板且未校验分号、换行符或注释符号，即构成基础触发条件。  
3. 错误回显非必需条件：即使无错误信息返回，攻击者仍可通过盲注方式（如延时、布尔逻辑、带外信道）验证堆叠语句执行效果。  
4. 权限边界决定危害程度：执行堆叠语句的数据库账户权限越高，可造成的破坏越严重，例如创建新用户、读写文件、调用系统函数。  

三、典型类型与常见问题  
1. MySQL中利用SELECT后堆叠执行UPDATE或DROP TABLE，配合information_schema可枚举数据库结构。  
2. PostgreSQL中通过堆叠执行COPY命令读取服务器本地文件，或调用dblink_connect发起跨库连接。  
3. SQL Server中利用堆叠执行xp_cmdshell执行系统命令（需启用高级选项且账户具备sysadmin权限）。  
4. 常见误判是将单引号闭合失败等同于无法利用堆叠注入——实际可通过注释符（--、#）或换行绕过语法错误。  
5. 某些ORM框架（如旧版MyBatis）若配置allowMultiQueries=true且使用${}而非#{}进行变量替换，会引入堆叠风险。  

四、防御措施与实践建议  
1. 严格使用预编译参数化查询（PreparedStatement），禁用字符串拼接构造SQL语句。  
2. 数据库连接配置中关闭多语句支持：MySQL设置allowMultiQueries=false，PostgreSQL禁用semicolon-separated queries。  
3. 最小权限原则：应用数据库账户仅授予必要表的CRUD权限，禁用CREATE USER、FILE、EXECUTE等高危权限。  
4. 输入层实施白名单校验：对ID、状态码等字段限制为数字或枚举值，拒绝含分号、括号、注释符的输入。  
5. 错误处理统一返回泛化提示，禁止向客户端泄露数据库类型、版本及SQL语法错误详情。  
6. 在WAF规则中添加针对分号后紧跟SQL关键字（如INSERT、UNION、EXEC）的特征检测，作为纵深防御补充。
