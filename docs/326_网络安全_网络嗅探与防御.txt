网络嗅探与防御

一、基本概念  
1. 网络嗅探指在共享或非安全网络环境中被动捕获并分析传输中数据包的技术，属于旁路式信息获取行为。  
2. 嗅探本身不修改流量，但可导致敏感信息（如明文账号、会话令牌）被未授权截获，构成机密性威胁。  
3. 合法用途包括网络故障排查、性能监控和安全审计，需经授权并在合规框架下实施。  
4. 与主动攻击不同，传统嗅探不触发目标响应，隐蔽性强，难以被常规日志或告警机制发现。  

二、原理与关键机制  
1. 依赖网卡混杂模式：使网卡接收所有经过物理链路的数据帧，而不仅限于本机MAC地址匹配帧。  
2. 利用以太网广播特性：在集线器（Hub）环境或ARP欺骗构造的伪广播域中，流量自然扩散至监听端口。  
3. 依赖协议设计缺陷：如HTTP、FTP、Telnet等明文协议未加密载荷，使解码后的应用层内容可直接读取。  
4. 可结合MAC地址泛洪或交换机CAM表溢出，迫使交换机降级为广播转发，扩大嗅探覆盖范围。  

三、典型类型与常见问题  
1. 被动嗅探：在Hub环境或已控制网关设备上直接捕获流量，无需干扰网络正常通信。  
2. 主动中间人型嗅探：通过ARP欺骗、DNS劫持或DHCP耗尽等手段劫持流量路径，再实施监听。  
3. 无线嗅探：利用802.11管理帧广播特性及弱WEP/WPA-PSK密钥，捕获并离线破解无线数据帧。  
4. TLS/SSL嗅探需依赖客户端信任恶意CA证书或终端代理配置，无法突破正确实现的证书验证机制。  
5. 容器或云环境中的嗅探风险源于虚拟交换机配置不当、宿主机网络命名空间隔离失效或CNI插件漏洞。  

四、防御措施与实践建议  
1. 强制使用TLS 1.2+并启用HSTS，对Web、API、邮件等服务实施端到端加密，消除明文传输面。  
2. 部署静态ARP绑定、DHCP Snooping与DAI（动态ARP检测）功能，在接入层交换机阻断ARP欺骗。  
3. 采用端口安全（Port Security）限制MAC地址学习数量，配合802.1X认证控制终端入网权限。  
4. 无线网络禁用WEP与TKIP，强制WPA3-Enterprise或WPA2-Enterprise配合RADIUS服务器认证。  
5. 在虚拟化平台启用vSwitch流量隔离策略，禁用混杂模式，对容器网络实施NetworkPolicy策略管控。  
6. 定期开展网络分段审计，将高敏系统置于独立VLAN，通过微隔离限制横向流量暴露面。
