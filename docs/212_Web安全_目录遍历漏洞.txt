目录遍历漏洞

一、基本概念  
1. 目录遍历漏洞是Web应用未正确校验用户输入的文件路径，导致攻击者可越权访问服务器任意文件系统资源。  
2. 该漏洞属于输入验证类缺陷，核心在于应用将未经净化的用户可控路径参数直接拼接到文件操作函数中。  
3. 常见触发点包括文件下载、图片预览、日志查看、模板加载等需动态解析路径的功能模块。  
4. 漏洞影响范围取决于Web服务运行账户权限及操作系统路径分隔符处理逻辑（如Windows支持\与/混用）。  

二、原理与关键机制  
1. 攻击者利用“../”等路径遍历序列向上回溯目录层级，绕过应用设定的初始路径限制。  
2. 服务端若对输入仅做简单字符串替换（如删除“../”），易被编码绕过（如%2e%2e/、..%c0%af、....//等变体）。  
3. 路径规范化发生在不同阶段（URL解码、路径标准化、文件系统解析），各环节处理不一致会引发逻辑断层。  
4. 某些语言内置函数（如PHP的realpath()）在路径不存在时返回false，若错误处理不当可能跳过安全检查。  

三、典型类型与常见问题  
1. 静态资源路径遍历：通过修改请求参数（如?file=../../etc/passwd）读取敏感配置或系统文件。  
2. 日志文件包含型遍历：结合日志注入，将恶意PHP代码写入日志后通过遍历路径触发远程代码执行。  
3. ZIP路径遍历：解压用户上传ZIP包时未校验内部文件路径，导致覆盖Web根目录关键文件（如.htaccess）。  
4. Windows平台特有风险：利用“C:\”绝对路径、UNC路径（\\server\share）或8.3短文件名绕过过滤。  
5. 编码混淆组合攻击：多层URL编码、Unicode编码（如%u002e%u002e）、大小写混合（..%c1%9c）规避WAF规则。  

四、防御措施与实践建议  
1. 禁止将用户输入直接用于文件路径构造，优先采用白名单映射（如file_id→/safe_dir/report.pdf）。  
2. 若必须使用路径参数，应严格限制为相对路径，并在拼接前调用标准化函数（如Python的os.path.normpath）并验证是否位于授权根目录内。  
3. 使用安全的文件操作API：如Java的Files.isSameFile()比字符串匹配更可靠；PHP应禁用allow_url_fopen且避免file_get_contents()直接受控路径。  
4. Web服务器层面配置路径白名单，Nginx可通过location指令限制静态资源访问范围，Apache启用mod_security规则拦截可疑路径序列。  
5. 对上传ZIP等归档文件，解压前逐项校验内部路径，拒绝含“../”、绝对路径或超出目标目录的条目。  
6. 运行Web服务的系统账户应遵循最小权限原则，禁止对/etc、/var/log等敏感目录具有读写权限。
