云上供应链安全

一、基本概念  
1. 云上供应链指云环境中软件、服务、基础设施组件的依赖关系链，涵盖IaaS/PaaS/SaaS层的第三方代码、镜像、API、托管服务等。  
2. 与传统供应链不同，云上供应链具有动态性、多租户共享性、跨域依赖性及自动化编排特征。  
3. 供应链环节包括开源库引入、容器镜像构建、CI/CD流水线集成、云市场应用部署、SaaS插件安装等。  
4. 云上供应链安全关注恶意注入、篡改、劫持等行为在交付链路中引发的横向移动、权限提升或数据泄露风险。  

二、原理与关键机制  
1. 依赖传递性使单一组件漏洞可沿调用链扩散至上游应用，如Log4j漏洞通过Maven依赖被云原生应用间接引入。  
2. 镜像签名与验证机制（如Cosign、Notary v2）通过数字签名绑定镜像哈希值与可信发布者身份，防止运行时篡改。  
3. SBOM（软件物料清单）以标准化格式（SPDX、CycloneDX）记录组件版本、许可证、漏洞关联信息，支撑溯源与合规审计。  
4. CI/CD流水线中的策略即代码（Policy-as-Code）工具（如OPA、Kyverno）可在构建、推送、部署阶段实时执行准入控制。  

三、典型类型与常见问题  
1. 恶意开源包投毒：攻击者注册相似包名（typosquatting）或接管废弃项目，植入后门代码至PyPI/NPM等公共仓库。  
2. 不安全镜像源：使用未经扫描的公共Docker Hub镜像，或配置insecure-registries跳过TLS校验，导致中间人劫持。  
3. CI/CD凭证泄露：硬编码在脚本中的云API密钥、访问令牌被提交至GitHub，触发自动化窃取与资源滥用。  
4. SaaS集成风险：OAuth授权范围过度宽泛（如“read:org”+“write:repo”），第三方应用越权访问企业代码库或用户数据。  

四、防御措施与实践建议  
1. 实施最小权限原则：为CI/CD服务账户分配仅限必要操作的IAM角色，禁用长期凭证，启用临时令牌与自动轮换。  
2. 强制SBOM生成与验证：在构建阶段自动生成CycloneDX SBOM，并在部署前比对NVD/CISA KEV数据库阻断已知高危组件。  
3. 建立可信镜像仓库：内部Harbor集群启用内容信任（Notary）、漏洞扫描（Trivy）、策略强制（如禁止root用户运行）。  
4. 对接云工作负载保护平台（CWPP）：监控运行时异常行为，如容器内非预期进程启动、敏感文件读取、横向网络连接。  
5. 审计SaaS应用权限：定期审查OAuth授权列表，撤销闲置集成，采用SCIM协议实现用户生命周期同步与权限自动回收。  
6. 开展供应链红蓝对抗：模拟恶意包注入、镜像篡改、凭证窃取等场景，验证检测响应时效与策略覆盖完整性。
