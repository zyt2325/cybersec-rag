关键信息基础设施保护条例

一、基本概念  
1. 关键信息基础设施（CII）是指一旦遭到破坏、丧失功能或数据泄露，可能严重危害国家安全、国计民生、公共利益的重要网络设施和信息系统。  
2. 《关键信息基础设施安全保护条例》于2021年9月1日起施行，是依据《网络安全法》制定的行政法规，具有强制约束力。  
3. CII认定由行业主管监管部门会同国家网信部门组织，实行“谁主管谁负责、谁运营谁负责”原则，覆盖能源、金融、交通、水利等11类重点行业。  
4. 运营者指依法承担CII建设、运维和安全保障责任的单位，须设立专门安全管理机构，并明确主要负责人为第一责任人。  
5. CII与等级保护制度存在衔接关系：所有CII至少应达到等保三级要求，但其保护要求高于等保，强调持续监测、主动防御与协同联动。

二、原理与关键机制  
1. 实行“三同步”原则：CII规划、建设、运行阶段必须同步规划、同步建设、同步使用安全技术措施。  
2. 建立安全检测评估机制：运营者每年至少开展一次网络安全检测和风险评估，并将结果报送主管部门。  
3. 强化供应链安全管控：对采购的网络产品和服务实施安全审查，禁止使用未经安全审查或审查未通过的产品。  
4. 落实数据分类分级保护：对CII中处理的核心数据、重要数据实行目录管理，严格限制跨境传输。  
5. 构建国家级协同响应体系：国家网信部门统筹协调，公安、工信等部门按职责开展监督检查与应急处置。

三、典型类型与常见问题  
1. 典型CII包括电力调度控制系统、铁路列车运行控制系统、大型商业银行核心交易系统、省级以上政务云平台等。  
2. 常见问题包括：安全管理制度不健全、安全管理人员配备不足、未落实日志留存180天以上要求、远程运维缺乏强身份认证。  
3. 第三方服务风险突出：外包运维、云服务商权限过大、接口未做最小化授权，易成为攻击跳板。  
4. 工控系统暴露面扩大：部分CII仍使用老旧操作系统、默认口令未修改、未部署工业防火墙，存在协议解析漏洞风险。  
5. 安全监测能力薄弱：多数运营者依赖边界防护，缺乏内部流量深度分析、威胁行为建模与异常横向移动识别能力。

四、防御措施与实践建议  
1. 部署CII专属安全运营中心（SOC），集成资产测绘、脆弱性管理、威胁情报与自动化响应能力。  
2. 对关键业务系统实施微隔离策略，基于零信任架构控制东西向流量，限制非必要跨域访问。  
3. 开展常态化攻防演练，每半年至少组织一次红蓝对抗，重点检验应急响应流程与备份恢复实效性。  
4. 建立CII供应链安全台账，对关键软硬件进行源代码审计、固件签名验证及国产化替代路线图管理。  
5. 加强人员安全意识与技能培养，关键岗位人员须通过国家认可的CISP-CSE或CISP-PTE等专项认证。  
6. 严格遵循《GB/T 39204-2022 信息安全技术 关键信息基础设施安全保护要求》，逐项落实分析识别、安全防护、检测评估、监测预警、主动防御、事件处置六大能力。
