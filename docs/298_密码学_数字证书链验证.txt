数字证书链验证

一、基本概念  
1. 数字证书链是由终端实体证书、一个或多个中间CA证书及根CA证书构成的层级信任路径。  
2. 验证目标是确认终端证书由可信根CA逐级签发，且整条链上所有证书均处于有效状态。  
3. 证书链必须满足完整性（无缺失环节）、顺序性（从终端到根方向逐级签名可验）和可信性（根证书预置在信任库中）。  
4. 每张证书包含公钥、持有者身份、签发者标识、有效期、签名算法及CA签名值，是链式验证的数据基础。  
5. 根证书通常自签名，其公钥通过操作系统或浏览器内置信任库分发，不依赖上级签发。

二、原理与关键机制  
1. 验证从终端证书开始，用上一级证书的公钥解密其签名，比对摘要值是否一致。  
2. 逐级向上验证签名有效性，直至根证书；根证书签名使用其自身公钥验证，仅需确认其在本地信任库中且未被吊销。  
3. 每级证书须检查有效期、密钥用途（如keyUsage、extendedKeyUsage）、基本约束（basicConstraints）是否允许签发下级证书。  
4. 必须校验证书吊销状态，通过CRL或OCSP协议获取实时吊销信息，忽略吊销检查将导致失效证书被误信。  
5. 名称约束（nameConstraints）和策略映射（policyMappings）等扩展字段影响跨域链的合法性判断，需严格解析。

三、典型类型与常见问题  
1. 中间CA私钥泄露会导致整个子链签发的证书失去可信性，但根证书仍可能被错误保留。  
2. 证书链不完整（如服务器未发送中间证书）是HTTPS握手失败主因，客户端无法构建完整路径。  
3. 根证书过期或被移出信任库（如Symantec根证书事件）将导致大量合法链验证失败。  
4. 自签名中间证书未正确标记basicConstraints为CA:true，或终端证书误设为CA:true，破坏链结构安全性。  
5. OCSP响应器不可达或返回“未知”状态时，部分客户端执行软失败，形成验证盲区。

四、防御措施与实践建议  
1. 服务端应配置完整证书链（含全部中间证书），避免依赖客户端自主查找，推荐使用SSL Labs测试工具验证。  
2. 客户端必须启用并强制执行吊销检查，优先采用OCSP Stapling以降低延迟与隐私泄露风险。  
3. 运维人员定期轮换中间CA密钥，缩短证书有效期（如≤13个月），并监控证书到期与吊销状态。  
4. 根证书管理须遵循最小权限原则，离线存储私钥，禁止用于日常签发；中间CA应部署于隔离环境并启用HSM保护。  
5. 开发TLS应用时禁用不安全的签名算法（如SHA-1、RSA-PKCS#1 v1.5无PSS填充），强制要求ECDSA或RSA-PSS。  
6. 建立证书生命周期管理流程，集成ACME协议实现自动化申请、续订与吊销同步，减少人工失误。
