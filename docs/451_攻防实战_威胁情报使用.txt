威胁情报使用

一、基本概念  
1. 威胁情报是经过验证、上下文关联、可机读且可操作的网络安全信息，用于支撑防御决策。  
2. 情报生命周期包含采集、处理、分析、分发和反馈五个阶段，强调闭环迭代而非单向输出。  
3. 区别于原始日志或告警，威胁情报必须具备TTPs（战术、技术与过程）、可信度评分及时效性标注。  
4. 使用主体涵盖SOC分析师、EDR策略工程师、威胁狩猎团队及蓝队演练设计人员，角色不同则消费粒度不同。  

二、原理与关键机制  
1. 情报融合依赖标准化格式（如STIX 2.1/TAXII 2.1），确保多源数据结构对齐与语义一致。  
2. 关联分析通过IOC（IP、域名、哈希）与行为图谱（如ATT&CK映射）建立攻击链还原能力。  
3. 自动化分发需配置细粒度订阅策略，例如按行业（金融/能源）、TTPs类别（横向移动/凭证转储）或置信度阈值（≥85%）过滤。  
4. 情报富化需集成地理IP库、ASN归属、SSL证书历史、被动DNS等第三方上下文，避免孤立IOC误判。  

三、典型类型与常见问题  
1. 战术层情报（如MITRE ATT&CK技术ID）指导检测规则编写；运营层情报（恶意C2域名集群）支撑网络层阻断。  
2. 情报过载表现为每日接收超50万条IOC但有效检出率低于3%，主因缺乏优先级排序与环境适配。  
3. 时效性衰减显著：钓鱼邮件中使用的短生存期域名平均存活仅17小时，延迟超4小时即失效。  
4. 误报传导风险高：某开源威胁源将合法CDN IP误标为恶意，导致企业WAF策略批量误阻断业务流量。  
5. 情报孤岛现象普遍，防火墙、SIEM、EDR系统间未打通共享通道，同一IOC需人工重复录入三次以上。  

四、防御措施与实践建议  
1. 建立情报分级制度：高置信度TTPs类情报直通检测规则引擎；低置信度IOC类情报仅进入沙箱待验队列。  
2. 实施环境感知校准：在导入外部情报前，自动比对本地资产指纹（如暴露面端口、Web框架版本），剔除不适用条目。  
3. 部署情报效果度量指标，包括IOC命中率、TTPs覆盖缺口数、平均响应时间缩短值，每季度生成效能报告。  
4. 采用双向反馈机制：将内部捕获的新型样本反哺至情报源，并标注验证结果（如“该哈希在本环境触发横向移动行为”）。  
5. 要求供应商提供情报元数据完整性，必须包含来源可信度、首次观测时间、最后更新时间、关联攻击组织编号（如APT29）。  
6. 在红蓝对抗中嵌入情报注入环节：蓝队需基于实时更新的APT组织最新TTPs调整检测逻辑，验证情报驱动防御有效性。
