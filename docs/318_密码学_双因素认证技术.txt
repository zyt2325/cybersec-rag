双因素认证技术

一、基本概念  
1. 双因素认证（2FA）要求用户同时提供两种不同类别的验证要素，缺一不可。  
2. 三类验证要素为：所知（如密码）、所有（如手机或硬件令牌）、所是（如指纹或虹膜）。  
3. 2FA 不等同于多因素认证（MFA），后者可包含两个以上要素，而 2FA 严格限定为两类。  
4. 单因素认证仅依赖一类要素（如仅密码），易受暴力破解、钓鱼或凭证泄露攻击。  
5. 国际标准 ISO/IEC 19792 和我国《GB/T 22239-2019》均将 2FA 列为中高安全等级系统的强制性访问控制要求。

二、原理与关键机制  
1. 认证流程分两阶段：第一阶段验证所知要素，第二阶段动态生成并验证另一类要素。  
2. 时间同步型令牌（如TOTP）基于HMAC-SHA1算法和共享密钥，每30秒生成6位一次性口令。  
3. 基于挑战-响应的硬件令牌（如YubiKey）在收到服务器随机挑战后，用内置私钥签名返回响应。  
4. 推送认证依赖可信设备安装的专用App，通过加密通道接收并确认登录请求，含设备绑定与会话绑定机制。  
5. 所有2FA协议必须确保第二要素传输过程加密（如TLS 1.2+），且服务端不持久化存储原始第二要素值。

三、典型类型与常见问题  
1. 短信2FA存在SS7协议漏洞、SIM卡劫持及中间人拦截风险，已被NIST SP 800-63B明确建议弃用。  
2. 邮件验证码易受邮箱账户接管、IMAP/POP3弱口令或邮件客户端同步泄露影响，时效性与机密性不足。  
3. TOTP实现若未校准设备时钟偏差（如允许±3个时间步长窗口），将扩大重放攻击时间窗口。  
4. 生物特征作为第二要素时，需确保模板本地存储、活体检测防照片/面具攻击，并避免明文传输原始生物数据。  
5. 恢复机制设计不当（如备用邮箱、安全问题）常成为2FA绕过入口，实际削弱整体安全性。

四、防御措施与实践建议  
1. 优先采用FIDO2/WebAuthn标准，利用公钥密码学实现无密码+硬件绑定的强2FA。  
2. 服务端须对TOTP输入做速率限制（如5次/分钟）并记录失败尝试，触发账户临时锁定。  
3. 移动端推送认证应启用设备级密钥保护（如Android StrongBox、iOS Secure Enclave）存储签名密钥。  
4. 用户注册2FA时强制完成一次完整验证流程，并保存唯一恢复码（AES-256加密存储，单次使用即失效）。  
5. 对管理员账户必须启用硬件安全密钥（如FIDO U2F），禁止使用短信或邮件等低保障方式。  
6. 定期审计日志，监控异常2FA使用模式（如同一设备频繁切换IP、跨时区高频验证请求）。
