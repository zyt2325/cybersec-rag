密钥轮换策略

一、基本概念  
1. 密钥轮换是指定期或按条件用新密钥替换旧密钥的过程，旨在限制密钥暴露时间与影响范围。  
2. 轮换对象包括对称密钥（如AES密钥）、非对称密钥对（如RSA私钥）及HMAC密钥等密码学原语。  
3. 轮换不等于密钥销毁：旧密钥需在安全策略规定的时间窗口内保留，用于解密历史密文或验证旧签名。  
4. 轮换周期由密钥用途、强度、使用频率及合规要求共同决定，例如PCI DSS要求加密密钥至少每年轮换。  

二、原理与关键机制  
1. 基于“密钥生命周期管理”理念，通过缩短单密钥有效时长降低密钥泄露后的危害熵值。  
2. 依赖密钥管理系统（KMS）实现自动化轮换，支持密钥版本控制、策略触发（如时间/调用次数阈值）和审计日志记录。  
3. 加密数据需支持密钥版本标识，解密服务根据密文头元数据自动选择对应历史密钥版本。  
4. 非对称场景中，公钥可公开分发，私钥轮换需同步更新证书链并触发CA重新签发或OCSP响应更新。  

三、典型类型与常见问题  
1. 时间驱动型：按固定周期（如90天）强制轮换，简单但可能忽略实际风险变化。  
2. 事件驱动型：密钥泄露嫌疑、员工离职、系统重装或合规审计失败时立即触发轮换。  
3. 使用量驱动型：基于密钥加密/签名操作次数（如10^6次）触发，适用于高吞吐场景如TLS会话密钥。  
4. 常见问题包括：未同步更新所有依赖服务导致解密失败；轮换后旧密钥过早删除引发数据不可恢复；缺乏密钥版本回溯能力。  
5. 混合策略更稳健，例如以180天为基线周期，叠加泄露检测告警的即时响应机制。  

四、防御措施与实践建议  
1. 实施密钥分级管理：根密钥（KEK）轮换周期应长于数据密钥（DEK），且KEK必须离线存储并人工审批轮换。  
2. 所有轮换操作须经双人复核与完整审计日志留存，日志包含操作者、时间、密钥ID、旧/新版本哈希及签名凭证。  
3. 在应用层集成密钥版本感知逻辑，避免硬编码密钥引用；采用KMS提供的加密/解密API而非本地密钥缓存。  
4. 对静态数据加密，轮换时需执行密钥重加密（re-encryption）：用新DEK加密原始明文，或用新KEK封装旧DEK密文。  
5. 定期开展密钥轮换演练，验证密钥归档、历史数据解密、证书链更新及服务降级容错能力。  
6. 遵循NIST SP 800-57 Part 1最新建议，对2048位RSA密钥设定最长3年有效期，对AES-256密钥可延长至5年但需结合使用强度评估。
