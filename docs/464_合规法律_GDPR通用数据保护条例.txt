GDPR通用数据保护条例  
一、基本概念  
1. GDPR是欧盟于2018年5月25日生效的综合性数据保护法规，具有域外效力，适用于处理欧盟居民个人数据的所有组织。  
2. 个人数据指任何可识别自然人身份的信息，包括姓名、身份证号、位置数据、在线标识符（如IP地址、Cookie ID）及生物识别数据。  
3. 数据控制者决定数据处理目的与方式；数据处理者代表控制者处理数据，二者须签订具有法律约束力的数据处理协议。  
4. 合法处理基础包括数据主体同意、合同履行、法定义务、重大公共利益、控制者正当利益等六类，单一处理活动须至少满足一项。  

二、原理与关键机制  
1. 数据最小化原则要求仅收集实现目的所必需的最少量个人数据，禁止过度采集或长期留存无关字段。  
2. 数据可携权允许数据主体以结构化、通用、机器可读格式获取其提供给控制者的个人数据，并有权将数据转移至其他控制者。  
3. 被遗忘权赋予数据主体在特定情形下（如撤回同意、数据不再必要、非法处理）要求删除其个人数据的权利，控制者须及时响应并通知第三方接收方。  
4. 数据保护影响评估（DPIA）是强制性前置程序，适用于高风险处理活动（如大规模监控、敏感数据自动化决策），须识别风险并记录缓解措施。  

三、典型类型与常见问题  
1. 跨境数据传输需满足充分性认定、标准合同条款（SCCs）、有约束力企业规则（BCRs）等合法机制，Schrems II判决后SCCs须辅以补充措施。  
2. Cookie弹窗滥用：仅提供“接受全部”选项、未区分必要与非必要Cookie、默认勾选、未记录用户选择均构成违法。  
3. 数据泄露通报义务要求72小时内向监管机构报告，若对个人权利造成高风险，还需及时通知数据主体，隐瞒或延迟通报将面临高额处罚。  
4. 假名化不等于匿名化：假名化数据仍属个人数据，需结合其他信息才可识别个体；完全匿名化数据则脱离GDPR适用范围。  

四、防御措施与实践建议  
1. 实施数据映射（Data Mapping）：梳理数据流图谱，明确各环节控制者/处理者角色、处理目的、存储位置及跨境路径。  
2. 部署隐私设计（Privacy by Design）：在系统开发初期嵌入数据保护机制，如默认关闭非必要数据收集、内置访问权限分级与日志审计功能。  
3. 建立数据主体权利响应流程：制定标准化请求验证、时限跟踪、跨部门协作机制，确保在法定一个月内完成响应（复杂情形可延长至三个月）。  
4. 定期开展员工GDPR意识培训，重点覆盖数据泄露识别、客户请求处理、第三方供应商管理等实操场景，保留培训记录备查。  
5. 与第三方处理者签订符合GDPR第28条的协议，明确安全义务、子处理者授权、审计权及违约责任，定期审查其合规状况。
