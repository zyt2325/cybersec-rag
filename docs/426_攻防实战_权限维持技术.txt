权限维持技术

一、基本概念  
1. 权限维持是指攻击者在初始入侵成功后，为长期控制目标系统而部署的隐蔽驻留与访问保持手段。  
2. 其核心目标是绕过常规安全检测，在系统重启、用户登出或安全策略更新后仍保有有效访问权限。  
3. 区别于横向移动和提权，权限维持聚焦于“持久化”而非“扩张”或“升级”，是APT攻击生命周期的关键阶段。  
4. 维持载体通常依附于操作系统启动机制、服务管理框架、用户登录流程或合法应用配置中。  

二、原理与关键机制  
1. 利用系统自启动机制（如Windows注册表Run键、Linux systemd服务、macOS LaunchDaemons）实现开机自动加载。  
2. 通过劫持合法进程的执行流程（如DLL侧加载、APC注入、父进程伪装）规避进程白名单检测。  
3. 借助可信数字签名或合法软件供应链漏洞（如驱动签名绕过、更新机制劫持）降低行为可疑度。  
4. 采用环境感知逻辑（如检查调试器、虚拟机、沙箱特征）实现条件触发，增强隐蔽性与时效性。  

三、典型类型与常见问题  
1. 注册表持久化：在HKCU\Software\Microsoft\Windows\CurrentVersion\Run等键值中写入恶意路径，易被注册表监控工具捕获。  
2. 服务/守护进程持久化：创建伪装为系统服务的后台进程，若未正确设置服务描述与依赖关系，易暴露异常行为。  
3. 计划任务/定时作业：利用schtasks或cron部署周期性执行任务，但任务元数据（作者、触发条件）常含可疑字段。  
4. 浏览器扩展与插件：通过篡改用户浏览器扩展目录实现持久化，但需匹配浏览器版本且易因扩展更新被覆盖。  
5. WMI事件订阅：在Windows中注册永久性WMI事件过滤器与消费者，隐蔽性强但日志记录较完整，存在审计线索。  

四、防御措施与实践建议  
1. 实施最小权限原则，限制普通用户对启动项、服务管理、计划任务等高风险配置区域的写权限。  
2. 启用并集中收集系统级日志（如Windows事件ID 4697/7045、Linux auditd execve记录），建立启动行为基线。  
3. 定期扫描注册表Run键、服务列表、systemd unit文件、crontab及浏览器扩展目录中的异常条目。  
4. 部署EDR解决方案时启用进程树溯源与父子进程行为关联分析，识别非标准启动链。  
5. 对驱动、内核模块、浏览器扩展等组件实施强签名验证策略，禁用未签名或自签名代码加载。  
6. 在开发与运维流程中纳入启动项审查环节，将服务配置、计划任务定义纳入IaC模板并实施自动化合规检查。
