移动应用隐私合规

一、基本概念  
1. 移动应用隐私合规指App在收集、存储、使用、共享、删除用户个人信息时，符合《个人信息保护法》《APP违法违规收集使用个人信息行为认定方法》等法律法规及国家标准（如GB/T 35273）。  
2. 个人信息包括姓名、身份证号、手机号、设备标识符（IMEI/IDFA/AAID）、位置信息、通讯录、相册、麦克风/摄像头权限数据等可识别特定自然人的信息。  
3. 隐私政策是App向用户明示处理规则的法定文本，须以显著方式展示、单独成文、语言通俗易懂，不得通过默认勾选、捆绑授权等方式获取同意。  
4. 同意必须基于用户自主、明确、知情、可撤回的原则；非必要权限（如读取短信、访问通话记录）不得以“提升体验”为由强制索取。  

二、原理与关键机制  
1. 权限最小化机制要求App仅申请实现业务功能所必需的最少权限，且在运行时动态申请，禁止安装时一次性索要全部权限。  
2. SDK合规管控依赖对第三方SDK的数据调用链路审计，重点核查其是否超范围收集、是否具备独立隐私政策、是否经用户单独授权。  
3. 数据匿名化需满足不可复原性标准：经脱敏处理后的数据无法通过任何合理技术手段识别到特定个人，否则仍属个人信息。  
4. 本地化存储优先原则要求境内用户个人信息原则上存储于中国境内；确需出境的，须通过安全评估、认证或标准合同备案。  

三、典型类型与常见问题  
1. 违规收集：未声明即采集剪贴板内容、后台持续获取定位、静默启用麦克风录音、未经同意上传通讯录哈希值。  
2. 超范围使用：将注册手机号用于用户画像推送广告，或将健康App采集的步数数据用于保险精算模型训练。  
3. 第三方共享失控：未在隐私政策中列明广告SDK名称及共享字段，或未对SDK进行合同约束导致其擅自转售设备标识符。  
4. 同意机制失效：采用“不授权即退出”设计、模糊表述“可能收集信息”、未提供便捷的撤回入口或撤回后仍继续收集。  

四、防御措施与实践建议  
1. 实施隐私影响评估（PIA）：在App上线前及重大功能更新时，识别高风险处理活动（如人脸识别、精准地理位置），形成书面评估报告。  
2. 建立SDK分级管理制度：按数据敏感度划分SDK等级，禁止高风险SDK接入支付/金融类核心模块，限制其调用系统API能力。  
3. 权限调用日志审计：在客户端记录每次权限请求的时间、场景、目的及用户响应结果，服务端同步留存6个月以上供监管核查。  
4. 隐私政策动态更新机制：当数据处理规则变更时，须通过弹窗+消息中心双通道通知用户，并重新获取明示同意，旧版本政策存档不少于3年。  
5. 自动化合规检测：集成静态代码扫描工具（如MobSF）识别硬编码密钥、明文传输token、越权调用敏感API等违规模式，每周执行一次基线扫描。
