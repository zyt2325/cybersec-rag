TCP/IP协议栈安全

一、基本概念  
1. TCP/IP协议栈是互联网通信的基础架构，由链路层、网络层（IP）、传输层（TCP/UDP）和应用层四层构成。  
2. 协议栈设计初衷强调鲁棒性与互通性，未内建强身份认证、完整性保护或加密机制。  
3. 各层协议间存在信任传递关系，下层缺陷可被上层协议放大，形成跨层安全风险。  
4. IPv4与IPv6在地址结构、报头格式及扩展机制上差异显著，安全影响不同，如IPv6的NDP易受欺骗攻击。  

二、原理与关键机制  
1. IP协议无连接、不可靠，依赖校验和仅检测传输错误，无法防范篡改或重放。  
2. TCP通过三次握手建立连接，但SYN队列容量有限，易被SYN Flood耗尽资源。  
3. TCP序列号若可预测，攻击者可伪造合法数据包实施会话劫持或RST注入。  
4. UDP无连接、无确认，端口扫描与反射放大攻击（如DNS/NTP）常利用其无状态特性。  
5. ICMP协议用于网络诊断，但ICMP重定向、时间戳请求等消息可被滥用于信息探测或路径操控。  

三、典型类型与常见问题  
1. IP欺骗：伪造源IP地址绕过基于地址的访问控制，配合TCP序列号预测实现会话劫持。  
2. ARP欺骗：局域网中伪造ARP响应，将流量导向攻击者主机，为中间人攻击提供基础。  
3. TCP连接耗尽：SYN Flood、RST Flood等消耗服务器连接表项或内存，导致拒绝服务。  
4. 路由协议漏洞：BGP劫持、OSPF认证缺失可致流量被重定向至恶意节点。  
5. 分片重组攻击：发送异常IP分片（如重叠偏移、超长分片）触发目标系统内核解析错误或崩溃。  
6. 协议指纹识别：通过TCP窗口大小、TTL、选项字段等特征推断操作系统与服务版本，辅助精准攻击。  

四、防御措施与实践建议  
1. 部署入口过滤（BCP38）阻止源地址伪造的出站流量，ISP与企业边界均需启用。  
2. 启用TCP SYN Cookie机制抵御SYN Flood，避免维护半连接队列，降低资源消耗。  
3. 在关键服务中强制使用TLS 1.2+或DTLS，对传输层以上数据加密并验证端点身份。  
4. 网络层部署IPSec（AH/ESP），尤其在站点间VPN或敏感管理通道中保障机密性与完整性。  
5. 关闭非必要协议功能：禁用ICMP重定向、限制ICMP类型、关闭IPv6 NDP无状态自动配置。  
6. 实施严格ACL与微隔离策略，按最小权限原则限制跨子网、跨主机的协议与端口通信。
