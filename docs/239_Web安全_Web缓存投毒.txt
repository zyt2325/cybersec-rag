Web缓存投毒

一、基本概念  
1. Web缓存投毒是一种服务器端缓存污染攻击，攻击者通过构造恶意请求使缓存系统存储并后续分发被篡改的响应内容。  
2. 该攻击不直接入侵后端服务器，而是利用缓存代理（如CDN、反向代理）对未充分校验的请求头或URL参数的错误处理逻辑。  
3. 缓存投毒成功后，所有访问相同缓存键的合法用户将收到恶意响应，具备一次触发、多用户影响的放大效应。  
4. 区别于缓存欺骗，投毒要求攻击者能主动诱导缓存系统存储恶意响应，而非仅利用已存在的缓存项进行重放。

二、原理与关键机制  
1. 缓存键（Cache Key）生成逻辑存在缺陷，例如将未经验证的HTTP头（如Host、X-Forwarded-Host）或查询参数纳入键计算。  
2. 服务器响应中包含动态生成的内容（如密码重置链接、JS脚本路径），且该内容依赖于被缓存的请求头字段。  
3. 缓存系统未对响应的Vary头进行严格校验，导致不同请求头组合被映射到同一缓存键，引发响应混淆。  
4. 后端应用未对客户端可控输入（如Host头）做白名单过滤或规范化，直接拼接进响应体或重定向Location头。

三、典型类型与常见问题  
1. Host头投毒：攻击者篡改Host头，使后端生成含恶意域名的响应（如<script src="https://attacker.com/x.js">），该响应被缓存后污染全站资源加载。  
2. X-Forwarded-Host投毒：当应用信任该头并用于生成绝对URL，而CDN未剥离或校验该头时，易被注入恶意主机名。  
3. Referer头投毒：部分应用将Referer值反射进响应（如“您来自：[Referer]”），若该反射内容被缓存且Referer未列入Vary，则造成跨域内容污染。  
4. 查询参数投毒：当缓存系统忽略特定参数（如utm_source）但后端将其用于生成JS路径，攻击者可注入恶意参数触发缓存存储恶意脚本引用。

四、防御措施与实践建议  
1. 严格定义缓存键：仅将安全、不可控的请求属性（如标准化后的路径、必要查询参数）纳入Cache Key，禁用Host、X-Forwarded-*等高风险头。  
2. 正确配置Vary响应头：对任何参与响应生成的请求头（如Accept-Language、User-Agent），必须显式声明在Vary中，确保缓存隔离。  
3. 后端输入净化：对所有客户端输入（尤其是Host、Referer、X-Forwarded-Host）执行白名单校验或强制重写为可信值，禁止直接反射。  
4. 禁用危险头传递：在CDN或反向代理层剥离或覆盖X-Forwarded-Host、X-Original-Host等非标准头，避免其进入应用逻辑。  
5. 启用Subresource Integrity（SRI）：对缓存的第三方JS/CSS添加integrity属性，防止恶意脚本注入后仍被浏览器执行。  
6. 实施缓存分级策略：静态资源使用强缓存（Cache-Control: public, max-age=31536000），动态内容禁用共享缓存或设置no-store。
