数据生命周期安全

一、基本概念  
1. 数据生命周期指数据从创建、存储、使用、共享、归档到销毁的全过程，共包含六个阶段。  
2. 每个阶段存在特定安全风险，需匹配对应防护策略，不能仅依赖边界防御或单一加密手段。  
3. 合规性要求（如GDPR、《个人信息保护法》）明确要求组织对全生命周期各环节承担安全责任。  
4. 数据分类分级是生命周期安全管理前提，须依据敏感程度、业务影响、法律属性动态标注标签。  

二、原理与关键机制  
1. 纵深防御原则贯穿各阶段：在采集入口设准入控制，在传输中用TLS/SM4加密，在存储时启用透明加密与访问审计。  
2. 最小权限机制需按阶段细化：开发环境禁用生产数据，测试数据须脱敏，归档数据仅保留必要元数据与访问日志。  
3. 数据血缘追踪通过唯一标识符（如UUID+哈希链）记录数据来源、转换操作及流转路径，支撑溯源与影响分析。  
4. 密钥生命周期管理独立于数据本身，密钥生成、轮换、撤销、归档须遵循NIST SP 800-57标准。  

三、典型类型与常见问题  
1. 创建阶段：未校验输入导致恶意数据注入，或元数据缺失造成后续无法识别敏感字段。  
2. 存储阶段：数据库明文存口令、日志文件含完整身份证号、备份介质未加密丢失。  
3. 使用阶段：API接口未鉴权返回全量用户数据，BI工具导出功能绕过行级权限控制。  
4. 销毁阶段：SSD固态硬盘仅执行delete命令未覆写，物理销毁未达GB/T 25060-2010三级标准。  
5. 共享阶段：跨部门数据交换未签订安全协议，第三方SDK擅自上传设备ID与位置信息。  

四、防御措施与实践建议  
1. 部署数据发现与分类分级工具（如基于正则+ML的扫描引擎），每季度自动更新敏感数据清单并同步至策略引擎。  
2. 在数据创建入口部署DLP策略，对含身份证号、银行卡号等模式的数据实时阻断或重定向至脱敏服务。  
3. 存储层启用静态加密（AES-256-GCM），密钥由HSM硬件模块托管，禁止应用层硬编码密钥。  
4. 对开发测试环境实施数据掩码（如姓名替换为“张*”、手机号中间四位替换为“****”），确保不可逆且保持格式兼容。  
5. 建立数据销毁审批流：触发条件包括系统下线、合同期满、监管要求，执行后留存HMAC校验日志并由审计员双签确认。  
6. 将数据生命周期安全纳入DevSecOps流程，在CI/CD流水线中嵌入数据合规性检查插件，拦截含高危字段的代码提交。
