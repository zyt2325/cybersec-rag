SQLMap使用

一、基本概念  
1. SQLMap是一款开源的自动化SQL注入检测与利用工具，支持主流数据库管理系统。  
2. 它通过HTTP请求与目标Web应用交互，识别可注入点并推断后端数据库类型及结构。  
3. 工具内置多种注入技术（如基于错误、布尔盲注、时间盲注），适配不同防护场景。  
4. 支持从URL、Burp Proxy日志、爬虫导出文件等多种输入源加载测试目标。  
5. 提供数据库枚举、表结构提取、数据导出、操作系统命令执行等高阶利用能力。  

二、原理与关键机制  
1. 利用SQL语法特性，在参数位置插入特殊载荷（如单引号、逻辑运算符）触发异常或行为差异。  
2. 通过响应内容、HTTP状态码、响应时间变化等侧信道信号判断注入点存在性与类型。  
3. 采用递归式枚举策略：先确认数据库名，再逐层获取schema、表、列、数据值。  
4. 支持多线程并发探测与智能载荷优化，降低被WAF拦截概率并提升探测效率。  
5. 内置指纹库可识别常见WAF（如ModSecurity、Cloudflare）并启用对应绕过策略。  

三、典型类型与常见问题  
1. 基于错误注入：依赖数据库返回详细错误信息，现代生产环境因错误屏蔽而失效率高。  
2. 布尔盲注：通过True/False响应差异逐位推断数据，速度慢但隐蔽性强，易受网络抖动干扰。  
3. 时间盲注：利用SLEEP()等函数造成响应延迟，对高负载服务器探测成功率下降明显。  
4. POST参数注入常被忽略，需配合--data参数或从历史请求中提取完整请求体。  
5. 多层编码（如URL编码、Unicode转义）或参数混淆（如大小写混用、空格替换）导致载荷失活。  
6. 登录态会话（Cookie、Token）未正确携带时，SQLMap无法访问需认证的注入点。  

四、防御措施与实践建议  
1. 严格使用参数化查询（Prepared Statement）或ORM框架，杜绝动态拼接SQL语句。  
2. 最小权限原则：Web应用数据库账户仅授予必要表的SELECT/INSERT权限，禁用sysadmin角色。  
3. 关闭数据库错误信息向客户端输出，统一返回泛化错误页，避免泄露版本与结构信息。  
4. 部署WAF时启用SQL注入规则集，并定期更新签名库；结合正则白名单校验关键参数格式。  
5. 对用户输入实施服务端深度校验：长度、类型、字符集、业务逻辑合法性缺一不可。  
6. 渗透测试应限定授权范围与时长，禁止在未签署书面协议的生产系统上运行高风险操作模式。
